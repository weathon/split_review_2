## Summary
This paper introduces ToolLLM, a framework for equipping open-source LLMs with tool-use capabilities. The core contributions are (1) ToolBench, a large-scale instruction-tuning dataset with 16,464 real-world REST APIs from RapidAPI and 126,486 instruction–solution pairs; (2) DFSDT, a depth-first search-based decision tree algorithm that improves multi-step reasoning over ReACT by enabling exploration of multiple reasoning paths; (3) a neural API retriever trained on the dataset; and (4) ToolEval, an automatic evaluator. Fine-tuning LLaMA-2 7B on this data yields ToolLLaMA, which achieves pass rates competitive with ChatGPT (66.7% vs. 64.8%) and outperforms other open-source models by a wide margin.

## Strengths
1. **Unprecedented scale and realism of the dataset.** ToolBench covers 16,464 real REST APIs from 49 categories, with 126,486 instruction–solution pairs involving 469,585 real API calls—dwarfing prior datasets (APIBench: 1,645 APIs; API-Bank: 53 APIs; ToolAlpaca: 400 simulated APIs). The inclusion of multi-tool scenarios (I2, I3) is novel and addresses a limitation of prior work. *Evidence: Table 1 (dataset comparison), Section 2.1.*

2. **DFSDT produces large and consistent gains over ReACT.** Across I1/I2/I3 settings using ChatGPT, DFSDT achieves an average pass rate of 63.8% vs. ReACT's 35.3% and ReACT@N's 44.5%. The improvement is largest on the hardest multi-tool settings (I2: 70.6 vs. 40.6; I3: 62.8 vs. 27.6), confirming the method's value for complex reasoning. *Evidence: Table 3 (dfsdt_vs_react), Section 2.3.*

3. **Neural API retriever drastically improves over sparse and generic-embedding baselines.** The trained retriever achieves 78.0% NDCG@1 averaged across all settings, compared to 18.5% for BM25 and 49.6% for Ada embeddings. *Evidence: Table IR (retrieval results), Section 3.1.*

4. **ToolLLaMA (7B) performs competitively with much larger closed-source models.** ToolLLaMA+DFSDT achieves an average pass rate of 66.7% vs. ChatGPT's 64.8% and GPT-4's 71.1%, while beating Claude-2 (22.6%) and Text-Davinci-003 (43.1%). The gap between ToolLLaMA and the zero-shot open-source baselines (Vicuna, Alpaca at 0%) underscores that the dataset meaningfully imparts tool-use ability. *Evidence: Table 2 (main results), Section 3.2.*

5. **ToolEval shows strong correlation with human judgment.** The automatic evaluator reports 87.1% agreement on pass rate and 80.3% on win rate with human annotators, which partially addresses concerns about evaluator bias. *Evidence: Section 3.1 (lines 203–205).*

## Weaknesses
### Fatal
None.

### Major

1. **Circularity in the evaluation pipeline.** The training data is generated by ChatGPT (gpt-3.5-turbo-16k), the evaluation (ToolEval) uses ChatGPT as the judge, and the headline comparison is against ChatGPT. This creates a closed loop: the model may learn to produce outputs that match the evaluator's preferences rather than matching an independent human standard. The human correlation results (87.1%/80.3%) provide partial mitigation, but the details of that study (sample size, inter-annotator agreement, per-metric breakdown) are deferred to the appendix and not substantiated in the main text. Consequently, the strongest claim in the abstract—"comparable performance to ChatGPT"—cannot be interpreted as an impartial measurement with full confidence. This does not invalidate the dataset or DFSDT contribution, but it tempers a central claim.
    *Paper evidence: Lines 7–11 (abstract), Lines 201–205 (ToolEval description), Lines 93–94 (human correlation claim).*

### Minor

1. **No statistical reliability reported for main results.** Table 2 reports pass rates and win rates as point estimates without confidence intervals, error bars, or significance tests. Many comparisons involve small gaps (e.g., ToolLLaMA+DFSDT at 57.0 vs. GPT4+DFSDT at 60.0 on I1-Inst.; 3 percentage points). With what appears to be 200 test instances per scenario (inferred from 0.5% increments), such differences may fall within sampling noise. The test set size is not stated in the main text. This is a common omission in the field but limits the reader's ability to assess the robustness of comparative claims.
    *Paper evidence: Table 2 rows, with increments of 0.5 (implying 200 instances). No explicit test size or variance in main text.*

2. **The API retriever is trained on labels produced by ChatGPT during instruction generation, not on independently validated relevance judgments.** The retriever learns to emulate ChatGPT's API selection heuristic. While in-distribution performance is strong (78.0% NDCG@1), the OOD results on APIBench (Table 5) show the retriever underperforms BM25 on TensorHub AST accuracy (40.59 vs. 41.90) and has higher hallucination rates on all three domains compared to Gorilla-RS+BM25. The paper's framing of "remarkable OOD generalization" is accurate for the model with oracle APIs but overstated for the full pipeline including the retriever.
    *Paper evidence: Section 2.2 (instruction generation produces labels), Table 5 (APIBench results).*

3. **The comparison between ToolLLaMA (7B) and ChatGPT is confounded by model scale.** The paper attributes the performance gap to tool-use instruction tuning, but ChatGPT is a much larger model with unknown training data composition. While achieving competitive results at 7B is impressive, the paper does not control for or discuss this confound.
    *Paper evidence: Section 3.2 (model/baseline descriptions).*

4. **No quantitative comparison of annotation cost for DFSDT vs. baselines.** The paper claims DFSDT saves annotation cost but only reports pass rates (Table 3), not actual API call counts, dollar costs, or number of search steps. A concrete cost comparison would strengthen the efficiency claim.
    *Paper evidence: Section 2.3 (lines 186–190), Table 3 (pass rate comparison).*

### Trivial

1. **The paper does not characterize what is lost during API filtering.** Of 53,190 APIs crawled, only 16,464 were retained. The filtering criteria are described (Section 2.1, details in appendix), but no analysis of which categories or API types were disproportionately dropped is given.

## Suggestions
1. **Add a small-scale human evaluation or GPT-4 judge as a second opinion** to break the ChatGPT→ChatGPT circularity in the evaluation loop. Even a 50–100 instance human evaluation with agreement statistics would significantly strengthen the headline claim.
2. **Provide bootstrapped confidence intervals for the main results** in Table 2. Since the test set appears to contain 200 instances per scenario, this is straightforward and would clarify which differences are meaningful.
3. **Acknowledge the retriever's OOD limitations more explicitly** and soften the "remarkable generalization" claim for the end-to-end pipeline, distinguishing model generalization (strong, even with oracle APIs) from retriever generalization (mixed).
4. **Move test-set sizes and key DFSDT hyperparameters from the appendix to the main text** — these directly affect how results should be interpreted and cost less than a paragraph each.

## Score and Decision

This paper makes substantial and reproducible contributions: a high-quality dataset that will serve the community, a practical reasoning algorithm (DFSDT) with clear empirical benefits, and a competitive 7B model. The evaluation circularity is a real concern that tempers the strongest claim but does not undermine the core contributions — the dataset, DFSDT, and retriever all stand independently. The weaknesses are addressable and do not outweigh the paper's clear value to the field.
