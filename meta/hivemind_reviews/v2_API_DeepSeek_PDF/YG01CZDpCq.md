# Final Review Report

## Summary

This paper proposes Adaptive Prompt Prototype Learning (APPLe), a method to improve CLIP-based zero-shot and few-shot classification by replacing the standard single text prompt per class with multiple descriptive prompts generated by GPT-3. The method introduces three main technical components: (1) using K text prototypes per class to cover intra-class visual variance, (2) an adaptive attention mechanism to weight prototypes based on their reliability, and (3) a decorrelation loss (L2 regularization on prototype logits) to discourage co-activation of multiple prototypes. Experiments are conducted on 11 datasets across three settings: base-to-new generalization, few-shot learning, and domain generalization.

**Core strengths**: The paper identifies a real and important limitation of existing prompt-tuning methods—a single embedding cannot capture multi-modal intra-class variance. The use of GPT-3-generated diverse prompts is intuitive and well-motivated. The training-free variant (APPLe*) demonstrates that multiple text prototypes can improve CLIP zero-shot performance without any parameter updates, which is a practically useful finding. The ablation study (Table 3) is thorough in decomposing component contributions.

**Critical weaknesses**: (1) The adaptive attention mechanism uses unnormalized multiplicative weights on cosine similarities without softmax or normalization, which is unconventional and may affect training stability. (2) The "decorrelation" loss is a misnomer—Eq. (4) is an L2 magnitude penalty, not a true decorrelation term. (3) The inference formula Eq. (7) double-counts the max-prototype logit without adjusting the temperature denominator. (4) Several claims are overstated: the training-free version does not "surpass all existing training-based methods" (it only wins on New class accuracy, lagging on Base and HM), and domain generalization claims are based on ImageNet-derived datasets sharing the same label space. (5) No variance estimates or significance tests are reported for any experiment. (6) The conclusion claims "consistent gains on all 11 datasets" but Table 1 shows performance drops on Food101 New (-0.17%) and EuroSAT Base (-3.17%).

Due to external paper search being unavailable in this run, novelty/comparison conclusions are deferred for manual verification. The technical and methodological issues identified above are manuscript-grounded and independently verifiable.

## Strengths
1. **Well-motivated problem formulation**: The paper correctly identifies that a single text embedding per class cannot capture multi-modal intra-class visual variance. The "apple pie" example (Fig. 1) effectively illustrates this limitation, and the similarity analysis showing that diverse descriptions match images better than a generic template is convincing.

2. **Training-free variant demonstrates clear value**: The APPLe* (training-free) version achieves 78.05% on novel classes compared to CLIP zero-shot's 74.22%, without any fine-tuning or support-set images. This is a practically useful finding—it shows that multiple text prototypes can better exploit CLIP's existing zero-shot capability.

3. **Thorough ablation study**: Table 3 systematically decomposes the method into 5 components and measures the contribution of each. This provides good scientific transparency about what drives the improvement. The finding that even simple averaging of GPT-3 prompts (Prototypes ✓ only) improves HM from 70.22% to 73.25% is an honest and informative result.

4. **Comprehensive evaluation scope**: Experiments span 11 diverse datasets (coarse, fine-grained, texture, satellite, scene, action) across three settings (base-to-new generalization, few-shot, domain generalization). This provides reasonable evidence of broad applicability, even though some claims need qualification.

5. **Reproducibility-friendly details**: The paper provides clear description of the training objective (Eq. 6), inference procedure (Eq. 7), prompt construction via GPT-3, and the attention matrix formulation. The loss weights λ1=λ2=3 are reported as fixed across all experiments, which simplifies reproduction attempts.

## Weaknesses
**Ranked by severity | research-value impact | validity risk**

**W1 (Major/Validity) — Unconventional attention mechanism without normalization**: The adaptive attention in Eq. (2) uses element-wise multiplication `⊙` between an unconstrained weight matrix W ∈ R^(C×K) and cosine similarity values. No softmax or normalization is applied across prototypes, meaning W can arbitrarily scale logits up or down, affecting the softmax temperature in unintended ways. This design choice is not justified.

**W2 (Major/Validity) — Misnamed "decorrelation" loss**: Eq. (4) defines ℓ_dec as the L2 norm of weighted cosine similarities across prototypes. This is an L2 magnitude penalty, not a decorrelation term. True decorrelation would minimize pairwise prototype similarity (e.g., covariance-based). The current formulation penalizes high-confidence predictions rather than encouraging diversity, which is the stated goal.

**W3 (Major/Validity) — Inference Eq. (7) has a normalization error**: The max-prototype logit cos*(t^{~k}_y, f) appears both in the sum over K prototypes and as an extra β-weighted term, but the denominator divides by τ·K rather than τ·(K+β). This causes incorrect temperature scaling when β > 0, systematically affecting confidence calibration.

**W4 (Major/Claim overreach) — Overstated claims about training-free performance**: The paper claims the training-free version APPLe* "surpasses all existing training-based methods." This is only true for New class accuracy. On Base classes, APPLe* (72.21%) is far below CoOp (82.69%), Co-CoOp (80.47%), and MaPLe (82.28%). On HM, APPLe* (74.83%) is below Co-CoOp (75.83%) and MaPLe (78.55%). This selective reporting is misleading.

**W5 (Major/Evidence) — Missing variance and significance testing**: No standard deviations, confidence intervals, or statistical significance tests are reported for any experiment. Improvements of 0.05–1.55 HM points on individual datasets (Table 1) could be within noise range, especially for few-shot settings where variance is known to be high. Without variance estimates, "consistent improvement" cannot be verified.

**W6 (Major/Claim overreach) — Inconsistent "gains on all datasets" claim**: The conclusion states "consistent performance gains on all 11 datasets and all tasks." However, Table 1 shows APPLe underperforms MaPLe on Food101 New class (-0.17%) and EuroSAT Base (-3.17%). The main text should explicitly acknowledge these exceptions.

**W7 (Major/Scope) — Limited domain generalization evaluation**: Out-of-distribution evaluation only includes ImageNet-derived datasets sharing the same 1,000-class label space. True cross-dataset generalization (e.g., ImageNet-trained → SUN397 or Caltech101) is not tested. The claim "more domain-generalizable than context optimization methods" is not supported by the evidence.

**W8 (Minor/Clarity) — GPT-3 dependence and reproducibility**: The paper does not specify GPT-3 model version, API parameters (temperature, max tokens, prompt template), or the exact set of generated prompts. Different GPT-3 outputs across versions could lead to different results, making exact reproduction difficult.

**W9 (Minor/Clarity) — Few-shot comparison missing key baseline**: Few-shot experiments (Fig. 3) compare against CoOp, ProDA, and PLOT but exclude MaPLe, which is the paper's primary baseline in other settings. This inconsistency in evaluation protocols weakens the overall comparison picture.

## Key Issues
### Issue 1: Unnormalized attention weights can destabilize training (W1)
**Location**: Page 4-5, Section 4 - Adaptive Attention
**Severity**: Major | **Type**: Technical correctness

The attention matrix W ∈ R^(C×K) is applied to cosine similarities via element-wise multiplication (Eq. 2) without any normalization. This means the scale of the weighted similarities depends on the magnitude of W, which is unconstrained. Since the softmax function in subsequent loss computations (Eq. 3-5) is sensitive to input scale, an unregularized W can produce arbitrarily sharp or flat probability distributions. The paper does not discuss any constraint (e.g., L2 regularization on W, softmax across K, or value range clipping).

**Fix**: Apply softmax normalization across the K prototypes within each class: `W_c = softmax(W_c)` for c=1..C. This ensures the weights are non-negative and sum to 1, making the attention interpretable as prototype importance scores.

### Issue 2: Decorrelation loss is an L2 magnitude penalty, not decorrelation (W2)
**Location**: Page 5, Section 4 - Prototype Decorrelation, Eq. (4)
**Severity**: Major | **Type**: Technical mischaracterization

Eq. (4) computes `ℓ_dec = Σ_c Σ_k ||cos*(t^k_y, f)||^2`, which is the sum of squared weighted cosine similarities. This penalizes large-magnitude logits but does not encourage prototypes to be dissimilar from each other. Two identical prototypes with halved weights would produce the same loss as two diverse prototypes. The term "decorrelation" implies reducing pairwise similarity (e.g., minimizing the Gram matrix's off-diagonal entries), which is different from magnitude penalization.

**Fix**: Rename to "prototype magnitude regularization" or "logit sparsity penalty." Alternatively, implement true decorrelation via: `ℓ_div = Σ_c Σ_{i≠j} [cos(t^i_c, t^j_c)]^2`, which directly penalizes pairwise prototype similarity.

### Issue 3: Inference normalization error in Eq. (7) (W3)
**Location**: Page 5, Section 4 - Inference, Eq. (7)
**Severity**: Major | **Type**: Mathematical error

The numerator sums over K prototypes plus an additional β-weighted max-prototype term (total K+β effective terms), but the denominator divides by τ·K rather than τ·(K+β). This causes the logit scale to be systematically different when β ≠ 0, affecting the softmax output.

**Fix**: Change denominator from `τ·K` to `τ·(K+β)` to correctly normalize the augmented logit sum.

### Issue 4: Selective performance reporting misrepresents contributions (W4)
**Location**: Page 2 (introduction claims), Page 6-7 (experiment results)
**Severity**: Major | **Type**: Objectivity

Introduction claims that training-free APPLe* "challenges the generalization ability claimed in existing context optimization methods," and the caption text states APPLe* "surpasses all existing training-based methods." Both statements are only true for New class accuracy. On Base and HM metrics, training-based methods substantially outperform APPLe*. This selective framing could mislead readers.

**Fix**: Add explicit qualifiers: "on novel class accuracy" and report the full picture including Base and HM performance.

### Issue 5: No variance or significance testing throughout (W5)
**Location**: All experiment tables
**Severity**: Major | **Type**: Missing evidence

No standard deviations, confidence intervals, or statistical tests accompany any experimental result. For few-shot settings (known to have high variance), and for datasets where improvements are <0.5% (Food101 HM: +0.05%, OxfordPets HM: +0.25%), the significance of reported gains cannot be assessed.

**Fix**: Report mean±std over ≥3 random seeds for all experiments. Add a paired t-test or Wilcoxon signed-rank test comparing APPLe against the strongest baseline on each dataset.

## Actionable Suggestions
### S1 (Must) — Fix attention normalization (Issue 1)
Apply softmax normalization over the K prototypes within each class after learning W:
`W_c = softmax(W_c)` for c=1..C.
This ensures attention weights are non-negative, sum to 1 per class, and the overall logit scale remains bounded. Update Eq. (2) and the architecture description accordingly. Retrain and report the effect on HM accuracy.

### S2 (Must) — Correct the inference normalization in Eq. (7) (Issue 3)
Change the denominator in Eq. (7) from τ·K to τ·(K+β). This ensures correct temperature scaling when the max-prototype logit is double-counted. If β=0.2 and K=50, the corrected denominator would be τ·50.2 instead of τ·50. While the effect may be small (~0.4% logit scale difference), it is a mathematical correctness issue.

### S3 (Must) — Rename or redesign the decorrelation loss (Issue 2)
Option A (rename): Change "prototype decorrelation" to "prototype magnitude regularization" throughout the paper. The current Eq. (4) penalizes the L2 norm of weighted logits, which is a sparsity-inducing regularizer.
Option B (redesign, recommended): Replace Eq. (4) with a true diversity loss: `ℓ_div = Σ_c Σ_{i≠j} [cos(t^i_c, t^j_c)]^2`, which directly minimizes pairwise cosine similarity between prototypes of the same class. Re-run the ablation study with this corrected loss.

### S4 (Must) — Add variance reporting and significance tests (Issue 5)
For all main experiments (Table 1, Table 2, few-shot results):
- Report mean ± std over ≥3 random seeds.
- Add a paired test (e.g., Wilcoxon signed-rank) comparing APPLe against the strongest baseline across all 11 datasets.
- Report the number of datasets where APPLe wins/ties/loses against the best baseline.

### S5 (Must) — Correct overstated claims (Issue 4)
Revise the following claims to be scope-bound:
- Change "surpasses all existing training-based methods" → "achieves competitive novel-class accuracy without training."
- Change "challenges the generalization ability claimed in existing context optimization methods" → "demonstrates that diverse text prototypes can improve zero-shot CLIP performance."
- Change "consistent performance gains on all 11 datasets" → "performance improvements on the majority of 11 datasets, with detailed per-dataset results in Table 1."

### S6 (Nice-to-have) — Add GPT-3 reproducibility details
Specify: GPT-3 model version (e.g., text-davinci-003 vs. gpt-3.5-turbo), temperature, max tokens, prompt template used for generation, and the exact set of prompts per dataset (provide as supplementary material). This is critical for reproducibility.

### S7 (Nice-to-have) — Add prototype quality control baseline
In the ablation study (Table 3), add a row where K prompts are generated by repeating the class name K times with different random prefixes. This controls for whether the gain comes from GPT-3's domain knowledge vs. the multi-prototype architecture itself.

### S8 (Nice-to-have) — Report per-class prototype analysis
For each dataset, analyze: (a) what fraction of test samples have their closest prototype belonging to the correct class, (b) how attention weights correlate with prototype quality. This would directly address the cross-class semantic overlap issue identified in the retrieval experiments (Fig. 6).

### Introduction Outline (6 paragraphs)

**P1 — Motivation**: Real-world visual recognition must handle high intra-class variance. Example: apple pies vary drastically in appearance. A single prompt template cannot capture this diversity.

**P2 — Background**: CLIP and ALIGN enable zero-shot classification via text-image similarity. Prompt-tuning methods (CoOp, Co-CoOp, MaPLe) optimize continuous embeddings to improve downstream performance but retain the single-embedding-per-class constraint.

**P3 — Gap**: Why single embeddings are insufficient. Analysis showing diverse descriptions achieve higher similarity with corresponding images (Fig. 1). The single-point representation cannot cover multi-modal visual distributions.

**P4 — Proposed Solution**: APPLe generates K diverse descriptions per class via GPT-3, encodes them as text prototypes, and computes image similarity against all prototypes. An adaptive attention mechanism weights prototypes by reliability.

**P5 — Technical Details**: Training objective combines (1) average prototype cross-entropy, (2) max-prototype cross-entropy, and (3) prototype diversity regularization. Inference balances averaged and max-prototype predictions.

**P6 — Contributions + Preview**: APPLe achieves consistent gains across 11 datasets. Training-free version unlocks CLIP zero-shot potential. Limitations include GPT-3 dependence and increased computation.

### (B) Research-Theme Gap Diagnosis

1. **New knowledge (value)**: The core insight—multiple text prototypes improve coverage of visual variance—is convincingly demonstrated. However, the paper does not establish *how much* of the gain comes from GPT-3's knowledge vs. the multi-prototype architecture itself. This limits the generalizable knowledge contribution.

2. **Reproducibility**: Missing GPT-3 version/settings details, missing variance estimates, and unconventional attention formulation without normalization all reduce reproducibility.

3. **Impact on practice/understanding**: The training-free variant (APPLe*) is the most practically useful finding, but it is under-emphasized relative to the training-based results. The paper could strengthen its practical impact by framing APPLe* as a no-cost way to improve zero-shot CLIP.
