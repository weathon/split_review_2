## Summary
This paper benchmarks nine open-source mid-sized LLMs (12–16B parameters) on function/variable name recovery and type inference from stripped binaries, evaluating across four architectures, four optimization levels, and both decompiled and assembly inputs using a 40K-function dataset. The authors find that all models achieve very low F1 scores (typically <0.1), fine-tuning yields modest and inconsistent improvements, and model size does not reliably predict performance.

## Strengths
- **Broad and systematic evaluation scope**: The paper evaluates 9 LLMs across 4 architectures (x86-64, x86-32, ARM 32-bit, MIPS), 4 optimization levels (O0–O3), and 2 input formats using a 40,000-function dataset (Section 4.1). This is substantially more comprehensive than prior work that typically evaluates one or two models on a single task.
- **Controlled architecture-ablation comparisons**: By comparing DeepSeek-R1 vs. Qwen2.5 (both 14B, Tables 2/3) and CodeLlama at 7B/13B/34B (Figure 2), the paper provides concrete evidence that training quality matters more than parameter count—directly actionable guidance for practitioners.
- **CodeWordNet ablation demonstrates evaluation methodology impact**: Figure 1 shows removing CodeWordNet causes sharp F1 drops (e.g., Qwen3 O0 drops from ~0.25 to ~0.08), providing concrete evidence that strict string matching underestimates LLM capability due to semantic equivalence in naming.
- **Consistent and honest reporting of poor performance**: All models achieve F1 scores around 0.03 for zero-shot name recovery and near-zero for type inference and assembly-based recovery (Tables 2–6), transparently establishing that current LLMs are limited at these tasks.
- **Real-world firmware evaluation with two decompilers**: Table 6 evaluates on stripped real-world firmware decompiled by both Ghidra and IDA Pro, adding ecological validity. Models perform slightly better on IDA Pro output, a practically useful finding.

## Weaknesses

### Fatal
None

### Major
- **Factual inconsistency in the abstract: DeepSeek-R1's claimed 0.37 F1 score is unverifiable.** The abstract (line 19) states "after fine-tuning, DeepSeek-R1 demonstrates a notable improvement, reaching an F1 score of 0.37." However, no table shows DeepSeek-R1 achieving 0.37 on any task. Table 2: DeepSeek-R1 fine-tuned scores are 0.04–0.05. Table 3: highest fine-tuned score is 0.17 (O0). Tables 4–6: scores of 0.00–0.07. The highest values in any table are 0.33 for Qwen2.5/WizardCoder/Phi4 (Table 3, O0 fine-tuned), but these are not DeepSeek-R1. For a paper whose contribution is empirical evaluation, an unverifiable headline number in the abstract is a serious credibility issue.
- **Confusion about whether main tables use CodeWordNet or strict matching.** Section 3.4 states the authors "adopt the SYMLM method, which leverages CodeWordNet," implying all name recovery results use CodeWordNet-based partial credit. However, Figure 1 shows CodeLlama O0 achieving ~0.15 with CodeWordNet and ~0.05 without; Table 2 reports CodeLlama O0 original at 0.04—matching the "without CodeWordNet" condition. Similarly, Qwen3 O0 in Figure 1 with CodeWordNet is ~0.25, but Table 2 shows 0.05. This large, consistent discrepancy across all models shown means either the main tables use strict matching (contradicting Section 3.4) or Figure 1 measures something different that is never explained.
- **No comparison against any existing reverse engineering methods.** The paper surveys SYMGEN, RESYM, SYMIm, Debin, VARBERT, etc. but never evaluates any of them on the same dataset. Without baseline comparisons, the claim that LLMs are "fundamentally limited" is unsubstantiated—prior approaches may achieve substantially better or worse results, which is crucial context for interpreting the low F1 scores.

### Minor
- **Fine-tuning hyperparameters and training adequacy are undocumented.** The paper uses 200 steps over 160K training samples with LoRA but reports no rank, alpha, target modules, learning rate, batch size, or dropout. Without batch size, it's unclear what fraction of training data was actually seen. The conclusion that "fine-tuning has limited impact" may reflect insufficient training rather than fundamental task difficulty.
- **Auxiliary LLM for output normalization is unidentified and unvalidated.** Section 3.2 uses an auxiliary LLM to normalize heterogeneous outputs but never identifies which model is used, reports no validation of normalization accuracy, and provides no error analysis. For models like DeepSeek-R1 that generate lengthy chain-of-thought, the normalization step makes complex parsing decisions that directly determine reported scores.
- **Precision and recall are reported only as F1, not separately.** Section 4.1 says the paper uses "precision, recall, and F1 score," but all tables show only F1. Decomposed metrics would help diagnose failure modes (low precision vs. low recall) and are standard for benchmark papers.
- **Narrow domain: only GNU software.** While multi-architecture evaluation is commendable, restricting the dataset to GNU software limits generalizability to other software ecosystems.

## Novel Insights
The most striking observation from this review is the persistent, unexplained discrepancy between Figure 1 (which shows CodeWordNet boosting scores 3–5×) and the main result tables (which show scores consistent with strict matching). This isn't just a presentation issue—it fundamentally affects how readers interpret all reported F1 scores. If the main tables use strict matching, the paper's headline numbers drastically understate LLM capability on name recovery; if they use CodeWordNet, the numbers in Figure 1 are inexplicable. Resolving this would significantly change the paper's narrative.

## Suggestions
- Resolve the 0.37 claim: either present the data supporting it or correct the abstract.
- Explicitly state whether Tables 2, 3, 6 use CodeWordNet or strict matching, and reconcile with Figure 1.
- Add at least one non-LLM baseline evaluated on the same dataset.
- Report LoRA hyperparameters and a training curve (F1 vs. steps).
- Report precision and recall separately alongside F1.
