## Summary

This paper presents CONVCODEWORLD, a reproducible multi-turn code generation benchmark that systematically combines three types of feedback (compilation, execution with partial/full test coverage, and verbal feedback) into 9 distinct scenarios via a Cartesian product. It also introduces CONVCODEBENCH, a static version that uses pre-generated feedback logs to avoid costly online LLM calls, achieving Spearman rank correlations of 0.82–0.99 with the live environment. Evaluation of 17 LLMs yields several empirical findings: LLM rankings shift across feedback combinations, weaker models with sufficient feedback can exceed single-turn SOTA, training on a fixed feedback combination limits generalization, and there exists an MRR-Recall trade-off. The systematic approach to varying feedback dimensions is the paper's core contribution, going beyond prior benchmarks (InterCode, MINT) which cover only 2–3 feedback combinations.

## Strengths

- **Systematic feedback combination design**: The paper defines three feedback types and takes their Cartesian product to create 9 distinct, reproducible scenarios (Section 2.2, Equation 1). This goes beyond prior multi-turn benchmarks — InterCode and MINT cover only 2–3 feedback combinations (Table 6) — and directly enables the paper's central finding that model rankings change across feedback settings. This is a genuine methodological contribution.

- **CONVCODEBENCH demonstrates strong rank correlation with the live environment**: Using pre-generated logs from a weaker reference model (CodeLlama-7B-Instruct), the static benchmark achieves Spearman rank correlations of 0.82–0.99 with CONVCODEWORLD across the tested feedback combinations (Section 4.3, Figure 2). This provides concrete evidence that the static proxy reliably reproduces model rankings, making the benchmark practical for low-cost evaluation.

- **Empirical finding: training on a fixed feedback combination limits generalization**: The paper shows that ReflectionCoder-DS models (trained on ⟨f_c, f_e*, f_v⟩) perform worse on unseen feedback combinations (especially f_v*) compared to their DeepSeek-Coder-Instruct base models (Section 4.2.3). This is a specific, data-supported insight about the risks of feedback-diverse training.

- **Empirical finding: MRR-Recall trade-off documented**: The paper provides concrete examples where models with high MRR (e.g., GPT-4o) have lower Recall than GPT-4, and open-source models like Qwen1.5-72B-Chat achieve better Recall than higher-MRR alternatives under specific feedback settings (Section 4.2.4). This nuanced two-metric evaluation is not offered by prior single-turn benchmarks.

- **Specific evidence that weaker models with sufficient feedback can exceed single-turn SOTA**: DeepSeek-Coder-6.7B-Instruct (82.8 Recall) outperforms GPT-4o (82.3 Recall), and DeepSeek-Coder-33B-Instruct (85.4) outperforms GPT-4-Turbo (84.7) under expert verbal feedback ⟨f_c, φ, f_v*⟩ (Table 4, discussed in Section 4.2.2). These concrete numbers support the claim that multi-turn feedback can substantially level the playing field.

## Weaknesses

### Fatal

None.

### Major

- **The novice vs. expert verbal feedback distinction ($f_v$ vs. $f_v^*$) is unvalidated.** The paper labels these as "novice-level" and "expert-level" verbal feedback and treats them as simulating different human expertise levels (Section 2.2, line 64). However, the paper provides no validation — neither human evaluation nor automated analysis — demonstrating that the two GPT-4o prompting strategies actually produce feedback that differs in expertise, accuracy, helpfulness, or specificity. The prompt designs themselves are not described in the main text. This does **not** invalidate the benchmark's core value (the 9-combination framework is still a systematic variation of feedback along a dimension), but it means the interpretation of findings that rely on this distinction (e.g., "Impact of Expert-Level Verbal Feedback" in Section 4.2.1) is ambiguous: observed differences could reflect prompt wording rather than any simulated expertise gap. The paper would be strengthened by either validating the distinction or reframing it as "two different verbal feedback styles from GPT-4o."

### Minor

- **Potential bias from using GPT-4o as both feedback generator and evaluated model.** In CONVCODEWORLD, verbal feedback is generated by GPT-4o based on the code produced by the target model. When the target model is itself GPT-4o (or another GPT-family model), GPT-4o may produce feedback that is more aligned with that model's output style. The paper does not discuss this potential confound. The concern is somewhat mitigated by (a) feedback being based on code content, not model identity, and (b) CONVCODEBENCH using fixed feedback logs applied uniformly across all target models — but the live evaluation results in Section 4.2 are affected.

- **CONVCODEBENCH correlation analysis based on only a subset of the 9 feedback combinations.** CONVCODEBENCH covers only feedback combinations that involve verbal feedback (excluding 3 combinations without verbal feedback, plus one where the reference model's 100% compilation success made the scenario moot). The paper reports correlations of 0.82–0.99 without confidence intervals or significance tests (Section 4.3). While the explanations for exclusion are reasonable and the correlations are solid, reporting bootstrap confidence intervals would strengthen the claim that CONVCODEBENCH is a "reliable proxy."

- **No dedicated limitations section.** The paper lacks an explicit discussion of limitations. Key caveats worth acknowledging: the benchmark currently covers only Python code generation from BigCodeBench-Instruct; the verbal feedback is generated by a single LLM (GPT-4o); and the static benchmark covers a reduced set of feedback combinations.

## Novel Insights
