## Summary

This paper introduces *Generative Model Identification* (GMI), a problem setting in which a user submits a single example image to a generative model hub and receives the most suitable generative model(s) for that image. The proposed solution combines a weighted Reduced Kernel Mean Embedding (RKME) framework, CLIP embeddings, and an image interrogator to convert the user's image into a query matched against model specifications. A benchmark of 16 Stable Diffusion models is constructed, and the method achieves top‑4 accuracy above 80%, outperforming several baselines.

## Strengths

- **Novel problem formulation with concrete failure analysis.** The paper defines GMI with a clear two‑stage setup (Section 2.1) and provides Example 2.1 with Figure 2 showing that standard RKME cannot distinguish two generative models that differ only in the prompt‑image relationship. This evidence directly supports the claim that GMI requires new methodology beyond existing learnware/RKME approaches designed for classification.

- **Strong empirical evidence on the constructed benchmark.** Figure 3 and Table 1 show that the proposed method achieves an average rank of approximately 3 and top‑4 accuracy of 80.8% on 2,880 identification tasks using a single user image (Section 4.1). These results demonstrate the method's effectiveness within the controlled evaluation setting.

- **Ablation study isolating component contributions.** Table 2 compares four variants (Download, RKME‑Basic, RKME‑CLIP, RKME‑Concat, and the full method). The progression from RKME‑CLIP → RKME‑Concat → full method provides quantitative evidence that each component (vision model, text branch, weighted formulation) adds measurable value, supporting the design choices in Section 3.

- **Qualitative visualization confirming alignment.** Figure 4 shows that images generated by the model identified via the proposed method are visually more similar to the user's example image than those from RKME‑CLIP or RKME‑Concat, for two different comic styles, aligning with the quantitative accuracy gains.

## Weaknesses

### Fatal

None.

### Major

- **Evaluation queries are in‑distribution (closed‑set attribution, not open‑ended identification).** All 2,880 query images are generated by the 16 models on the platform itself (Section 4.1: "each testing image x_τi is generated by model f_t_i and its best matching model index is t_i"). This reduces the task to *source attribution* — can the method identify which model produced a given image? — rather than the broader claimed use case where a user brings an arbitrary external image and the system finds the model that best matches its style or content. The paper provides no evidence that the method generalizes to out‑of‑distribution queries (e.g., real photographs, artwork from unknown models), nor does it discuss this limitation. This is the single most significant gap between the central claim and the experimental support. [*Verifiable from Section 4.1, lines 169‑170.*]

### Minor

- **Weighting scheme is empirically effective but lacks analysis of alternatives.** The cosine‑similarity weighting between prompt embeddings (Eq. 9) is motivated intuitively from conditional MMD (citing Li et al. 2015; Ren et al. 2016), but no derivation, theoretical analysis, or comparison with alternative weighting functions (e.g., uniform weights, learned similarity, nearest‑prompt weighting) is provided. While the ablation (Table 2) confirms that the full weighted method outperforms concatenation and CLIP‑only variants, it does not isolate whether the specific *form* of the weighting matters or whether simpler alternatives would work as well.

- **Specific model versions are not reported.** The paper states "we adopt the official code in Radford et al. (2021) to implement the CLIP model" (Section 4.1) but does not specify which CLIP variant (e.g., ViT‑B/32, ViT‑L/14, RN50x64). Similarly, the image interrogator Z(·) is described without naming a specific model or version. These omissions hinder precise reproducibility.

- **No uncertainty quantification.** Accuracy, rank, and top‑k metrics are reported as point estimates without confidence intervals, error bars, or per‑model performance breakdowns (Figure 3, Table 1). Given that the 2,880 tasks are generated from 16 models × 18 prompts × 10 seeds, there is inherent variability across seeds and models that is not quantified.

- **Benchmark size is limited.** The platform contains only 16 models, all from the same category on CivitAI. While the paper notes this simulates category‑level filtering, it limits the difficulty and generality of the task. The paper does not discuss how the method would scale to hundreds or thousands of models (e.g., computational cost of the interrogator for each query, storage requirements for specifications).

## Suggestions

1. **Add an out‑of‑distribution experiment.** Even a small‑scale study (e.g., 50 external images with human evaluation) would substantially strengthen the central claim. If OOD performance is reasonable, this addresses the main criticism.

2. **Ablate the weighting function.** Compare cosine similarity (current) against uniform weights, learned similarity, and the CLIP image‑text matching score. This would demonstrate whether the specific weighting form is crucial or incidental.

3. **Report per‑model results and confidence intervals.** Provide per‑model accuracy and rank, and show variability across the 10 seeds (e.g., error bars on accuracy). This would strengthen the statistical grounding of the results.

4. **Specify model versions.** Name the exact CLIP variant and interrogator model used. This is a simple fix for reproducibility.
