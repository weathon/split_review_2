## Summary

This paper proposes Exploratory Inverse Constraint Learning (ExICL), a method that recovers a diverse set of feasible constraints from offline expert demonstrations — addressing the inherent ill-posedness of ICL where multiple constraints can equivalently explain expert behavior. The key innovations are: (1) a Generative Diffusion Verifier (GDV) that uses guided denoising to efficiently check whether a candidate constraint allows reproducing expert trajectories, bypassing expensive policy optimization; (2) a noise-robust constraint update that enables the diffusion model to correctly predict costs on noisy trajectories; and (3) a contrastive regularization term that encourages the learned constraint set to be diverse. Experiments on PointMaze, MuJoCo, and autonomous driving tasks show that ExICL achieves better reward-cost trade-offs than baselines (ICSDICE, OptiDICE-Constraint, SMODICE), discovers more diverse constraints, and improves sample efficiency.

## Strengths

- **Novel problem framing with practical value**: Instead of pursuing a single "minimum" constraint (which prior work acknowledges may not match the true constraint), ExICL targets a *diverse feasible set* of constraints. This is a well-motivated response to the ill-posedness of ICL and provides practitioners flexibility to select constraints based on deployment needs (Section 1, Definition 3.1).

- **GDV provides a principled efficiency improvement**: The use of guided denoising (extending Diffuser to the CMDP setting via Eq. 9–10) to verify constraints without iterative policy/value function updates is creative and well-grounded in the duality of constrained RL (Theorem 4.1). The method avoids the bi-level optimization bottleneck that makes prior ICL methods computationally expensive for set recovery (Section 4.1, lines 137–139).

- **Consistent empirical advantage in constraint accuracy**: Across PointMaze (Table 1) and three MuJoCo tasks (Table 2), ExICL achieves the lowest cumulative cost and competitive or highest reward against six baselines including dedicated ICL methods (ICSDICE, OptiDICE-Constraint) and imitation learning methods (BC, LS-IQ, SMODICE). The cost improvements are substantial in several settings (e.g., 7.16 vs. 17.36 in HalfCheetah).

- **Noise-robust constraint update is well-motivated**: Section 4.2 correctly identifies that for GDV to steer the denoising process, the constraint/permissibility model must accurately predict costs on *noisy* trajectories. Extending the standard ICL gradient to noise-augmented trajectories (Eq. 11) directly addresses this requirement and is a necessary design component for the diffusion-based verification pipeline.

- **Contrastive diversity objective is principled**: The exploratory regularization (Eq. 12–13) adapts InfoNCE loss to treat constraint functions as embeddings to be separated, providing a principled alternative to ad-hoc noise injection or random initialization baselines (Section 4.3).

## Weaknesses

### Fatal
None.

### Major

- **The source of D^P in the constraint update is underspecified, creating ambiguity about the verification pipeline.** The noise-robust constraint update (Eq. 11, line 148–151) requires D^P, defined as "the nominal trajectory data generated by policy π under CMDP M_c (with the estimated cost before update)." The paper does not clarify whether D^P is (a) generated by GDV itself, (b) drawn from the offline non-expert dataset D^{−E} (defined in Definition 3.1), or (c) produced by a separate CRL policy — which would reintroduce the computational overhead GDV claims to avoid. The efficiency claims (Figure 6, Section 5.3) hinge on this point: if a separate policy generates D^P, the GDV's advantage is limited to the final verification step, not the iterative constraint update loop. This specification gap undermines reproducibility and weakens the core efficiency narrative. *The paper should explicitly state the provenance of D^P and how it relates to the GDV pipeline.*

- **No explicit metric or threshold is given for the GDV feasibility check.** The paper states that GDV validates constraints "by comparing the generated trajectories τ̃ ∼ p̃_{M_c}(τ) with the expert ones τ^E" (lines 139–140), but never specifies what comparison is used — likelihood ratio, trajectory divergence (KL/MMD), cost threshold violation, or something else. This makes the core algorithmic loop (propose constraint → verify via GDV → accept/reject) unimplementable from the paper alone. Since the method's entire efficiency advantage rests on replacing CRL policy optimization with this verification step, the verification criterion must be precisely defined.

### Minor

- **Diversity evidence relies on a single quantitative metric (cost variance) plus qualitative visualizations.** Section 5.2 shows that ExICL achieves higher variance in predicted costs on constraint-violating trajectories compared to random-noise and random-initialization baselines (Figure 4). While this is valid evidence, it is narrow: a constraint set could have high cost variance while still being functionally similar (e.g., the same constraint at different scalings). The paper would benefit from additional metrics such as pairwise distance between learned constraint functions (e.g., L2 norm over the cost map) or the number of constraints that independently pass the GDV feasibility check. Figure 5 provides qualitative behavioral differences in MuJoCo, which is illustrative but not quantitative.

- **The Lagrange multiplier λ in the GDV guided denoising (Eq. 10) is not specified.** The paper invokes strong duality (Theorem 4.1) to transform the constrained objective into a penalty form with λ, but does not describe how λ is chosen during trajectory generation — whether it is learned, optimized per constraint candidate, or fixed with some justification. Since the guided sampling quality depends on λ, this is a missing implementation detail that affects reproducibility.

- **The learning efficiency experiment (Figure 6) lacks explicit textual identification of compared baselines.** The text mentions "three methods" and "the EX-ICL curve" but does not name the baselines in the running text. While the figure labels are likely present in the image, the text should explicitly state which methods are being compared (presumably ICSDICE and OptiDICE-Constraint, based on the experimental context) and account for the upfront cost of diffusion model training (the "orange ellipse" region).

- **No ablation of the noise-robust training component (Eq. 11).** The paper describes this as a key design element for GDV compatibility but provides no experiment comparing the full method against a version trained only on clean trajectories. Without this ablation, the necessity and impact of noise-robust training cannot be assessed.

- **No limitations or failure mode discussion.** The paper does not discuss scenarios where the approach might fail — e.g., when the diffusion model's approximation error is large, when the guidance with a poorly chosen λ produces unrepresentative trajectories, or when the contrastive objective pushes constraints away from feasibility. Including such discussion would strengthen the paper.

## Nice-to-Haves

- **Ablation on δ (diversity regularization strength):** Showing how δ affects both (a) the number/variance of learned constraints and (b) constraint accuracy (cost under the true constraint) would demonstrate that diversity does not come at the expense of feasibility.

## Suggestions

1. **Clarify the D^P provenance**: Explicitly state whether D^P is drawn from the offline non-expert data D^{−E}, generated by GDV, or produced by a policy. If GDV generates it, explain how the diffusion model's output feeds the constraint update loop. If D^{−E} is used, state this clearly.

2. **Define the feasibility verification metric**: Specify the exact comparison function (e.g., average per-step log-likelihood of expert trajectories under the guided distribution, or MMD/divergence threshold) used to accept/reject a candidate constraint. This is essential for reproducibility.

3. **Add quantitative diversity metrics**: Report pairwise distances between learned constraint functions (e.g., L2 norm of φ_ω parameter differences or cost map differences) and the number of constraints that pass the GDV feasibility check, to complement the cost variance metric.

4. **Specify λ selection**: Describe how the Lagrange multiplier λ is chosen for the guided denoising (Eq. 10) — fixed, learned, or scheduled — and whether it interacts with the diversity regularization parameter δ.

5. **Include an ablation for noise-robust training**: Compare the full method against a variant using the classic (non-noise-robust) MLE gradient to isolate the impact of Eq. 11.

## Score and Decision

This paper makes a genuine contribution to the inverse constraint learning literature. The motivation (diverse feasible set vs. single identifiable constraint) is well-grounded in the fundamental ill-posedness of ICL, and the GDV approach to verification is a creative application of diffusion-based planning. The empirical evidence for accuracy (Tables 1–2) is strong across multiple domains, and the diversity results (Figure 4) show a measurable improvement over naive baselines.

The main weaknesses are specification gaps (D^P provenance, verification metric, λ selection) rather than fundamental flaws or incorrect results. These are addressable in a rebuttal. The paper is a solid contribution that meets the bar for publication.
