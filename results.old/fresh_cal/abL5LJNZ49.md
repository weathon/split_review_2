## Summary

The paper proposes SCHEMA, a framework for procedure planning in instructional videos that explicitly models state changes. It represents each action step via LLM-generated (GPT-3.5) before/after state descriptions using chain-of-thought prompting, aligns visual observations with these descriptions through contrastive learning, and decomposes planning into mid-state prediction and step prediction. Experiments on CrossTask and COIN show consistent improvements over prior methods.

## Strengths

1. **Novel step representation as state changes via LLM-driven description generation.** The paper proposes representing each action step by its before- and after-state descriptions, generated by GPT-3.5 with a chain-of-thought prompting strategy (Sec. 3.2). This goes beyond prior work (P³IV, PDPP) that treated steps as atomic labels. The prompt design is detailed and addresses a concrete failure case of naive prompting.

2. **Clean architectural decomposition into mid-state and step prediction.** The formulation in Equation (1) factorizes procedure planning into $p(s_{1:T-1}|s_0,s_T)$ and $p(a_{1:T}|s_{0:T})$, providing a principled way to inject state-change information. The ablation (Table ab_state) shows that adding mid-state prediction improves SR by up to 1.68% when combined with state alignment, directly supporting the claim that modeling state changes helps.

3. **Strong and consistent empirical results.** On CrossTask (T=3), SCHEMA achieves SR 31.83 vs. P³IV 23.34 and EGPP 26.40. On COIN (T=3), SR 28.12 vs. P³IV 11.32. Improvements hold across T=3,4,5,6 and on all three metrics (SR, mAcc, mIoU), demonstrating robustness of the approach.

4. **Outperforms PDPP under both evaluation settings.** The paper identifies that PDPP uses a different state temporal-window definition (Sec. 4.2). It provides a separate comparison table (tab:pdpp) showing SCHEMA outperforms PDPP under both the conventional setting and PDPP's setting (e.g., SR 35.12 vs. 33.54 for T=3 on CrossTask), showing the gain is not due to evaluation differences.

5. **Efficient inference.** SCHEMA performs a single forward pass with Viterbi post-processing, avoiding the 1,500-sequence sampling required by P³IV (Sec. 3.4 Inference).

6. **Qualitative evidence of interpretable state alignment.** Figure similarity (referenced in Sec. 4.2) shows top-5 retrieved language descriptions for start/goal frames match visual content, illustrating that the learned vision-language alignment is interpretable.

## Weaknesses

### Fatal
None.

### Major
None. The issues below are addressable in a rebuttal/revision and do not undermine the paper's core empirical contributions.

### Minor

1. **No direct validation that predicted intermediate state embeddings correspond to actual visual states.** The mid-state prediction loss (Eq. 3) uses the average of LLM-generated description embeddings as targets, with no visual supervision for intermediate states. While the ablation shows this component improves planning performance, the paper does not evaluate whether the predicted embeddings $s^{\text{dec}}_t$ are actually closer to real visual frames of the corresponding step than random baselines (e.g., via nearest-neighbor retrieval on a held-out subset). The claimed "structured state space" would be strengthened by such validation.

2. **PDPP comparison presentation could be clearer.** The paper correctly identifies the different state definition used by PDPP and provides a separate fair-comparison table (tab:pdpp). However, the main results tables (tab:sota, tab:coin) include PDPP without specifying which state definition was used for each entry. A reader scanning the main tables might misinterpret the relative ordering. The information is available in the text, but the presentation is suboptimal.

3. **No systematic evaluation of LLM-generated description quality.** The paper provides two anecdotal examples and an empirical observation about the prompt design, but no human ratings, agreement scores across multiple LLM calls, or comparisons against alternative description sources (e.g., random descriptions, template-based descriptions). The ablation shows the two trained components help, but the unique contribution of the *specific LLM descriptions* (vs. any structured text) is not isolated.

4. **NIV results not shown in the main text.** The abstract and datasets section (Sec. 4.1) claim evaluation on three datasets — CrossTask, COIN, and NIV — but the results section (Sec. 4.2) only discusses and references tables for CrossTask and COIN. While NIV results may exist in the appendix, the main paper should at least reference them.

5. **No confidence intervals or error bars.** Given the modest dataset sizes and the stochasticity of GPT-3.5 output, single-run numbers provide an incomplete picture of result reliability. Reporting variances across multiple runs would increase confidence.

6. **GPT-3.5 temperature and filtering not reported.** The paper does not state the temperature setting, number of samples generated per step, or any filtering/rejection criteria for the LLM outputs, which affects reproducibility.

7. **Viterbi post-processing not ablated.** The Viterbi transition matrix is estimated from global action co-occurrence frequencies, and its effect is not isolated in an ablation. It is unclear how much the reported results depend on this post-processing heuristic vs. the core model.

### Trivial
- The contrastive loss (Eq. 2) uses a sum (rather than average) of dot products over $K=3$ descriptions per step. Since $K$ is constant across all step classes, the difference is a uniform scaling factor and does not affect the relative ordering. This could be clarified to avoid confusion.

## Nice-to-Haves

- An ablation replacing LLM descriptions with random descriptions, template-based descriptions, or step names alone would isolate the contribution of LLM knowledge.

## Removed Points
- **"Information leak" concern (Harsh Critic Sec. 3.3 note):** The critic claims that using description embeddings as both external memory (cross-attention) and supervision targets creates a "potential information leak." The state decoder attends to description embeddings via cross-attention, while the loss target is the *average* of description embeddings — these are different operations serving different purposes. Using external knowledge as both conditioning and supervision is a deliberate design choice, not a flaw. Removed as a misunderstanding of the architecture.
- **Contrastive loss sum vs. average (Harsh Critic Training note):** The critic claims "longer descriptions (more tokens) will naturally have higher magnitude." Since $K=3$ is fixed and each description embedding is a pooled representation (from the language encoder), there is no variable-length token effect. The sum vs. average is a constant scaling. Removed as factually incorrect about the implementation.
- **"Mid-state loss averages potentially very different descriptions" (Harsh Critic Training note):** The critic argues that the after-state of step $t$ and before-state of step $t+1$ "could describe quite different things." But a mid-state $s_t$ is *by definition* the after-state of $a_t$ and the before-state of $a_{t+1}$ — they refer to the same physical state. The descriptions are expected to be consistent. Removed as a misunderstanding of the formulation.

## Novel Insights

The two reviews together surface a tension worth noting: the paper's strongest evidence (improved planning performance on real benchmarks) is aggregate and task-level, while its weakest evidence is at the representational level (what do the intermediate state embeddings actually encode?). The paper implicitly assumes that better planning implies better state representations, but the mapping from representation quality to planning quality is not isolated. A focused experiment — e.g., using predicted intermediate embeddings for retrieval on videos that *do* have intermediate annotations — would address this gap directly. That said, the paper's core claim ("state changes matter for procedure planning") is well-supported by the planning results alone; the representational claim ("structured state space") is the part that would benefit from additional evidence.
