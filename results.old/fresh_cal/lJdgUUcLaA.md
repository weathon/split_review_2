## Summary

The paper introduces AlphaIntegrator, a system for step-by-step indefinite integration that combines a tiny GPT-style transformer (10M params) with a symbolic engine. The model is trained on synthetic step-by-step integration data derived from SymPy's manualintegrate module, then uses beam search to propose integration rule actions that are executed by the symbolic engine, guaranteeing correctness. On a held-out test set of 10k integrals, the system achieves 87.3% accuracy vs SymPy's 83.3% (with 12x more timeout) and GPT-4o-mini's 65.5%, while exploring roughly 50% fewer search nodes.

## Strengths
- **Outperforms SymPy on completeness**: AlphaIntegrator achieves 87.3% accuracy on the test set vs SymPy's 83.3% (Table 1), despite being trained on data generated by SymPy. This demonstrates genuine improvement beyond the teacher.
- **More efficient search**: The model explores an average of 12.9 tree nodes per successful integration vs SymPy's 25.6 (Section 7.2, Figure 3), a reduction of ~50%.
- **Dramatically better robustness**: On perturbed inputs (e.g., $k_1 \sin(k_2 x)$, $k_1 \cos(k_2 x)$), AlphaIntegrator's Fail@5 is 0.2% and 0.0% respectively, compared to the prior seq2seq model's Fail@10 of 19.6% and 20.7% (Table 2). This convincingly shows that delegating arithmetic to a symbolic engine avoids the "symbolic brittleness" of direct antiderivative prediction.
- **Extremely small model achieves strong results**: The transformer uses only 10M parameters (6 layers, hidden dim 384) yet outperforms both a symbolic solver and GPT-4o-mini. This demonstrates the data efficiency of the action-search paradigm.
- **First rigorous step-by-step integration dataset**: The paper constructs and releases a dataset of 42.5M integration steps mapped to a formal action space, which did not exist before this work.
- **Identifies concrete limitations in SymPy**: Three specific failure modes of SymPy's manualintegrate are documented (Table 4), providing practical insight into where the learned policy generalizes beyond the teacher.

## Weaknesses

### Fatal
None.

### Major
- **Test set composition and the SymPy accuracy discrepancy are not explained**: The test set consists of 10k expressions "with integration steps" drawn from the same data generation pipeline (random tree sampling → SymPy manualintegrate → IBP augmentation). The paper reports SymPy accuracy at 83.3%, yet if all test set expressions have step-by-step solutions derived from SymPy, the paper must explain why SymPy fails on 16.7% of them within 120 seconds. If the test set includes expressions from the integration-by-parts augmentation that SymPy cannot directly solve from scratch (because their steps were derived from related expressions), then the accuracy comparison conflates two different failure modes. This gap needs clarification. *(Referenced: Section 5 "Generating A Synthetic Mathematical Integration Dataset", Section 8.1 "Test Set Accuracy")*

- **"Node" is undefined for SymPy, undermining the efficiency comparison**: The paper reports that AlphaIntegrator explores 12.9 nodes vs SymPy's 25.6, but it never specifies what constitutes a "node" for SymPy's manualintegrate. SymPy's heuristic pattern matcher does not perform tree search in the same sense as the transformer-guided beam search, so the two numbers may be incommensurate. Without a definition of what counts as a "node" for each system, the 50% reduction claim cannot be properly evaluated. *(Referenced: Section 8.2 "Efficient Tree Exploration")*

### Minor
- **Generalization claims are overstated given the evaluation scope**: The paper asserts "strong generalization" and "surpassing its data generator," but the test set is drawn from the same distribution as the training data (random polynomial-trigonometric expressions). The model has not been tested on any external benchmark (e.g., textbook integrals, integration bee problems, integrals involving functions not seen in training). While beating the teacher on its own distribution is a real achievement, it does not constitute "strong generalization" in the sense the term typically implies; a more appropriate framing would be "outperforming its teacher on the teacher's own distribution." *(Referenced: Abstract, Section 4.2, Section 8)*

- **Robustness comparison uses different beam sizes**: Table 2 reports Fail@10 for the seq2seq baseline vs Fail@5 for AlphaIntegrator. Although the results are striking (AlphaIntegrator with beam 5 still vastly outperforms the baseline with beam 10), the asymmetry in beam size should be acknowledged and ideally controlled for a cleaner comparison. *(Referenced: Section 8.3, Table 2)*

- **Complete inventory of symbolic engine actions is not provided**: The paper mentions specific rules (URule, PartsRule, AddRule, ConstantRule, ArcSinh rule) in examples but does not give a full listing of the action space. This makes it difficult for readers to assess whether the action space is sufficiently expressive, and it hampers reproducibility. *(Referenced: Section 3 "Symbolic Engine with Parametric Action Space")*

- **Failure mode analysis is missing**: The paper reports 87.3% accuracy but never analyzes the 12.7% failure cases. Understanding whether failures stem from action prediction errors, search strategy limitations (greedy depth-first), or missing rules in the symbolic engine would significantly strengthen the paper and guide future work. *(Referenced: Section 8 "Experimental Evaluation")*

### Trivial

## Nice-to-Haves
- **Fine-tuned small transformer baseline**: The paper claims that "standard fine-tuning of LLMs on question-answer pairs is insufficient" for this task, but the only LLM baseline is GPT-4o-mini with zero-shot CoT. A direct baseline of a comparable-size transformer (10M params) fine-tuned on (expression → antiderivative) pairs or (expression → step sequence) without symbolic engine guardrails would directly test whether the action-search architecture is necessary or whether the synthetic data itself drives performance.
- **Ablation of beam size**: Showing how accuracy varies with beam size N (e.g., N=1, 3, 5, 10) would demonstrate the sensitivity of results to search effort and support the claim that beam search is beneficial.
- **Controlled efficiency comparison**: Comparing node counts only on the subset of integrals that both systems solve correctly would control for the confound where AlphaIntegrator's lower average node count may partly stem from solving different (easier) problems.

This reasoning is backwards: SymPy already receives 12× more time. If anything, this asymmetry *favors* SymPy, making AlphaIntegrator's accuracy advantage conservative, not inflated. ## Suggestions
1. **Clarify test set construction**: Explicitly state what fraction of the test set (if any) consists of IBP-augmented expressions that SymPy cannot directly solve from scratch. If such expressions are present, explain why the comparison is still fair (or re-run the comparison on only the subset where both systems have an equal starting point).
2. **Define "node" for SymPy**: State what counts as a node for SymPy's manualintegrate (e.g., recursive calls, heuristic attempts) and note any differences from the AlphaIntegrator definition. Alternatively, use wall-clock time or a different efficiency metric.
3. **Tone down generalization claims**: Replace "strong generalization" with language like "outperforms the teacher on its own domain" or "generalizes beyond the teacher's heuristic coverage within the same expression distribution."
4. **Add failure analysis**: Categorize the 12.7% failure cases into action prediction errors, search failures, and missing engine rules.
5. **Release the complete action space inventory** in the appendix or supplementary material.

## Score and Decision

The paper presents a solid approach — applying the LLM+symbolic-engine paradigm to step-by-step integration — with genuinely impressive results (a 10M model outperforming SymPy and GPT-4o-mini while being more efficient). The main weaknesses are in evaluation clarity, not fundamental methodology. The test set composition issue is the most significant concern, but it is addressable through clarification rather than requiring new experiments. The efficiency comparison and generalization claims need more careful framing but do not invalidate the core contribution.
