## Summary

This paper tackles the underexplored problem of readability in SVG code generated by deep learning models. The authors propose three readability desiderata (Good Structure, Appropriate Element Use, Redundant Element Removal), define three corresponding metrics (SPI, ESS, RQ), and design differentiable proxy losses (L_SC, L_EA, L_RR) to optimize SVG generators toward these readability objectives. Evaluation is conducted via a GPT-3.5 comprehension study on the SHAPES dataset and font reconstruction experiments on SVG-Fonts.

## Strengths

- **Clear identification of a real gap in prior work (Sec. 1):** The paper explicitly documents that existing SVG generators (Im2Vec, DeepVecFont, DualVector) produce "a complex web of path elements, with intricately defined Bezier curves and redundant nodes," while prior evaluation focused solely on visual accuracy. This articulation of the overlooked readability problem is concrete and well-supported by the paper's own examples.

- **First formal set of readability desiderata (Sec. 2.1):** The three principles—Good Structure, Appropriate Element Use, and Redundant Element Removal—provide a structured framework for thinking about SVG code quality where none existed before in the SVG generation literature.

- **Novel quantitative metrics for SVG readability (Sec. 2.2):** Equations (1)–(3) for SPI, ESS, and RQ are the first dedicated quantitative measures targeting SVG code readability, as opposed to the visual accuracy metrics (SSIM, IoU) that previous work relied on exclusively.

- **Differentiable proxy losses for inherently discrete objectives (Sec. 3.2):** The paper recognizes that element type selection and redundancy detection are discrete and designs differentiable proxies (L_EA via edge detection on rasterized output, L_RR via gradient magnitude). While imperfect, these represent a reasonable first attempt at making readability optimizable via gradient descent.

- **Ablation study showing each loss improves its corresponding metric (Table 3, Sec. 4.4):** Adding L_SC improves SPI, L_EA improves ESS, and L_RR improves RQ over the base VAE, confirming each loss term has a measurable effect on its target.

## Weaknesses

### Major

- **Abstract directly contradicted by the paper's own results:** The abstract claims "significant improvements in code readability **without compromising visual accuracy**" (emphasis added). However, Table 2 shows the proposed method achieves substantially lower accuracy than baselines (SSIM 0.67 vs. 0.74 for Multi-Implicits and 0.80 for Im2Vec; L1 and s-IoU also much worse). Section 4.3 itself acknowledges a "Compromise in Accuracy" and describes a "balanced trade-off." This contradiction between the headline claim and the evidence is a serious issue.

- **GPT-3.5 study is not a valid measure of human readability and is critically underspecified (Sec. 4.2):** The paper uses GPT-3.5's ability to answer questions about SVG code as a proxy for readability. This conflates language-model parsability with human readability—two very different concepts. The experimental setup is underspecified: no information is given about the number of images, the exact questions asked, the prompt format, the variability of results (no error bars or significance tests in Table 1), or how the baselines' outputs were handled. Furthermore, the paper states that their method works by "predefining the number of simple shapes in accordance with the characteristics of the test images," which gives their method prior knowledge about the target structure that baselines do not receive, making the comparison inequitable.

- **Core readability metrics unvalidated against human judgment (Sec. 2.2):** SPI, ESS, and RQ are proposed as measures of readability, but no human study or user evaluation is conducted to establish that these metrics correlate with how humans actually perceive SVG code readability. Without such validation, these remain ad-hoc indices. The paper acknowledges this limitation but does not address it—this is the foundational weakness upon which the entire evaluation rests.

- **Loss weights omitted from the paper, harming reproducibility (Sec. 3.3):** The overall objective in Section 3.3 is written as a simple sum with the explicit note "the weight of each term is omitted from the equation." While a parameter study (Table 4) shows that weight choices affect results, the specific weights used for the main experiments (Table 2) are never reported. Combined with the vague architectural description (the encoder is just "a convolutional network," decoder operation is described in one sentence), the method cannot be reproduced from the paper alone.

### Minor

- **RQ metric (ΔR definition) is underspecified (Sec. 2.2.3):** The formula for RQ uses ΔR(e_i) to "quantif[y] the change in rendering when an element e_i is omitted," but no formal definition is given (e.g., pixel-wise L2 difference? SSIM? some other metric?). This makes the metric impossible to interpret or reproduce.

- **SPI formula includes a constant term that adds unnecessary confusion (Sec. 2.2.1):** The term |i+1−i| in the SPI formula always equals 1, making it a constant offset in the sum. The paper's explanation that "This part is included for conceptual clarity" is not convincing; the metric would behave identically without it, and most readers will find it confusing rather than clarifying.

- **Cross-architecture comparison in Table 2 conflates architecture choice with readability loss effect:** The font reconstruction comparison pits the authors' VAE-based method (with readability losses) against Im2Vec (transformer-based) and Multi-Implicits (multiple implicit functions). The authors' base VAE is already substantially less accurate (as acknowledged in Sec. 4.3), so the accuracy gap in Table 2 primarily reflects architectural differences, not the effect of readability losses. The ablation study (Table 3) partially addresses this by testing the same base model with/without losses, but the main comparison Table 2 remains unfairly stacked.

## Nice-to-Haves

- A human evaluation study validating the readability metrics would significantly strengthen the paper. This could be a user study where participants rate SVG code readability or perform editing tasks, with their judgments compared to SPI/ESS/RQ.
- The L_EA proxy (edge detection on rasterized output) is acknowledged to be only indirectly related to element simplicity. A loss that more directly penalizes complex element types (e.g., via a differentiable relaxation of element-type selection) would be a stronger design.
- Architecture details (encoder depth, kernel sizes, latent dimension, decoder architecture) should be specified to support reproducibility.

## Suggestions

1. **Resolve the abstract/evidence contradiction.** If accuracy is compromised, say so honestly up front. The current framing undermines trust in the paper.
2. **Either conduct a human evaluation of readability or significantly downscale the claims about readability.** Without human validation, the metrics remain uncalibrated indices.
3. **Report the loss weights used in all main experiments.** Without this the paper cannot be reproduced.
4. **For the controlled experiment (Table 3), also report accuracy metrics** so readers can see how much each readability loss costs in accuracy.
5. **Either provide full specifications for the GPT-3.5 study (prompts, sample counts, error bars) or remove it** in favor of a more rigorous evaluation.
6. **Formally define ΔR(e_i) in the RQ metric.**
