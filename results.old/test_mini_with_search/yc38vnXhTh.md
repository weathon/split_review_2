## Summary

This paper introduces ACTOR, an LLM-powered agent for simulating human behavior in 3D scenes, and BEHAVIORHUB, a large-scale dataset of 10k human behavior samples across 1.5k scenes with linguistic plans and motion sequences. ACTOR uses value-driven hierarchical tree search (with real-valued and language-based value functions) to decompose goals and adapt to environmental dynamics. The dataset is generated semi-automatically via LLM distillation with human verification. Experiments show ACTOR outperforms baselines (LLMaP, HuggingGPT) on planning and simulation metrics, and BEHAVIORHUB improves downstream motion generation tasks.

## Strengths

1. **Value-driven hierarchical planning is well-motivated and ablated.** The integration of real-valued (shortest-path) and language-based (e.g., "a neat person") value functions into a unified probability for plan selection is a clean formulation that distinguishes this work from prior LLM-as-planner methods that require retraining. The ablation study (Table 3a) confirms the contribution of each component — hierarchical prior (+7.6% BERT-S, +1.6% GSR on Dynamic), value functions (+4.4% GSR), and active tree search (+8% GSR) — providing concrete evidence for the architecture's design.

2. **BEHAVIORHUB is a large-scale, practical asset.** At 10k samples across 1.5k scenes with 8.6M motion frames, the dataset is an order of magnitude larger than previous human-authored resources (ActivityPrograms). The human verification of all samples by three annotators is a notable quality-control step. Downstream task results (Table 4) provide convincing evidence of the dataset's utility beyond planning: FID improves from 19.94→16.73 on PROX and from 0.63→0.52 on HumanML3D.

3. **Human evaluation provides a direct sanity check on planning quality.** The human ratings on the Dynamic subset (Table 2) compare ACTOR, LLMaP, HuggingGPT, and human-written plans on completeness, rationality, and quality using a 5-point Likert scale. This is a meaningful step beyond automatic metrics and shows ACTOR (3.05/3.47/3.75) meaningfully outperforms baselines (LLMaP: 2.23/2.48; HuggingGPT: 2.71/2.89/3.18), though still below human-written plans (4.02/4.85).

4. **Modular scalability is cleanly demonstrated.** Table 3c shows monotonic improvement as the LLM core is upgraded (Vicuna-7b: 17.7% GSR → GPT-3.5: 21.3% → GPT-4: 27.0%), supporting the claim that the framework can leverage advances in base LLMs without architectural changes.

## Weaknesses

### Fatal
None.

### Major

1. **The planning evaluation has a circularity problem that is only partially mitigated.** The ground-truth plans in BEHAVIORHUB are themselves generated by an LLM pipeline (GPT-4 — the same model family used by ACTOR). The automatic metrics (Sentence-BLEU, BERTScore) therefore measure how well predicted plans match LLM-generated ground truth, not how well they match genuinely correct plans. The human verification of all 10k samples (three annotators vote on completeness/validity) provides partial mitigation, and the human evaluation on the Dynamic subset (300 samples, Table 2) independently validates ACTOR's output quality against human-written plans. However, the automatic metrics on the full benchmark — which constitute the paper's primary quantitative evaluation — remain tainted by this circularity. The gap to human-written plans in the human eval (e.g., ACTOR 3.05 vs. Human 4.02 on Completeness) also suggests room for skepticism about how much of the automatic metric gain reflects genuine planning ability versus alignment with LLM biases.

2. **The HuggingGPT baseline adaptation is critically underspecified.** The paper states it benchmarks HuggingGPT as a "general tool agent" (Section 6.1) but provides no description of how HuggingGPT was given access to the 3D environment, what perception models, motion generators, action primitives, or prompt structure were provided to it. Without this, the comparison is uninterpretable: if HuggingGPT was given a weaker action interface, its poor GSR (0.21 on Main vs. ACTOR 0.38) simply reflects that it was ill-equipped for the task, not that its planning is inferior. This weakens the headline claim that ACTOR "nearly doubles the success rate."

### Minor

1. **No variance or statistical significance is reported.** All quantitative tables (Tables 1, 3, 4) report point estimates without error bars, confidence intervals, or significance tests. Given stochastic elements (LLM sampling, tree search), results could vary across runs. This is especially concerning in Table 3a where differences between adjacent rows are small (e.g., GSR 0.380 vs. 0.394). While single-run evaluation is common in some LLM-agent papers, the lack of variance estimates limits confidence in fine-grained comparisons.

2. **The perception module is a black box.** Section 4.1 describes perception using "readily available models" and "heuristic functions" without naming the specific models, detection criteria, or robustness characteristics. Since the Dynamic subset manually configures environment states, the perception module is essentially bypassed in the main experiments. This does not invalidate the lab results, but it makes it impossible to assess how the system would perform under realistic perception noise in novel environments.

3. **The conversion of language-based value classifications to probabilities is ad hoc.** The paper maps "sure/more-likely/less-likely/impossible" to probabilities 1.0/0.7/0.3/0.01 (Section 4.2) without justification or sensitivity analysis. While the ablation (Table 3a) shows the value function contributes overall, it does not disentangle the real-valued and language-based components, nor test sensitivity to the specific probability assignments.

4. **Inter-rater reliability is not reported for the human evaluation.** With five judges, standard metrics (Fleiss' kappa, Krippendorff's alpha) would help assess whether ratings are consistent or driven by a single outlier.

### Trivial
- The paper lists "barrier (iv)" (absence of a comprehensive testbed) alongside three agent-oriented barriers (i-iii), though it is qualitatively different — it is a limitation of prior benchmarks rather than an agent capability barrier. This is a framing inconsistency but does not affect the technical content.

## Nice-to-Haves
- Validate planning quality against a human-authored gold standard for a subset of goals (e.g., 50-100 goals commissioned from humans). This would directly address the circularity concern and provide a cleaner assessment than human-evaluating only 300 samples.
- Include a sensitivity analysis of the value function probability thresholds (1.0/0.7/0.3/0.01) to rule out brittleness to these arbitrary numbers.
- Provide a complete list of motion success thresholds (SSR) for all action types, not just the lying-down example (30 cm).
