# Final Review Report

## Summary

This paper proposes a hierarchical attention model (CodeTransformer-GAT) for learning code state representations in reinforcement learning settings. The method combines token-level transformer attention, function-level graph attention over ASTs, and module-level attention over code dependency graphs (CDGs), producing a multi-level embedding that is optimized end-to-end via the policy gradient objective. The approach is evaluated on three code-related RL tasks — code completion (PY150), program repair (ManySStuBs4J), and algorithmic problem solving (APPS) — against five baselines including CodeBERT, Tree-LSTM, and a flat GAT.

**Core assessment:** The paper introduces a technically plausible architecture for hierarchical code representation in RL and reports competitive results (Table 1 shows improvements of 4.5–6.6% absolute over CodeBERT). However, the manuscript in its current form has severe writing quality issues that prevent it from being publishable without major revision. Multiple sections contain grammatically broken or incomprehensible text (Introduction paragraphs 2–3, Section 2.2, Conclusion), placeholder content (empty Limitations section, missing figures for t-SNE analysis), and factual-reporting errors (unsubstantiated significance testing claims, unidentified baseline models in scalability analysis). The Conclusion contains a catastrophic phrasing error ("hierarchical cherry-picking") that alone would require rewriting. The mathematical presentation has inconsistencies (Equation 1 dimension mismatch) and the experimental reporting lacks variance information needed to support statistical significance claims. 

Given the extent of writing and reporting deficiencies, the paper requires major revisions focused on: (1) comprehensive proofreading and rewriting of garbled sections, (2) completion of placeholder content (Limitations, Error Analysis), (3) addition of statistical rigor (variance reporting, identified baselines), and (4) removal or correction of unsupported claims. The technical core has merit, but the current presentation is not yet publication-ready.

## Strengths
**1. Well-motivated hierarchical architecture.** The proposed three-level decomposition (token → function → module) is a natural and sensible way to process code that mirrors its inherent structural organization. Combining transformer-based sequential attention with graph attention over AST and CDG provides a principled way to capture both local token interactions and global structural dependencies — an approach that is technically sound and addresses a real limitation of single-level code embeddings.

**2. End-to-end RL optimization of code embeddings.** Unlike methods that pre-train code representations independently of the downstream RL task (e.g., CodeBERT fine-tuned separately), the proposed approach optimizes the entire hierarchical embedding through the policy gradient objective. This task-adaptive training is a legitimate technical contribution that aligns the representation learning objective with the RL agent's goals.

**3. Comprehensive experimental scope across three distinct tasks.** The evaluation covers code completion, program repair, and algorithmic problem solving — three tasks requiring different levels of code understanding. This breadth strengthens the generalizability claims more than evaluation on a single task would. The inclusion of five baselines covering sequential (Transformer), tree-structured (Tree-LSTM), pre-trained (CodeBERT), graph-only (GNN-CDG), and flat-attention (Flat-GAT) methods provides reasonable coverage of the methodological landscape.

**4. Ablation study identifying component contributions.** The ablation results (Table 2) systematically quantify the marginal contribution of each attention level, with token-level attention showing the largest individual impact (−6.2%). This provides useful insight into which components drive performance and helps validate the hierarchical design's importance.

**5. Scalability analysis with respect to program size.** The analysis showing that prediction error grows more slowly with program complexity (Figure 3) and memory scaling is linear (vs. quadratic for sequence transformers) is practically relevant. If substantiated with proper baseline identification and memory measurements, this would be a meaningful advantage for real-world deployment.

## Weaknesses
**W1. [Critical] Catastrophic writing errors throughout the manuscript.** Multiple sections contain incomprehensible or severely garbled text that undermines scientific credibility. The most critical instance is the Conclusion (Page 8): "The hierarchical cherry-picking of the code embedding system with multi-level attention Research into mechanisms provides major breakthrough in reinforcement learning state representation for code related task." The phrase "hierarchical cherry-picking" has a strongly negative connotation (implying biased selection of favorable results) and appears to be a word-substitution error. The sentence is grammatically broken and uses "breakthrough" — an unsupported overclaim. Additionally, Introduction Paragraphs 2–3 are essentially unreadable (garbled phrases: "Neural Investigations," "code Sequential or Tele-centric analysis," "Peps by itself," "without context being aware of the token of the word embeddings. level"). Section 2.2 contains a broken bullet-list fragment mid-sentence. These errors collectively suggest the manuscript was not proofread before submission. *Severity: Critical — the Conclusion error alone could result in desk rejection.*

**W2. [Critical] Empty Limitations section (7.1) and missing Error Analysis content.** Section 7.1 titled "Limitations of the Hierarchical Code Embedding System" contains only a placeholder sentence: "While our hierarchical attention model is able to demonstrate strong performance across several tasks. Need to discuss several limitations of this study." This is a note-to-self, not a finished manuscript section. No concrete limitations are identified, discussed, or bounded. Similarly, the Error Analysis (Section 6.7) is two vague sentences without quantitative breakdown, concrete examples, or per-task analysis. These omissions signal that critical analytical work was not completed. *Severity: Critical — incomplete sections indicate the manuscript is not ready for review.*

**W3. [Major] Statistical significance claims are unsubstantiated.** The paper states that "statistical significance tested via paired t-tests (p < 0.01)" but Table 1 reports only single point estimates without standard deviations, confidence intervals, or standard errors for any model or metric. No information about the number of runs/seeds is provided. Without variance data, no t-test can be computed or verified. The learning curves in Figure 2 also lack error bands or confidence shading. This is a methodological reporting deficiency that undermines the core performance claims. *Severity: Major — affects confidence in all reported improvements.*

**W4. [Major] Missing figures and placeholder text in Results.** Section 6.4 describes t-SNE visualizations and nearest neighbor analysis as if they exist ("t-SNE visualizations of the learned state representations are shown here"), but no such figures appear in the manuscript. Similarly, the nearest neighbor analysis is asserted without quantitative results. This suggests placeholder text was left in during final manuscript preparation. *Severity: Major — these are evidence claims without evidence.*

**W5. [Major] Equation (1) contains a dimension mismatch in relative attention formulation.** The term $(W_q x_i)^\top (W_k x_j + \mathbf{R}_{i-j})$ adds the relative position embedding $\mathbf{R}_{i-j}$ directly to the transformed key $W_k x_j$. For this addition to be valid, $\mathbf{R}_{i-j}$ must be a vector in $\mathbb{R}^{d_k}$ (same dimension as $W_k x_j$), but this dimensionality is never specified. Standard relative attention implementations (Shaw et al., 2018; TransformerXL, Dai et al., 2019) typically use a separate bias term rather than element-wise addition to the key vector. The current formulation is mathematically ambiguous. *Severity: Major — affects reproducibility of the core attention mechanism.*

**W6. [Major] Scalability analysis baselines are not identified.** Figure 3 labels comparison methods as "Baseline 1" and "Baseline 2" without mapping them to any of the five named baselines. Without this mapping, the scalability comparison is uninterpretable. Additionally, the claim that "Memory consumption is linearly proportional to program size with our model, compared to quadratic growth for sequence transformers" is presented without any empirical memory measurement data. *Severity: Major — the key practical advantage claim is unsupported.*

**W7. [Major] CodeBERT and baselines comparison fairness concerns.** The paper reports comparing against CodeBERT fine-tuned for RL, but does not specify how CodeBERT's representations were adapted for the RL setting, nor whether a comparable number of parameters or training compute was used. The "comparable dimensionality (768-D)" claim ensures equal embedding size but does not ensure equal model capacity or training budget. The learning curves (Figure 2) show the proposed model still improving at 50K steps while baselines plateau earlier, suggesting training may not have been calibrated to baseline convergence. *Severity: Major — affects validity of the claimed improvements.*

**W8. [Major] Unspecific novelty positioning against closely related work.** The paper acknowledges Wang et al. (2020b) "which uses hierarchical attention for code summarization using RL guidance" but does not clearly differentiate the proposed method from this directly relevant prior work. Given that Wang et al. also combines hierarchical attention with RL guidance for code tasks, the novelty claim needs explicit boundary articulation — what specific design choices or problem formulations distinguish this work from Wang et al.? This is particularly important because a reviewer familiar with Wang et al. may challenge the novelty claims. *Severity: Major — novelty assessment requires stronger differentiation.*

**W9. [Moderate] Missing variance information in ablation study.** Table 2 reports ablation deltas (e.g., −6.2% for removing token-level attention) without standard deviations or confidence intervals. Given that the ablation is performed on a single task (program repair) with what appears to be a single run, readers cannot determine whether the observed component contributions are statistically reliable. *Severity: Moderate — affects robustness of ablation conclusions.*

**W10. [Minor] "CodeBLEU score (?)" contains a literal question mark.** This appears to be a placeholder or expression of uncertainty about the metric definition, which is inappropriate in a submitted manuscript. CodeBLEU is a well-defined metric and should be cited properly. *Severity: Minor — easily fixable but signals lack of attention to detail.*

**W11. [Minor] Grammatical errors in Section 3.1.** "have the troubles with long-range dependencies" and "structure relationships inherent on code" contain grammatical errors. A sentence ends with a dash mid-phrase ("retain the coding hierarchy - can neglect important semantic connections"). *Severity: Minor — can be fixed with light copyediting.*

**W12. [Moderate] Section 9 (LLM use disclosure) is overly terse.** The sentence "We use LLM polish writing based on our original paper" is grammatically incorrect and does not specify which parts of the manuscript were polished, which LLM was used, or whether any substantive technical content was generated by the LLM. As LLM use policies in conferences become stricter, a more detailed disclosure is recommended. *Severity: Moderate — could raise integrity questions under current AI authorship policies.*

**Novelty status (deferred):** External literature verification is unavailable in this run (Retrieval-Disabled Mode). All novelty and comparison conclusions are explicitly deferred for manual verification. The authors should independently verify that their hierarchical attention approach is not substantially overlapped with Wang et al. (2020b), SG-Trans (Gao et al., 2023), and other hierarchical code representation methods surveyed in the related work.

## Score
**Final Score: 4/10**

**Rationale:** The score reflects the severe gap between the paper's technical ambition and its current state of execution. The hierarchical attention architecture is well-motivated and the experimental scope is reasonably broad, which supports a baseline score in the lower-mid range. However, three critical issues prohibit a higher score:

1. **Research value (novelty + contribution):** The core idea — hierarchical multi-level attention for code — has conceptual merit but the paper does not sufficiently differentiate itself from closely related work (particularly Wang et al. 2020b). The novelty assessment is deferred pending external literature verification, but from the manuscript alone, the contribution may be partially overlapping with existing approaches. The claimed "end-to-end RL optimization" and "graph + sequential attention integration" need sharper boundary articulation.

2. **Validity and soundness:** The significance testing claim (t-test, p<0.01) is unsubstantiated without variance reporting. The scalability advantage (linear vs. quadratic memory) is asserted without supporting measurements. Missing figures (t-SNE) and placeholder sections (Limitations, Error Analysis) indicate incomplete work. These gaps mean the core empirical claims are not verifiable from the current manuscript.

3. **Writing quality and completeness:** The Conclusion's "hierarchical cherry-picking" error, garbled Introduction paragraphs, empty Limitations section, and multiple broken sentences collectively indicate that the manuscript was submitted without adequate proofreading or completeness checking. In its current form, the paper does not meet the minimum standards of scholarly communication.

**Revision outlook:** The paper could become publishable after major revisions addressing: (a) comprehensive rewriting of garbled/placeholder sections, (b) addition of variance reporting and statistical rigor, (c) completion of missing analysis content, (d) proper differentiation from related work, and (e) repair of the mathematical inconsistencies. If these revisions are carried out thoroughly, a revised version could merit a score in the 6–7/10 range.
