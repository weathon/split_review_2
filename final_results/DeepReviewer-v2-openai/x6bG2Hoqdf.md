## Summary
This paper presents CALM (Co-evolution of Algorithms and Language Model), a framework for Automatic Heuristic Design (AHD) that combines evolutionary prompt manipulation ("verbal guidance") with reinforcement learning-based LLM fine-tuning ("numerical guidance"). The core idea is to use the performance scores of generated heuristics as reward signals for fine-tuning the LLM via GRPO, enabling the model to improve its heuristic generation capability over time. CALM also introduces several evolutionary operators (injection, replacement with novel instructions, diversity-aware crossover) and a collapse mechanism to escape local optima.

The method is evaluated on four optimization tasks — Online Bin Packing (OBP), Traveling Salesman Problem (TSP), Capacitated Vehicle Routing Problem (CVRP), and Orienteering Problem (OP) — under step-by-step construction and ACO-based search frameworks. Using an INT4-quantized Qwen2.5-7B-Instruct model on a single 24GB GPU, CALM achieves competitive or superior results compared to prior LLM-based AHD methods, including those using GPT-4o-mini. Ablation studies confirm the contribution of individual components (GRPO fine-tuning, operators, collapse mechanism).

**Core contributions claimed (C1-C3):**
- **C1:** One of the first frameworks to jointly optimize prompt generation and the LLM model itself for AHD via RL fine-tuning (GRPO).
- **C2:** Novel evolutionary operators (fine-granularity injection/replacement, diversity-aware crossover) and collapse mechanism for improved heuristic search.
- **C3:** Demonstrating that a compact, locally-run quantized 7B model with RL fine-tuning can outperform API-based methods using more powerful models.

## Strengths
**1. Novel integration of RL fine-tuning into LLM-based AHD.** The paper makes a compelling case for treating heuristic generation as a source of RL training data. Using GRPO to provide "numerical gradients" that update the LLM itself — rather than only manipulating prompts — is a conceptually clean extension of existing LLM-based AHD methods. The ablation study (Table 4) confirms that GRPO fine-tuning provides the largest performance contribution among all components.

**2. Resource efficiency.** Running on a single 24GB GPU with an INT4-quantized 7B model is a genuine practical achievement. If the reported performance holds under matched computational budgets, this substantially lowers the barrier to entry for AHD research and deployment. The paper correctly acknowledges the quantization trade-off (reduced precision) and compares against stronger API-based models, which is good scientific practice.

**3. Comprehensive ablation and analysis.** Table 4 provides systematic ablation of all major components (GRPO, reward design variants, collapse mechanism hyperparameters, individual operators). This level of detail is rare and greatly strengthens the paper's empirical contribution. The authors correctly identify simplification as the most critical operator and diversity-aware crossover as more effective than performance-only crossover.

**4. Multi-task evaluation across four optimization problems.** Testing on OBP, TSP, CVRP, and OP — combining step-by-step construction and ACO search frameworks — demonstrates that the approach generalizes across different heuristic structures, rather than being tailored to a single solver paradigm.

**5. Good positioning relative to concurrent work.** The Related Work section explicitly acknowledges concurrent fine-tuning approaches (Surina et al., 2025; Liu et al., 2025) and distinguishes CALM's use of score-based RL (GRPO) from preference-based methods (DPO). This transparency about the rapidly evolving landscape is commendable.

## Weaknesses
### W1: Budget fairness between CALM and baselines is not properly established (Major)
*Relevant annotations: Page 1 - Experiments Setup paragraph, annotation_id=0c297b97; Page 1 - Table 3 paragraph, annotation_id=d2200e43*

The paper compares baselines limited to 1,000 "heuristic evaluations" against CALM with 2,000 "LLM queries." Since CALM samples $G$ responses per query (the paper does not disclose $G$ in the main text for all tasks), the effective number of candidate heuristics generated by CALM is $T \times G$, which could be substantially larger than 1,000. For example, if $G=4$, CALM generates 8,000 candidates vs. 1,000 for baselines. While many candidates may be filtered before full evaluation, this asymmetry makes it difficult to attribute performance gains to algorithmic superiority rather than increased computational budget.

**Required action (Must):** (a) Report $G$ for all experiments. (b) Report the effective number of heuristic function evaluations (not just LLM queries) for CALM. (c) Include a matched-budget comparison where CALM is limited to the same number of heuristic evaluations as baselines.

### W2: Missing variance and significance reporting in main results (Major)
*Relevant annotations: Page 1 - Table 3, annotation_id=d2200e43*

All main results (Tables 1-3) report averages over 3 runs without standard deviations, confidence intervals, or significance tests. Given that some improvements are modest (e.g., CVRP N=50: 3.83% vs 5.44% for MCTS-AHD — about 1.6 percentage points), the reader cannot assess whether gains are statistically reliable or within noise. The paper mentions p-values in Appendix I, but (a) the appendix is not verifiable from the extracted content, and (b) significance should be reported in the main text for central claims.

**Required action (Must):** Add standard deviation or 95% CI to all main tables. For key comparisons, include statistical significance indicators (e.g., $p<0.05$ via Mann-Whitney U or paired bootstrap test). If the appendix contains these, move a summary to the main text.

### W3: Key analytical result (Eq. 2) has limited practical validity under experimental settings (Major)
*Relevant annotations: Page 1 - Collapse Mechanism, annotation_id=5de2f89b*

Equation (2) provides an analytical approximation $\mathbb{E}[c_n \mid \text{collapse}, C > 1/\delta_0] \approx \sqrt{\pi/(2\delta_0)}$ for the expected stagnation rounds before collapse. However, the condition $C > 1/\delta_0$ is violated in the default experimental setting ($C=15$, $\delta_0=0.0005 \rightarrow 1/\delta_0 = 2000$). This means the hard cap $C$ dominates the collapse trigger, and the formula does not provide practical guidance for hyperparameter selection in the regime actually used. The derivation is deferred to an unavailable appendix, making the result untestable.

**Required action (Must):** (a) Clarify in the main text that Eq. (2) applies only when $C$ is very large relative to $1/\delta_0$. (b) Provide practical guidance for finite $C$ (e.g., simulation results or a simpler upper bound). (c) Report the empirical distribution of $c_n$ (e.g., average stagnation rounds before collapse) observed in experiments.

### W4: Overclaiming in "first" and "transformative" language (Moderate)
*Relevant annotations: Page 1 - Introduction paragraph, annotation_id=f36d0dc9; Page 1 - Conclusion, annotation_id=8b87a977; Page 1 - Discussion "Power of RL", annotation_id=c35ebd62*

Three instances of overclaiming: (1) The conclusion calls CALM "the first framework to marry prompt evolution with on-the-fly LLM adaptation for AHD" despite concurrent work (Surina et al., 2025 EvoTune; Liu et al., 2025) acknowledged in Section 2. (2) The discussion describes RL as having "transformative power" — this is subjective and not supported by the ablation data, which shows RL fine-tuning gives the largest performance contribution but the API-based variant (no RL) achieves close results. (3) "Outmatch SOTA API-based baselines" oversimplifies — on TSP N=50 in-domain, CALM (10.04%) underperforms MCTS-AHD with GPT-4o-mini (9.69%).

**Required action (Must for "first"; Nice-to-have for tone):** Replace "first" with a qualified statement acknowledging concurrent work and specifying the technical distinction (score-based RL vs. DPO). Tone down "transformative" to measured language such as "consistent improvement." Bound "outmatch" with specific reference to the overall average vs. individual test set results.

### W5: Credit-assignment argument for fine-granularity operators is plausible but untested (Moderate)
*Relevant annotations: Page 1 - Fine-Granularity Mutation Operators, annotation_id=065907c6*

The paper argues that injection and replacement operators help GRPO perform better token-level credit assignment by keeping most code structure constant while varying specific components. This is an intuitive argument but is not empirically verified. The ablation (Table 4) shows that removing injection or replacement hurts performance, but this could be due to reduced heuristic diversity rather than improved credit assignment. Without measuring token-level advantage alignment or comparing against a simpler mutation baseline (e.g., random uniform mutation), the stated mechanism remains speculative.

**Required action (Nice-to-have):** Add a controlled ablation comparing injection/replacement against simple token-level mutation with the same GRPO setup. If the gain is largely from diversity rather than credit assignment, reframe the motivation accordingly.

### W6: Duplicate detection in reward function is fragile (Minor)
*Relevant annotations: Page 1 - Reward Function Eq. (4), annotation_id=7b911ec0*

The reward function identifies duplicate heuristics by exact performance equality $g(h) = g(h_{\text{new}})$. This is brittle: numerical noise in evaluation could cause identical heuristics to have slightly different scores (false negative), while different heuristics could produce the same training-set score by chance (false positive). The paper evaluates on small training sets (e.g., 4 instances for OBP, 64 for TSP), increasing the likelihood of coincidental score matches.

**Required action (Nice-to-have):** Replace exact equality with tolerance-based comparison ($|g(h) - g(h_{\text{new}})| < \epsilon$) and optionally add code-structure fingerprinting (e.g., AST hash) for robust duplicate detection.

### W7: Notation inconsistency in GRPO description (Minor)
*Relevant annotations: Page 1 - Section 3.2 GRPO, annotation_id=5769fc1b*

The GRPO description uses $\pi_\phi$ and $\pi_\theta$ interchangeably without clarifying the relationship between $\phi$ and $\theta$. The initial model is $\pi_0$, the reference model is $\pi_{\text{ref}}$, and the optimization variable is $\theta$, while $\phi$ appears in the reward function $r_\phi$. This notational inconsistency creates confusion about which parameters are being updated.

**Required action (Minor):** Unify notation: consistently use $\pi_\theta$ for the current policy and clarify that $\phi$ in $r_\phi$ denotes the reward function parameters (which are separate from the policy parameters $\theta$).

### W8: Duplicate HSEvo rows in Table 3 (Minor)
*Relevant annotations: Page 1 - Table 3, annotation_id=d2200e43*

Table 3 contains two rows labeled "HSEvo" with different values (lines 130-131). No explanation is provided. This may be a formatting error or represent different HSEvo variants. Either way, it undermines the professionalism of the result presentation.

**Required action (Must):** Clarify the labeling — rename rows if they correspond to different HSEvo variants, or remove duplicates if it is an error.

## Score
**Final Score: 6/10**

**Rationale:** CALM presents a technically sound integration of RL fine-tuning (GRPO) into LLM-based Automatic Heuristic Design, with comprehensive ablations and competitive results across four optimization tasks. The core idea — using heuristic performance as a dense reward signal to fine-tune the LLM — is novel and well-motivated. The resource efficiency (single 24GB GPU, quantized 7B model) is a genuine practical strength.

However, the score is constrained by the following factors (in descending importance):

1. **Evaluation fairness (W1):** The budget comparison between CALM and baselines is inequitable (LLM queries vs. heuristic evaluations), making it unclear whether performance gains reflect algorithmic superiority or increased computation. *This is the single largest validity concern.*

2. **Missing statistical rigor (W2):** All main tables lack variance reporting, preventing assessment of whether modest improvements are meaningful.

3. **Unsupportable strong claims (W4):** "First" and "transformative" language, combined with an undefended "first" statement given acknowledged concurrent work, weakens the paper's otherwise strong empirical positioning.

4. **Limited analytical grounding (W3):** The collapse mechanism's analytical approximation (Eq. 2) has limited practical validity under the experimental hyperparameters used, and the credit-assignment argument for the operators (W5) is untested.

5. **Novelty verification deferred:** Without access to external literature search in this run, the novelty claims relative to the full body of prior work (beyond the well-surveyed related work) cannot be independently verified.

The paper has clear technical merit and the ablation study (Table 4) is a model of thoroughness. With proper budget-controlled comparisons, variance reporting, and toned-down claims, the score would likely rise to the 7-8 range.
