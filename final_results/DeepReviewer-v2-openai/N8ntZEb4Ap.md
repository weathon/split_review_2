# Final Review Report

## Summary

This paper proposes AutoNFS, a neural feature selection method that uses Gumbel-Sigmoid relaxation to learn a global binary feature mask jointly with a downstream prediction model. The key ideas are: (1) a masking network that generates feature logits from a learned embedding, transformed to a soft mask via Gumbel-Sigmoid sampling; (2) a cardinality penalty that automatically determines the number of selected features without requiring the user to specify a feature budget; and (3) near-constant computational overhead with respect to input dimensionality by decoupling the masking network's complexity from the feature count.

The paper evaluates AutoNFS on 11 OpenML benchmarks (with three corruption scenarios) and 24 metagenomic datasets, comparing against 10 baseline methods including Lasso, LassoNet, XGBoost, Deep Lasso, and attention mechanisms. Results show competitive average ranking and substantial dimensionality reduction (e.g., 7.7% of original features on metagenomic data).

**Key contributions:** The automatic feature-count discovery and the near-constant scaling behavior are novel and practically relevant contributions to the feature selection literature. The metagenomic validation on 24 real-world datasets is a strength.

**Core weaknesses identified in this audit:** (1) The empirical comparison is confounded by an unfair baseline setup — baselines select the full pre-corruption feature count while AutoNFS selects fewer, making the performance ranking comparisons potentially misleading. (2) A formula inconsistency in the selection penalty (1/D in text vs 1/B in Algorithm 1) harms reproducibility. (3) Several claims overreach the evidence, including "consistently outperforms," "independent of downstream classifier," and unsupported forward-looking statements in the conclusion. (4) The complexity analysis uses imprecise terminology ("exponential" vs power-law) and lacks regime bounds. (5) The Related Work section lists methods chronologically without precise mechanism-level differentiation, obscuring novelty boundaries against closest competitors like STG and Hard-Concrete.

## Strengths
**1. Practical automatic feature-count discovery.** The core idea — using a cardinality penalty with a soft-to-hard mask transition to automatically determine the number of features — addresses a genuine pain point in applied feature selection. Most existing methods (LASSO, STG, LassoNet) require the user to pre-specify a sparsity budget or regularization strength that controls feature count indirectly. AutoNFS's approach of letting the feature count emerge from the optimization with a fixed λ=1 is practically convenient and was validated across 11+24 datasets.

**2. Near-constant computational scaling.** The complexity analysis (Section 4.3, Figures 4a-4b) demonstrates that AutoNFS's runtime is nearly independent of input dimensionality up to 10^5 features, with an estimated α≈0.08 power-law exponent. This is a quantifiable advantage over linear-scaling methods (ANOVA, Mutual Information) and super-linear RFE. The architectural design choice of a fixed-size learned embedding driving the masking network is the mechanistic reason, and this is clearly described.

**3. Extensive real-world validation on metagenomic data.** The evaluation on 24 metagenomic datasets (Table 2) is a strength — it tests the method on genuine high-dimensional biological data with complex interactions, not just synthetic corruption benchmarks. The dimensionality reduction to 7.7% of original features while maintaining average predictive performance is practically meaningful for bioinformatics applications.

**4. Reproducibility commitment.** The paper provides Algorithm 1 with explicit hyperparameters (τ₀=2.0, α=0.997, λ=1), an anonymous code repository, and a reproducibility statement. While there is an inconsistency between the text and algorithm (noted in Weaknesses), the overall level of implementation detail is above average for a conference submission.

**5. Clean problem framing.** The paper clearly identifies the gap it addresses (automatic feature count determination + constant-time scaling) and the method is self-contained. The architecture diagram (Figure 1) and training algorithm are understandable without external references.

## Weaknesses
### W1. Unfair baseline comparison confounds main empirical claim (Major)
The predictive performance comparison (Section 4.1, Figure 2) has a critical confound: all baseline methods are configured to select the same number of features as were in the initial pre-corruption representation, while AutoNFS automatically selects fewer. As the paper itself notes, "all baseline methods select the same number of features as were in the initial representation (before corruption), whereas our method automatically chooses a much smaller subset." This means baselines are not operating in their feature-selection mode — they are essentially being compared at an artificially restricted configuration. A fair comparison would either: (a) configure baselines to select a similar number of features as AutoNFS, or (b) report the full performance-sparsity Pareto frontier for each method. Without this control, the "consistently outperforms" claim is not methodologically justified. **Severity: Major. Fix: Add matched-feature-count comparisons or reframe claims.**

### W2. Formula inconsistency between text and algorithm (Major)
The selection penalty $\mathcal{L}_{select}$ is defined as $\frac{1}{D}\sum_{j=1}^D m_j$ in Section 3.3 (normalizing by feature count D), but Algorithm 1 step 14 writes $\frac{1}{B}\sum_{j=1}^D m_j$ (normalizing by batch size B). These produce gradient magnitudes that differ by a factor of D/B, which can be large (e.g., D=128, B=64 yields a 2x difference; for D=718, B=64 it's 11x). This inconsistency makes the exact optimization procedure ambiguous and harms reproducibility. **Severity: Major. Fix: Align both definitions; the correct normalization should be 1/D to make the penalty independent of both batch size and dataset size.**

### W3. Overclaim "independent of downstream classifier" contradicted by data (Major)
Section 4.2 claims that the representation generated by AutoNFS is "independent of a downstream classifier" based on average improvements of +0.7 pp (MLP) and +1.2 pp (RF). However, Table 2 shows multiple datasets where one classifier improves and the other degrades (e.g., KeohaneDM_2020: MLP drops from 0.469→0.344, RF improves 0.469→0.531; LiJ_2017: MLP improves 0.341→0.511, RF drops 0.561→0.432). The average improvement does not imply independence. The claim should be reframed as: "AutoNFS-selected features are useful across different classifier types on average, but the optimal feature subset may be classifier-dependent." **Severity: Major. Fix: Replace "independent" wording with bounded per-classifier analysis.**

### W4. Conclusion introduces unsupported forward-looking claims (Major)
The conclusion states that AutoNFS "opens doors for broader applications, such as real-time model compression, adaptive inference, or integration with AutoML frameworks" and is a "drop-in replacement for feature selectors in a wide range of tasks." None of these applications were tested, and "drop-in replacement" overstates readiness — the method requires end-to-end retraining of both masking and task networks, which is not a drop-in substitution for inference-only FS pipelines. **Severity: Major. Fix: Remove unsupported claims or explicitly label them as untested future work.**

### W5. "Exponential function" error in complexity description (Major)
Section 4.3 states "Denoting time complexity as an exponential function of the number of features $t \approx D^\alpha$." The function $t \approx D^\alpha$ is a power law (polynomial), not exponential. An exponential function would be $t \approx a^D$. This is a technical inaccuracy in a central claim section. Additionally, the claim of "nearly constant time" ($\alpha \approx 0.08$) is reported without specifying the tested dimensionality regime or experimental conditions (hardware, software, exact AutoNFS configuration). **Severity: Major. Fix: Replace "exponential" with "power-law"; add experimental conditions and regime bounds.**

### W6. Related Work lacks mechanism-level differentiation (Moderate)
Section 2 lists differentiable FS methods chronologically (Hard-Concrete, STG, Concrete Autoencoders, INVASE, LassoNet, Gumbel-Top-k) but does not provide a precise mechanism-level comparison. Key questions for novelty assessment remain unanswered: How does Gumbel-Sigmoid compare to STG's Gaussian-based stochastic gates? How does the global mask (single embedding) compare to instance-specific masks in Concrete Autoencoders and INVASE? Without these comparisons, the novelty boundary against closest prior work is unclear. **Severity: Moderate. Fix: Reorganize by comparison axes (relaxation type, mask granularity, feature-count mechanism) with explicit differentiation.**

### W7. Average predictive power metric lacks clear definition (Moderate)
Section 4.1 reports "average predictive power of individual features" as 0.313, but does not define the metric units, computation procedure, or aggregation method. Is this absolute accuracy drop, relative accuracy drop, or a normalized score? Without definition, the value cannot be interpreted. The claim that this "means the returned set cannot be further reduced without affecting predictive performance" is also a logical overstatement — removing one feature and observing a drop does not prove subset minimality (it only shows the feature is individually non-redundant in the current set). **Severity: Moderate. Fix: Define metric precisely and replace minimality claim with bounded statement about individual feature importance.**

### W8. Abstract overclaims "consistently outperforms" (Moderate)
The Abstract states AutoNFS "consistently outperforms both the classical and neural FS methods." This claim is too strong given (a) the unfair baseline comparison issue (W1), (b) absence of variance/confidence intervals in reported results, and (c) several individual datasets where AutoNFS underperforms full-data baselines. A bounded claim referencing average rank improvement would be more appropriate. **Severity: Moderate. Fix: Rephrase to "achieves competitive or superior average performance while selecting fewer features."**

### W9. No statistical significance or variance reporting (Minor)
Across all experiments, results are reported as point estimates without standard deviations, confidence intervals, or significance tests. For the benchmark datasets (Tables 3-5, referenced but not shown in main text), only mean ranks are provided. For the metagenomic results (Table 2), no variance is reported. Given that some performance differences are small (e.g., average MLP improvement of 0.7 pp), readers cannot assess whether differences are statistically reliable. **Severity: Minor. Fix: Add multi-seed variance or bootstrap confidence intervals for main results.**

### W10. Temperature annealing RL analogy is loose (Minor)
Section 3.4 compares the annealing schedule to "exploration-exploitation trade-off, which parallels fundamental concepts in reinforcement learning" and redirects to Appendix B. This analogy adds limited explanatory value without a formal connection, and the critical details in Appendix B could be summarized in the main text. **Severity: Minor. Fix: Either remove the analogy or explain the continuation-optimization perspective directly.**

### Novelty and Literature Comparison (Deferred)
Due to retrieval infrastructure limitations in this run (paper_search unavailable), external literature verification was not possible. The novelty assessment of C1 (Gumbel-Sigmoid + cardinality penalty FS), C2 (near-constant scaling), and C3 (metagenomic validation) should be verified against closest prior work: STG (Yamada et al. 2020b), Hard-Concrete (Louizos et al. 2017), Concrete Autoencoders (Balin et al. 2019), LassoNet (Lemhadri et al. 2021), INVASE (Yoon et al. 2018), and Gumbel-Top-k (Kool et al. 2019). Based on manuscript evidence alone, claim C2 (efficiency scaling) appears the strongest, C1 has partial overlap with existing differentiable FS methods, and C3 (validation) is a standard evaluation contribution. Formal novelty verdicts require manual literature verification.

## Score
**Final Score: 6/10**

**Rationale.** The paper identifies a genuine practical problem (automatic feature count selection, efficient scaling) and proposes a clean, principled approach using Gumbel-Sigmoid relaxation with a cardinality penalty. The near-constant computational scaling claim is novel and well-motivated. The metagenomic validation across 24 datasets provides realistic evidence of practical utility.

However, the empirical evaluation has a significant methodological confound (baselines operate under restricted configuration, W1) that undermines the main "consistently outperforms" claim. Several statements overreach the available evidence (W3, W4, W8). A formula inconsistency between text and Algorithm 1 (W2) reduces reproducibility confidence. The complexity analysis contains a technical inaccuracy (W5). The Related Work section lacks mechanism-level differentiation (W6), making novelty boundaries unclear against closest prior differentiable FS methods (STG, Hard-Concrete, Concrete Autoencoders). Statistical significance/variance is absent throughout (W9), which is concerning for small-margin comparisons.

The core research value — automatic feature-count discovery via a learned global mask with near-constant time — is solid and worth publishing, but the evaluation, claim calibration, and reproducibility details need substantial revision before acceptance.

**Post-Revision Target:** [6, 7]/10 — achievable with the following priority fixes: (1) resolve the baseline comparison confound (W1) by adding matched-feature-count comparisons; (2) fix formula inconsistency (W2); (3) calibrate overstated claims (W3, W4, W8); (4) correct complexity terminology (W5); (5) restructure Related Work with mechanism-level differentiation (W6); (6) add variance reporting for main results (W9).

**External literature verification of novelty claims is deferred** (paper_search unavailable in this run). A manual check against closest prior differentiable FS methods is recommended before acceptance.
