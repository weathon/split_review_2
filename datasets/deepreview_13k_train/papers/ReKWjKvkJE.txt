\title{Structure-Guided Large Language Models for Text-to-SQL Generation}

\begin{abstract}
Generating accurate Structured Querying Language (SQL) is a long-standing problem, especially in matching users' semantic queries with structured databases and then generating structured SQL. Existing models typically input queries and database schemas into the LLM and rely on the LLM to perform semantic-structure matching and generate structured SQL. However, such solutions overlook the structural information within user queries and databases, which can be utilized to enhance the generation of structured SQL. This oversight can lead to inaccurate or unexecutable SQL generation. To fully exploit the structure, we propose a structure-to-SQL framework, which leverages the inherent structure information to improve the SQL generation of LLMs. Specifically, we introduce our \textbf{\underline{S}tructure \underline{Gu}ided SQL~(SGU-SQL)} generation model. SGU-SQL first links user queries and databases in a structure-enhanced manner. It then decomposes complicated linked structures with grammar trees to guide the LLM to generate the SQL step by step. Extensive experiments on two benchmark datasets illustrate that SGU-SQL can outperform sixteen SQL generation baselines.

\end{abstract}

\section{Introduction}


Structured Querying Language (SQL) is the most popular language for communicating with databases and retrieving user-desired data. Due to the popularity of Large Language Models~(LLMs), there is an increasing need to input a user query and automatically generate the corresponding SQL to communicate with the database. 
However, unlike natural languages, SQL is a standardized structured language that must exactly match the database in order to be executable and retrieve the correct data. Considering the impact of these factors, incorporating structure information can improve the performance of SQL generation models.

 
Existing state-of-the-art solutions primarily rely on the comprehensive and generative capabilities of LLMs to generate SQL, thus adopting a text-to-SQL approach. T5~\cite{raffel2020exploring} first attempts to train a language model to understand the user query and build connections with the database.
After the emergence of ChatGPT, especially GPT4~\cite{openai2023gpt4}, some pioneers~\cite{dong2023c3,ma2023demonstration} directly input the user query and database schema to ChatGPT to generate SQL. Building upon this, DIN-SQL~\cite{pourreza2023din} employs chain-of-thought by requiring ChatGPT to decompose the SQL generation into several sub-tasks and then lead ChatGPT to generate the SQL according to the sub-tasks.

However, existing models primarily rely on the semantic information of user queries and database schema, while overlooking the inherent structure of queries, databases, and SQLs. The neglect of structure results in the following limitations:
\\\textbf{1. Semantic Ambiguity}: Only relying on the semantics of the query and the database may not fully capture the user's intent. For example, when a user queries ``income'', it may ambiguously refer to the summation of the ``salary'' and ``bonus'' tables in the database. However, these tables are indirectly linked through the "ID" and "DT" (DateTime) keys. By adopting a purely semantic approach, there is a risk of overlooking this implicit linking and neglecting either the salary or the bonus.
\\\textbf{2. Complex Relational Linking}: Real-world databases often contain implicit and intricate structures, such as storing metadata in meta tables and storing transactional data in detail tables. The complicated structure presents challenges for semantic-based SQL generation in precisely organizing the complex structure.
\\\textbf{3. Opaque Matching Processes}: Existing models employ a black-box approach to query-database matching, which provides little interpretability to users. As a result, it is difficult for users to inspect or refine the SQL generation process, thus limiting the reliability and usability.

While leveraging structural information to enhance SQL generation shows promise, it remains a challenging task due to the following reasons.
\\\textbf{1. Structured Representation}: The challenge lies in creating representations that accurately capture the structural nuances of queries and databases. It is especially demanding to develop a model that aligns query structures with database architectures.
\\\textbf{2. Precise Query Matching}: The key to SQL generation is linking query intents precisely with database structures. It is challenging to propose an accurate structured query-database linking.
\\\textbf{3. Decomposition Strategies}: When dealing with complex queries, it is challenging to devise effective strategies for decomposing the complicated linked structure for step-by-step SQL generation.
In this paper, we enhance the existing framework of text-to-SQL by introducing the tailored \textbf{\underline{S}tructure \underline{Gu}ided SQL~(SGU-SQL)} generation model. This model represents user queries and databases in a structured manner and employs a tailored semantic-enhanced structure matching model to establish a connection between the query structure and the database structure. Subsequently, we decompose the linked structure into sub-grammar trees to guide the step-by-step generation of SQLs by the LLM. The main contributions of our research are summarized as follows:
\begin{itemize}[leftmargin=*]
\item We discover the limitation of neglecting the structure in the SQL generation task and propose our tailored Structure Guide to utilize the structure information to enhance the SQL generation.
\item SGU-SQL proposes graph-based structure construction to comprehend user query and database understanding and then link query structure and database structure with semantic-enhanced solutions.
\item SGU-SQL introduces tailored structure-decomposed generation strategies to decompose queries with grammar trees and then generate accurate SQL with LLM.
\item Extensive experiments on two benchmark datasets verify SGU-SQL outperforms sixteen state-of-the-art SQL-generation baselines.
\end{itemize}


\section{Related Work}


Text-to-SQL facilitates user interaction with databases via natural language queries, circumventing the necessity for SQL syntax and database structure proficiency. Historically, this challenge was tackled through rule-based methods and hand-crafted heuristics. However, these approaches often faltered due to the complexity and diversity inherent in natural language queries.

\subsection{Fine-tuning Large Language Models for Text-to-SQL}
The emergence of large language models (LLMs) has markedly altered the landscape for text-to-SQL tasks. LLMs, with their capacity for understanding and generating human-like text, present a robust solution for text-to-SQL applications \cite{liu2023comprehensive}. The development of LLMs typically encompasses pre-training followed by fine-tuning. Research has concentrated on fine-tuning with domain-specific data and optimization techniques to enhance base models for coding tasks, including text-to-SQL. This process enables models to master programming language syntax and database schema intricacies \cite{raffel2020exploring, roziere2023code}. Through training on tailored datasets of annotated SQL queries, LLMs acquire the grammar and structure necessary for generating compliant SQL code \cite{trummer2022codexdb, sun2023sql}. Furthermore, \citet{scholak2021picard} introduced a decoding mechanism for LLMs that ensures the generation of valid sequences by discarding inadmissible tokens at each step, employing incremental parsing to guarantee the validity of SQL queries produced by auto-regressive models.

\subsection{In-Context Learning for Text-to-SQL}
In-context learning enhances LLM performance by providing contextual examples during inference, thereby improving performance for specific tasks~\cite{zhang2023knowgpt}. This approach has seen innovative applications in text-to-SQL, with strategies aimed at optimizing example selection based on user queries and referenced data. \citet{liu2021makes} first investigated the impact of in-context examples on GPT-3's performance. \citet{nan2023enhancing} proposed categorizing problems by complexity to facilitate the identification of similarly complex examples, whereas \citet{guo2023case} developed a domain-specific vocabulary masking technique for example similarity assessment, highlighting the relevance of SQL-specific terms. DIN-SQL represents a sophisticated application of this concept, dissecting the text-to-SQL task into schema linking, query classification, and decomposition to improve the generation of complex SQL queries \cite{pourreza2023din}. DAIL-SQL further enhanced the performance by incorporating suitable formatting of the database schema and selecting examples based on skeleton similarities\cite{gao2023text}. \citet{dong2023c3} designed a framework for ChatGPT with clear prompting for effective input layout and tailored hints for calibration and consistency check during the query generation.
\subsection{Structure Learning for Text-to-SQL}
As text-to-SQL models often employ an encoder-decoder architecture, many strategies such as Graph Neural Networks (GNNs)~\cite{NEGCN,zhang2023integrating,zhang2022contrastive,dong2023hierarchy,LAGCN,shengyuan2024differentiable} have been designed to learn structural representations for the decoders to comprehend questions and database schemas. RATSQL employs a graph-based structure to delineate relationships within database schemas and queries, treating the schema as a graph of tables and columns connected by relational edges \cite{wang2019rat}. \citet{cao2021lgesql} introduced LGESQL, an edge-centric graph model derived from conventional node-centric graphs, to capture diverse structural topologies. S2SQL, proposed by \citet{hui2022s2sql}, integrates syntactic dependency information into a question-schema interaction graph, focusing on primary relationships to mitigate overfitting while emphasizing essential graph structures. \citet{li2023graphix} explored the integration of GNN layers into the T5 model, aiming to leverage both semantic and structural information from PLMs and GNNs, respectively. \citet{li2023resdsql} designed a ranking-enhanced encoder to rank and filter the schema items for the skeleton-aware decoder to decouple the schema linking and the skeleton parsing stage.




\section{Methodology}

In this section, we introduce the rationales of our framework. We leverage the implicit structural information in both queries and databases from three aspects: \((i)\) A graph-based structure construction for both user query and database understanding; \((ii)\) A tailored structure linking method is proposed to bind the query nodes with corresponding schema nodes, i.e., tables and columns. \((iii)\) Structure prompting to LLMs for accurate SQL generation. The overall illustration is presented in Figure~\ref{fig:figure1}.

\subsection{Structure Construction}
Initiating LLMs with the comprehension of the user query and database schema is challenging in complex real-world scenarios. First, natural language queries often contain ambiguous references or terminologies. Second, the implicit structure information is not readily accessible in the plain text format. In this part, we introduce the details about structure extraction in both query and database to achieve effective mapping and interaction. 

Inspired by the superiority of graphs, which can effectively represent the structural information in both natural language sentences and real-world entities~\cite{dong2023hierarchy}, we aim to construct build a comprehensive query-schema graph 
 by combining the \textit{query structure} and \textit{databse structure} based on the topic concepts in the query, pre-defined relations in the query, database schema as well as the table/column names present within the schema. The graph contains three key structures:
\begin{itemize}
    \item \textbf{Query Structure} (\(R_{\text{query}}\)): Encodes syntactic dependencies between tokens in the question, derived from its syntactic parse.
    \item \textbf{Database Structure} (\(R_{\text{schema}}\)): Represents intrinsic relationships within the database schema, like foreign keys.
     \item \textbf{Linking Structure} (\(R_{\text{linking}}\)): Aligns query entities with corresponding schema columns or tables.
\end{itemize}
 

\subsection{Structure Linking}
Schema linking plays a vital role in accurately interpreting and generating SQL queries from textual input.Existing schema linking has been actively adopted as a rule-based mapping problem. However, the hard mapping based on concept and table/column names results in an unsatisfactory performance. To tackle this, given the constructed query and database structures, we value the adjacency information during the matching process and propose to automatically build the connection between the query structure and schema at the node level. Specifically, we design a tailored structure-based linking framework. Both query and schema structures are first encoded through a Relational Graph Attention Transformer (RGAT) for initial node representations. The representation learning process is guided by the message propagation within the self-structure. We formalize the procedure of structure-aware question-schema structure linking as follows:
\begin{gather} \small 
    \label{eq_ga}
    \mathcal{G}_{s}^{Agg} = {\rm Agg}(\mathcal{G}_{s}, \mathcal{G}_{q}), \\
    \mathcal{G}_{q}^{Agg} = {\rm Agg}(\mathcal{G}_{q}, \mathcal{G}_{s}), %\quad 
\end{gather}
where the structure-aware aggregation function ${\rm Agg}(.)$ is employed to gather information from both the schema-graph $\mathcal{G}_{s}$ and the query-graph $\mathcal{G}_{q}$ and transfer it to the adjacent graph.

Let $ \{\boldsymbol h_{i}^{q}\}^{m}_{i=1}$ represent a set of node embeddings in the query-graph $\mathcal{G}_{q}$ and let $ \{\boldsymbol h_{j}^{k}\}^{n}_{j=1}$ denote a set of node embeddings in the subgraph $\mathcal{G}_{k}$ that extracted from schema-graph $\mathcal{G}_{s}$. In particular, we first employ global-average pooling on the node embedding $\boldsymbol h_{i}^{q}$ of the query structure $\mathcal{G}_{q}$ in order to derive the global query structure embedding $\boldsymbol h^{q}_{g}$. Following this, to encapsulate globally pertinent information, the key node embedding $\boldsymbol h^{k}_{j}$ is updated in the subsequent manner:
\begin{gather} \small
   \label{global_updated_1}
   \boldsymbol h^{q}_{g} =\frac{1}{m}\sum\nolimits ^{m}_{i=1} \boldsymbol h^{q}_{i}, \\
   \alpha_{j} =\theta \left( { \boldsymbol h^{q}_{g}}^{T} \boldsymbol W_{g} \boldsymbol h^{k}_{j}  \right), \\
   \label{global_updated_2}
   \boldsymbol h^{k}_{j} =  \sum\nolimits_{l \in \mathcal{N}_j} \alpha_{l} \boldsymbol W_{k} \boldsymbol h^{k}_{l} + \alpha_{j} \boldsymbol W_{k} \boldsymbol h^{k}_{j}  \\+ (1 - \alpha_{j}) \boldsymbol W_{q} \boldsymbol h^{q}_{g} 
\end{gather}
where $\boldsymbol W_{g}$, $ \boldsymbol W_{q}$, $ \boldsymbol W_{k}$ represent trainable parameters, and $\theta$ illustrates a sigmoid function. While $\alpha_{j}$ denotes the relevance score situated between the $j$-th key node and the global query structure.

For each node $a$ in the query structure $\mathcal{G}_q$, it is necessary to find a corresponding matching node $s$ in the database $\mathcal{G}_{s}$. The proposed solution mainly consists of three steps. First, a set of most relevant candidate nodes $\{s_1, s_2, \dots, s_K\}$ is identified through string matching in the set of tables and columns $A$. Second, for each candidate node $s$, a specialized subgraph $\mathcal{G}(a,s)$ is constructed. As shown in Figure 1, $\mathcal{G}(a,s)$ includes the query graph $\mathcal{G}_q$, adjacent nodes of $s_k$ (first-order and second-order), and an edge connecting $a$ and $s_k$. Lastly, we train a structure learning model  $\text{RGAT}(\cdot)$ to learn the graph-level embedding representation of $\mathcal{G}_(a,s_k)$ for predicting a matching score of the candidate pair $(a,s_k)$ . The expression for this is as follows,
\begin{gather} \small
\boldsymbol h = \text{RGAT}(\mathcal{G}(a,s)),\\
\text{Score}_{(a,s_k)}= \sigma ( \sum\nolimits_{l \in \mathcal{G}(a,s_k)}  \boldsymbol h^{k}_{l}).
\end{gather}
Based on positive samples $(a, s)$ and negative samples $(a, s_k)$, where $s_k\neq s$, the structure learning model $\text{RGAT}(\cdot)$ is iteratively trained.

\subsection{Structure-Decomposed Prompting}

{\bf Decomposing query with grammar tree}
The performance of LLMs on complex tasks can be improved by using decomposing-based methods. However, decomposing a SQL query into subtasks is challenging due to its declarative structure and the intricate connections between query concepts.  To this end, in this section, we introduce a context-free grammar tree (defined in Figure~\ref{fig:grammar_main}-(a)) to break the query into subtasks according to the syntax structure of the user query. Specifically, we first employ the Stanford Parser~\cite{klein2003accurate} to build the grammar tree to achieve a linguistic understanding of the natural language query and then adopt a node mapper to match nodes in the linguistic parse tree to SQL operations~\cite{kate2008transforming}. Following this, the original query can be divided into several subtasks according to the SQL operations distributed on the grammar tree.
\noindent {\bf Meta-operation in SQL} Based on the commonly used operations and properties in SQL, we define four meta-operations as the major identifiers for sub-task division:
\begin{itemize}[leftmargin=*]
    \item \textbf{A}: a start of a \texttt{SELECT} statement;
    \item \textbf{R}: a root node or continue with the result returned by last \texttt{SELECT};
    \item \textbf{T}: a corresponding Table name;
    \item \textbf{C}: a corresponding Column name.
\end{itemize}
Following this, the original query can be divided into several subtasks according to the SQL operations distributed on the grammar tree.

\noindent {\bf Prompt design for Text-to-SQL}
Given LLMs are sensitive to the prompts, we aim to transform the graph-structured sub-tasks into the form of text. This helps the LLMs better understand the task requirements to generate effective SQL queries. Specifically, given a user query $q_j$, to systematically guide the language model in generating SQL queries, we decompose the generation task into multiple steps and guide the language model to solve it step by step.
The final prompts follow the format $<Q_j;G_j;<Q_{j1};A_{j1}\dots;Q_{jk};A_{jk}>;I_j;A_j>$, where $k$ represents the number of subtasks, $Q_j$ and $A_j$ represent the statement of each subtask and the relevant information involved in this task, respectively, $G_j$ denotes the linked query-schema structure, and $I_j$ is the task description.

\noindent {\bf Datasets}
We assess the performance of text-to-SQL models using two renowned datasets, Spider~\cite{yu2019spider} and BIRD~\cite{li2023can}. Spider, a cross-domain text-to-SQL dataset, comprises 8659 instances in the training split and 1034 instances in the development split, spanning across 200 databases. Each instance comprises a natural language question related to a specific database and its corresponding SQL query. For evaluation purposes, we utilize the Spider-dev development split since the test split has not been released. On the other hand, BIRD (BIg Bench for large-scale Database Grounded text-to-SQL Evaluation) is another pioneering cross-domain dataset that focuses on exploring the impact of extensive database contents on text-to-SQL parsing. BIRD features over 12,751 unique question-SQL pairs, encompassing 95 large databases with a total size of 33.4 GB. It encompasses more than 37 professional domains, including blockchain, hockey, healthcare, education, and others.\\

\noindent {\bf Baselines} To valid the effectiveness of SGU-SQL, we compare it with the state-of-art baselines according to our best knowledge. Following the taxonomy aforementioned in Section~\ref{sec:related_work}, we divide all baselines into three categories: $(i)$ \textit{Fine-tuning-based}: \textbf{T5-base}~\cite{raffel2020exploring}, \textbf{T5-large}~\cite{raffel2020exploring}, \textbf{T5-3B}~\cite{raffel2020exploring}; $(ii)$ \textit{structure-learning-based}: \textbf{RAT-SQL}~\cite{wang2019rat},  \textbf{RASAT}~\cite{qi2022rasat}, \textbf{S$^2$SQL}~\cite{hui2022s2sql} ,\textbf{RESDSQL}~\cite{li2023resdsql},\textbf{GRAPHIX}~\cite{li2023graphix}; and $(iii)$ \textit{incontext-learning-based}: \textbf{PaLM-2}~\cite{anil2023palm}, \textbf{CodeX}~\cite{chen2021evaluating}, \textbf{ChatGPT}~\cite{openai2023gpt4}, \textbf{GPT-4}~\cite{openai2023gpt4}, \textbf{C3-GPT}~\cite{dong2023c3}, \textbf{DIN-SQL}~\cite{pourreza2023din}, \textbf{DAIL-SQL}~\cite{gao2023text}.

\noindent {\bf Evaluation Metrics}
The effectiveness of our models is analyzed by employing two frequently used measurement standards, namely Exact-Set-Match Accuracy (EM Acc) and Execution Accuracy (Exec Acc). EM Acc approaches treat each clause as an individual set and examine its prediction to the equivalent validated SQL query. %Exec Acc will check whether the execution results of the SQL query match the verified truth or not. 
However, this parameter does not take into consideration values, potentially triggering false positives and negatives. Conversely, Exec Acc places the execution result of the prospective SQL query alongside that of the confirmed SQL query on certain database iterations. With Execution Accuracy, a more nuanced understanding of the model’s functionality is attained since there can be several legitimate SQL queries corresponding to one question, and Exact-Set-Match Accuracy only assesses the predicted SQL in contrast to one of them.

\subsection{Main Results: Q1}
To answer Q1, we perform extensive experiments to compare SGU-SQL with the strongest baselines best to our knowledge. The comparison results on Spider and Bird are placed in Table~\ref{tab:main_spider}. We summarize our experimental observations as follows.

\noindent \textit{Obs.1. Our proposed SGU-SQL significantly outperforms SOTA text-to-SQL baselines.} We compare SGU-SQL (ours) with $3$ fine-tuning based methods, $5$ structure-learning-based methods and $8$ SOTA incontext-learning-based methods over two benchmark datasets. As shown in Table~\ref{tab:main_spider}, SGU-SQL achieves superior performance across both datasets, outperforming all baselines in terms of execution accuracy and exact match accuracy.\\
\noindent \textit{Obs.2. In-context learning-based method is better than the methods of the other two categories.} Among the three categories of methods, in-context learning-based methods consistently demonstrate superior performance. This suggests that leveraging in-context learning mechanisms is crucial for enhancing the understanding and generation of SQL queries from natural language inputs. Specifically, the in-context learning-based methods, i.e., DIN-SQL and DAIL-SQL in our comparison set achieve higher accuracy rates and require less computational overhead compared to fine-tuning and structure-learning-based methods. Additionally, the in-context learning-based methods exhibit better generalization across different datasets, indicating their robustness and adaptability.
\subsection{Ablation Staudy: Q2}
{\bf The effect of prompting strategy}
In this part, we conduct comprehensive experiments to investigate the effectiveness of our proposed prompting strategy. Specifically, we compare the structure-based decomposing strategy used in our SGU-SQL with other prompting strategies like CoT~\cite{wei2022chain} and few-shot prompting. As shown in Table~\ref{tab:diff_llm}, we can have the following observations.\\
\noindent \textit{Obs.1. Our structure-based decomposing significantly outperforms other prompting strategies.} Our method demonstrates superior performance across all tested LLMs. Specifically, compared to CoT, our approach achieves an average improvement of 5.03\%, while outperforming few-shot prompting by 4.98\% on average. \\
\noindent
\textit{Obs.2. Traditional decomposing-based methods are ineffective in the text-to-SQL task.} While decomposing complex tasks into subtasks like CoT, can enhance model performance in many natural language understanding tasks, it proves to be ineffective in the text-to-SQL task. As shown in Table~\ref{tab:diff_llm}, applying COT on PaLM-2 even leads to a performance decrease of 1.08\% compared to the naive few-shot prompting. This is attributed to the complex syntax of SQL, and the intricate correspondence between query terms in user queries and database data units. Conversely, we formally define the meta-operations in SQL and propose a decomposing strategy according to the grammar tree to separate the query into subtasks. This boosts the LLMs' comprehension of linked queries to generate accurate SQLs step by step.\\

\section{Conclusion and Future Work}

Generating accurate Structured Query Language (SQL) has long been a challenging task, especially in matching users' semantic queries with structured databases. Existing models typically input queries and database schemas into LLMs to perform semantic-structure matching and generate structured SQL. However, these models often overlook the structural information inherent in user queries and databases, which could significantly enhance the generation of accurate SQL queries. This oversight can result in the production of inaccurate or unexecutable SQL queries.
To fully exploit the structure, we propose the structure-to-SQL framework, which leverages the inherent structure information to improve the SQL generation of LLMs.  Specifically, we introduce our \textbf{\underline{S}tructure \underline{Gu}ided SQL~(SGU-SQL)} generation model. SGU-SQL links user queries and databases in a structure-enhanced manner. It then decomposes complicated linked structures with grammar trees to guide the LLM to generate the SQL step by step. Extensive experiments conducted on two benchmark datasets demonstrate SGU-SQL outperforms all state-of-the-art baselines.
