\title{Generating CAD Code with Vision-Language Models for 3D Designs}

\begin{abstract}

Generative AI has transformed the fields of Design and Manufacturing by providing efficient and automated methods for generating and modifying 3D objects. One approach involves using Large Language Models (LLMs) to generate Computer-Aided Design (CAD) scripting code, which can then be executed to render a 3D object; however, the resulting 3D object may not meet the specified requirements. Testing the correctness of CAD generated code is challenging due to the complexity and structure of 3D objects (e.g., shapes, surfaces, and dimensions) that are not feasible in code. In this paper, we introduce {\ours,} a novel approach to iteratively verify and improve 3D objects generated from CAD code. Our approach works by producing ameliorative feedback by prompting a Vision-Language Model (VLM) to generate and answer a set of validation questions to verify the generated object and prompt the VLM to correct deviations.  To evaluate \ours, we introduce, \emph{CADPrompt}, the first benchmark for CAD code generation, consisting of $200$ natural language prompts paired with expert-annotated scripting code for 3D objects to benchmark progress. Our findings show that {\ours} improves VLM performance by providing visual feedback, enhancing the structure of the 3D objects, and increasing the success rate of the compiled program. When applied to GPT-4, \ours achieved a 7.30\% reduction in Point Cloud distance and a 5.0\% improvement in success rate compared to prior work.

\end{abstract}

\section{Introduction}









Generative AI, such as Large Language Models (LLMs) and Vision-Language Models (VLMs), offers a unique opportunity to enhance productivity, reduce costs, and increase efficiency within Design and Manufacturing sectors ~\citep{kumar2023machine}. These industries are critical contributors to the global economy and responsible for creating products and infrastructure. Recent work has shown that Generative AI can provide solutions towards generating, evaluating, and correcting designs of 3D objects ~\citep{nelson2023utilizing, kodnongbua2023reparamcad, makatura2023can}. However, while these solutions improve efficiency for designers and engineers, they lack efficient feedback mechanisms or refinement loops to automatically correct any inaccuracies in the initially generated 3D object. 

Our research explores the potential of using VLMs to generate and refine Computer-Aided Designs (CAD), the leading method in industrial design for creating, modifying, analyzing, and optimizing 3D objects~\citep{sarcar2008computer}. Utilizing CAD software such as FreeCAD \citep{riegel2016freecad} and AutoCAD \citep{yarwood2013introduction} to design products typically requires significant training and domain expertise. 
CAD software typically includes underlying scripting languages which allow a user to build parametric 3D objects using code, rather than through the user interface.  Leveraging the code generating faculties of Generative AI allows us to circumvent the challenges of utilizing CAD software by directly generating the underlying scripting code representing a 3D object.  
We define the process of generating and refining 3D objects using LLMs or VLMs, via CAD scripting code, as CAD code generation. Designs produced by off-the-shelf VLMs or LLMs frequently deviate functionally or structurally from stakeholder specifications, because Generative AI models tend to hallucinate on complex, out-of-distribution tasks. Developing refinement methods to correct inaccuracies in a generated design is a critical next-step in this research. Current state-of-the-art refinement methods are contingent on human-in-the-loop domain expertise ~\citep{makatura2023can, nelson2023utilizing}. Obtaining a domain expert is not always feasible and can be time consuming. Automated refinement mechanisms are necessary to improve on the initially imperfect designs and close the feedback loop. Augmenting CAD code generation methods with fully-automated feedback mechanisms will empower non-expert end users to generate their own designs, and reduce the onerous, iterative design process. 

In this work, we introduce \ours, a fully automated method for refining CAD code generation. \ours eliminates the need for human involvement by generating and answering validation questions based on user requirements and providing feedback to refine 3D object code. 
This feedback is employed to iteratively refine the design.
To evaluate \ours, we introduce a novel benchmark, \textit{CADPrompt}, designed specifically for assessing the performance of Generative AI (e.g., LLMs and VLMs) in CAD code generation and refinement. \textit{CADPrompt} contains $200$ 3D objects annotated with natural language prompts and expert-written Python code. This multimodal benchmark enables researchers to evaluate aspects of CAD code generation such as object quality and the syntactical correctness of the generated code. Our experimental results demonstrate that \ours not only enhances the quality of generated 3D objects but also improves the performance of LLMs and VLMs by increasing the success rate of compiled programs. %By incorporating visual feedback into the code generation process, \ours sets a new state-of-the-art in CAD code refinement.


Our work presents three key contributions:
\begin{enumerate}[topsep=0pt]
    \setlength{\itemsep}{-3pt}%
    \item 
    We propose \ours, a novel CAD code refinement method that enables a VLM to visually inspect generated objects and provide corrective feedback, through a question-generation and answering process, to resolve any deviations from the user's specifications.
    \item With our benchmark, \textit{CADPrompt}, we provide the first quantitative evaluation of CAD code generation capabilities across widely used VLMs, including GPT-4, Gemini 1.5 Pro, and CodeLlama.
    \item We demonstrate that \ours sets a new state-of-the-art in refining 3D designs via CAD scripting, achieving a $7.30\%$ reduction in Point Cloud distance and a $5.5\%$ increase in successful object generation when applied to GPT-4, the leading VLM for CAD code generation.
    
\end{enumerate}

\section{Related Work}

We review two integral categories of prior work: LLMs for code generation and recent advances in automated design and manufacturing.

\subsection{LLMs for Code Generation}
\label{sec:code-gen}

LLMs have demonstrated impressive results in a variety of code generation applications. The most popular application is the text-to-code task, wherein users prompt LLMs with a description of the code, which facilitates the LLM to generate the code \citep{Code_llama, svyatkovskiy2020intellicode, GPT3, poesia2022synchromesh}. 
Another application is the text-to-SQL task, in which a database and question are provided to the LLMs, and then the LLMs generate the SQL query \citep{rajkumar2022evaluating}.
We build upon these contributions to explore how LLMs can assist non-experts and designers to generate 3D objects via CAD code. 

Prior research has demonstrated that LLMs can notably improve their generated code through feedback pertaining to the quality of the generated code ~\citep{chen2023personalised}. One approach involves LLMs providing their own feedback, wherein the LLMs generate explanatory rationales for the initially generated code. These rationales are then used as feedback, along with the initial code, to refine the output~\citep{self_debug}. Another approach involves receiving feedback from external tools, such as static code analysis~\citep{alrashedy}, or a Python Interpreter~\citep{madaan2023self}. Contrary to other works, self-correction ~\citep{welleck2022generating}, involves training two models: a generator and a corrector. The generator model produces the initial output, which is then refined by the corrector model. In CAD code refinement, one line of work introduced a basic feedback mechanism ~\citep{yuan20243d}, using VLMs to refine 3D object code based on a script and an image. However, this method still struggles with feedback efficiency and refinement detail. In this work, we propose a novel approach to generate visual feedback that enhances the shapes, surfaces, and dimensions of 3D objects through code refinement.

\subsection{Language for Automated Design and Manufacturing}
\label{sec:language-design}


Learning a shared embedding space between language and 3D objects is essential to integrate language modeling into design and manufacturing. 
Recent work has developed foundational multimodal transformers in the image-text space~\citep{radford2021learning, li2023blip, liu2023visual}, which can be leveraged to perform a variety of tasks.
These approaches have inspired similar techniques to integrating 3D objects into this a shared embedding space~\citep{zeng2023clip2, xue2023ulip, yu2022point, guo2023point}, thereby facilitating a range of multimodal tasks such as dialog, classification and evaluation with 3D data~\citep{hong20233d, xu2023pointllm}.
While these approaches are capable of learning a shared embedding space between language and 3D objects, they are incapable of generating 3D objects. 

Generative modeling of 3D data has historically relied on probabilistic models for 3D space, such as Generative Adversarial Networks (GANs)~\citep{goodfellow2014generative}, Variational AutoEncoders (VAEs)~\citep{kingma2013auto}, and Diffusion Models~\citep{ho2020denoising}. While GANs and VAEs~\citep{wu20153d, achlioptas2018learning, gadelha2018multiresolution, yang2019pointflow, YAN202416} have historically been popular approaches, diffusion models have recently emerged as the state-of-the-art for probabilistic 3D modeling~\citep{zeng2022lion, koo2023salad}. Diffusion models facilitate controllable object generation through language-guided shape generation and completion albeit their applicability in producing manufacturable designs remains limited ~\citep{li2023diffusion, kodnongbua2023reparamcad}. These models typically output point clouds or voxels, neither of which are readily adaptable to manufacturing, due to their non-parametric nature. Thus, methodologies producing parametric outputs suitable for manufacturing are needed.

Recent studies have revealed the capability of VLMs to produce designs via parametric CAD code~\citep{makatura2023can, nelson2023utilizing}; however, these works find that GPT-4 requires a significant amount of human feedback to produce code that accurately reflects the initial specifications. 
In this paper, we address this limitation by developing \ours to alleviate the need for a human expert by allowing a VLM to automatically generate and adapt a 3D object.
 


\section{CAD Code Generation}



Our goal is to enable VLMs to accurately generate 3D objects from non-expert language specifications. As shown in Figure \ref{fig:overview}, we take a three-step approach: (1) code generation (\S \ref{subsec:codegen}), (2) code execution (\S \ref{subsec:codeexec}), and (3) code refinement via \ours (\S \ref{sec:Code_Refinement}). 
\subsection{Code Generation} 
\label{subsec:codegen}
We prompt the VLM to generate initial CAD scripting code, $y_0$, based on a natural language description of the 3D object, $x$, along with task specifications. We employ CADQuery, a Python-based parametric CAD language equipped with a compiler that processes code, to output parametric 3D objects, i.e., render. 

Thus, CAD code generation can be broadly formulated as per Equation~\ref{eq:1}.

\begin{equation}
y_0 \sim P_{LM}(y_0|x,E_{g}). 
\label{eq:1}
\end{equation}

\subsection{Code Execution} 
\label{subsec:codeexec}

The generated CAD code, $y_0$, is next executed by the CADQuery compiler, $\psi$, to produce the initial CAD design, $d_0$, in the Standard Triangle Language (STL) format,\footnote{Standard Triangle Language is also referred to as ``Standard Tessellation Language''. The STL (STereoLithography) file format is an openly documented format for describing the surface of an object as a triangular mesh, that is, as a representation of a 3-dimensional surface in triangular facets.\label{fn:note2}} where $0$ indicates the initial version of both the generated code and CAD design. We denote this process as $d_0 \sim \psi(y_0)$. Occasionally, the model produces code which does not compile, typically caused by syntactical issues in the Python code. 
We apply insights from prior work on code repair~\citep{self_debug}, to CAD code generation. 

This process is repeated until a 3D-object, $d_k$, is successfully rendered by $\psi(y_k)$, or the maximum number of iterations $N$ is reached as per Equation~\ref{eq:compiler_errors}.

\begin{equation}
y_k \sim \{P_{LM}(y_k|x,y_{k-1},F_{err})\}_{k=1}^N.
\label{eq:compiler_errors}
\end{equation}





 



\subsection{Code Refinement via \ours} 
\label{sec:Code_Refinement}
To correct any discrepencies in the generated design, we construct feedback, $F_{ref}$, to further refine $y_k$ as described by Equation \ref{eq:code-ref}, where $M$ is the number of refinement iterations,\footnote{In all our experiments, we set the number of refinements to 2, as we did not observe any improvement after the second refinement, which is also consistent with prior work on refinement for code generation~\citep{madaan2023self, chen2023personalised}}. We optionally include a set of four reference images of the generated object, taken from different angles (0, 90, 180, and 270 degrees), $I_{ref} = \{I_l^0,I_l^{90},I_l^{180},I_l^{270}\}$. 
\begin{equation}
y_{M} \sim \{P_{LM}(y_{l+1}|x,y_{l},{F_{ref}}, I_{ref})\}_{l=N}^{N+M}.
\label{eq:code-ref}
\end{equation}
The key intuition behind our approach, \ours, is to develop a feedback mechanism that leverages a vision-language model to produce visual feedback, which helps improve the generated 3D object \textit{without} needing human expertise as in prior work~\citep{makatura2023can} or any external tools (e.g., geometric solvers --- see \S \ref{Baseline}). \ours consists of two sub-steps:
\paragraph{(1) Question-Answer Generation:}% \ours generates a set of Yes/No verification questions $\mathrm{Q} = \{q_1, q_2, \dots, q_n\}$ based on the language description $x$ and a set of few-shot example questions $E_q$, i.e., $\mathrm{Q} \sim P_{LM}(\mathrm{Q}|x, E_q)$. Using the initial object description, generated questions, and images of the generated 3D object, we prompt the LLM to answer each of the validation questions as shown in Equation \ref{eq:Generate answer}.

\ours generates a set of binary Yes/No verification questions, $\mathrm{Q} = \{q_1, q_2, \dots, q_n\}$, based on the language description, $x$, and a set of few-shot example questions, $E_q$, i.e., $\mathrm{Q} \sim P_{LM}(\mathrm{Q}|x, E_q)$. 
 To generate answers, \ours uses images of the generated 3D object ${I_{ref}}$, the generated questions $Q$, and the language description $x$, where \ours answers each of the validation questions as described in Equation \ref{eq:Generate answer}.

\begin{equation}
A \sim P_{LM}(A|x,\mathrm{Q}, \mathrm{I_{ref}}). 
\label{eq:Generate answer}
\end{equation}
 Additionally, \ours is instructed to respond with "Unclear" when it determines that sufficient information is lacking to accurately answer the question.


\paragraph{(2) Feedback Generation:} The question-answer sets are next used to generate ameliorative feedback for refining the 3D object as per Equation \ref{eq:f_ref}.
\begin{equation}
F_{ref} \sim P_{LM}(F_{ref} |\mathrm{Q}, \mathrm{A}).
\label{eq:f_ref}
\end{equation}

\noindent The feedback, $F_{ref}$, is then utilized for the code refinement, as described Equation (\ref{eq:code-ref}). During the feedback generation step, we exclude any questions for which the answer is ``Yes'' to enable the model to focus on resolving any outstanding issues. If the answer to all questions is ``Yes,'' then we assume that no further refinement is needed.

\section{\textit{CADPrompt}

\label{sec:dataset}

For evaluating \ours on CAD code generation, we introduce a new benchmark \textit{CADPrompt}, which consists of $200$ 3D objects, represented both in images and in the Standard Triangle Language (STL) formats. We hired annotators to write natural language prompts for creating each of the objects step-by-step (see examples in Figure \ref{fig:examples}), and we also hired a CAD design expert to write Python code.

\subsection{Prompt Creation}
\label{Prompt_Creation}
To construct \textit{CADPrompt}, we first selected $200$ 3D objects from a dataset of modular CAD objects used in the prior work ~\citep{Wu_2021_ICCV}. We then manually annotated each of the $200$ objects with natural language prompts. If a 3D object was abstract or difficult to describe, two annotators would write separate prompts, followed by a third independent annotator who selected the better option.
This dual annotation process was conducted for $65$ out of the $200$ examples. 
Finally, an independent reviewer, who was not involved in the original annotation process, verified and further refined each of the $200$ language prompts to ensure accuracy and grammatical correctness.
We chose to exclude the precise numeric parameters (e.g., height of an object) in the prompt as average users may not have access to such knowledge or lack the expertise necessary to specify accurate parametric designs in the real-world use cases. Table \ref{tab:statistics_data} provides the statistics of the \textit{CADPrompt} dataset. 


\subsection{Code Annotation}To annotate \textit{CADPrompt} with Python code, we hired a CAD design expert to develop Python scripts that generate the 3D objects described in \S \ref{Prompt_Creation}. The expert was provided thelanguage description of the 3D object, the 3D object in STL format, and the geometric properties generated by the geometric solver (see Figure \ref{fig:geometric_solver_feedback}). We then use Blender \citep{flavell2011beginning} to verify the 3D objects produced by the Python code with the ground truth, as well as evaluate its geometric properties (see Figure \ref{fig:comparison_code_GT}). In cases where discrepancies were found, the Python code was returned to the CAD expert for further refinement. Figures \ref{fig:CADPromptExample_1} and \ref{fig:CADPromptExample_2} provide examples of Python code from \textit{CADPrompt}. 
\subsection{Data Stratification}
\label{sec:dataset-stratification}
We stratify \textit{CADPrompt} examples according to compilation difficulty and object complexity to gain insights into model performance (\S \ref{sec:results}).

\paragraph{Object complexity:} The complexity of a 3D object is defined by the total number of faces and vertices it contains. The ground truth of the 3D object is represented in mesh file formats, which consist of a collection of vertices, edges, and faces $(x, y, z)$ used to create the 3D object in the STL format. A 3D object with a large number of faces and vertices is considered more complex, while an object with fewer faces and vertices is regarded as simple (see Table \ref{tab:statistics_data}). We split our dataset by complexity, classifying each 3D object as either (i) Simple or (ii) Complex based on its complexity in relation to the median. Simple objects are defined as those with less complexity than the median while complex objects are greater than the median.

\paragraph{Compilation difficulty:} The difficulty of the 3D object is measured by the total amount of compiled code for each object generated during the initial generation step across all experiments. We compare the compiled code resulting from zero-shot and few-shot prompting techniques across all language models utilized in this paper: GPT-4, Genimi, and CodeLlama. We split the data based on the total number of compilable outputs from the experiments (ranging from 0 to 6).

\section{Experiment Results}

\label{sec:results}
\color{black}
We utilize \textit{CADPrompt} to quantitatively evaluate the capabilities of \ours approach across various VLMs. The following are our key findings:  

\textbf{GPT-4 exhibits the highest capacity to generate compile-able code on \textit{CADPrompt}.}
We report our primary results in Table~\ref{tab:main_results}, comparing the distance and success-rate for three LLMs and three refinement methods. 
With regards to ``success-rate,'' GPT-4 exhibits superior performance $96.5\%$ on the \textit{CADPrompt} benchmark compared to Gemini $85\%$ and CodeLlama $73.5\%$. 
While prior work has provided valuable qualitative insights into  GPT-4's competency to producing compile-able code~\citep{makatura2023can}, our analysis, via \textit{CADPrompt}, provides a concrete assessment of each LLMs CAD code generation capacity.

\textbf{\ours shows superior performance on more challenging data. }
Figure~\ref{fig:easy-hard-bargraph} presents the success rates for each feedback mechanism at generation and refinement stages, using the difficulty and complexity splits of \textit{CADPrompt}. For "Easy" data, the performance across all baselines is relatively comparable. However, results on the "Hard" data underscore the effectiveness of \ours. It is the only refinement approach that improves the success rate of object generation, achieving approximately a 9\% increase at the Refine-1 stage. In contrast, 3D-Premise struggles to provide effective feedback for "Hard" data, resulting in a 20\% drop in success rate at Refine-1, bringing it down to 62\%. %A similar pattern is observed in the "Complex" data split, where 3D-Premise experiences a steeper decline in success rate across refinement stages compared to \ours. 
Real-world data in design and manufacturing is likely to align more closely with the "Complex" and "Hard" data splits. Our results demonstrate the value of \ours in providing feedback that can be applied to real-world product design.

This result emphasizes the model-agnostic nature of the multimodal ``assess and reason'' analysis induced by our \ours refinement process, to universally produce actionable feedback for correcting object generation errors.

\textbf{Ablation Analysis.} We perform an ablation analysis to test the effectiveness of each independent component of \ours (See Table~\ref{tab:main_results}). We conduct this ablation with GPT-4, with a few-shot prompt, on 100 randomly selected examples from \textit{CADPrompt}. First, we ablate the inclusion of few-shot example questions in the question-generation component (see Equation~\ref{eq:code-ref}).  The results shows that zero-shot QA generation increases the distance between the ground truth and refined 3D objects from $0.126$ to $0.141$ in Point Cloud distance and from $0.444$ to $0.471$ in Hausdorff distance. 
Our second ablation measures the impact of the reference images, $I_{ref}$,  during the code refinement step of Equation~\ref{eq:code-ref}. Removing the reference images worsens the Point Cloud distance and Hausdorff distances from $0.126$, $0.444$ to $0.153$, $0.451$ respectively, highlighting the importance of the reference images.





\section{Limitations}



It is essential to recognize that Point Cloud distance and Hausdorff distance are noisy metrics, measuring only the spatial similarity between two 3D objects. While they provides an broad estimate of similarity, there is a need for a more granular metric that can distinguish the structural differences between objects. For instance, a desk and a desk with small gaps between the legs and the surface might have a small distance measure, but these gaps represent critical logical or structural issues that should be captured in the evaluation. In future work, we aim to explore evaluation methods for CAD code generation that incorporate logical design principles to assess object similarity more accurately.

The quality of the generated objects and the likelihood of successfully compiling code are highly dependent on the user's initial prompt. Due to the flexibility of natural language, the interpretation of 3D objects can vary, resulting in multiple valid but functionally different descriptions for the same object. For example, one could describe a desk functionally as "Draw a desk with four legs," or more geometrically as "Draw an object with a flat rectangular top supported by four long rectangular prisms at each corner." In our approach, we incorporated review procedures to improve data quality, though it was not feasible to exhaustively explore all possible annotation methods. Future research could further investigate this prompt sensitivity and explore strategies for identifying the most effective prompts for specific VLMs.



\section{Conclusion}

In this work, we formally define a nascent task, CAD code generation, wherein VLMs are utilized to generate code for 3D parametric models.
We compiled a novel \textit{CADPrompt} dataset, consisting of $200$ 3D objects paired with corresponding language descriptions and Python code. \color{black}Next, we propose a novel approach for code refinement within CAD code generation, called \ours, wherein we enable a VLM to validate and correct its generate object to fix any errors in the generation. 
We compare \ours to two relevant approaches for code refinement for CAD code generation to highlight the strengths and weaknesses of each code refinement method. Our approach marks a significant improvement over previous CAD code generation methods, which primarily relied on manual human feedback through language interactions with VLMs.
