\title{AutoCode4Math: Learning Autonomous Code Integration for Math LLMs}

\begin{abstract}
Recent research on tool integration for math Large Language Models (LLMs)  aims to combine complementary strengths of chain-of-thought (CoT) reasoning and code execution. However, we discover a critical limitation: current tool-integrated math LLMs rely on externally dictated instructions to decide whether to use CoT or code, lacking the autonomy to choose the most appropriate method independently. This prompts us to study \emph{Autonomous Code integration } (AutoCode) for math LLMs, which enables models to \emph{independently} develop their own methodology-selection strategy in the absence of reliable supervision. To address this challenge, we propose an innovative Expectation-Maximization (EM) formulation that refines the model's decision-making through the exploration of its capabilities. This framework alternates between (a) computing a reference strategy that improves the model's belief over its capabilities through self-exploration, and (b) updating the model based on the refined belief. We further enhance this framework with an efficient implementation, incorporating a novel data synthesis strategy and off-policy reinforcement learning. Extensive experiments demonstrate that our approach, using only a public query set, significantly boosts the performance of existing math LLMs, raising accuracy by nearly 20% to 65.28%  on the challenging MATH benchmark, while reducing code executions by up to 65% . 
\end{abstract}

\section{1 INTRODUCTION  }


Large Language Models (LLMs) have demonstrated remarkable performance across various domains (Kaddour et al., 2023; Achiam et al., 2023; Dubey et al., 2024; Team et al., 2023; Yang et al., 2024), yet they face significant challenges when addressing complex mathematical problems, such as abstract reasoning and intricate calculations (Gao et al., 2023; Yue et al., 2023; Gou et al., 2023; Li, 2024). To tackle these challenges, two primary paradigms have emerged: chain-of-thought (CoT) reasoning (Wei et al., 2022; Yu et al., 2023; Luo et al., 2023) and the use of external tools, such as Python programs (Toshniwal et al., 2024; Yue et al., 2023). Both strategies offer distinct yet complementary benefits. CoT is highly effective for semantic analysis, planning, and abstract reasoning, but it often struggles with precise computations. In contrast, leveraging python programs offloads mathematical operations to specialized tools like symbolic solvers or numerical libraries. Nonetheless, this approach has shown vulnerability in effectively translating natural language queries into correct code (Li, 2024).  

Recent advancements focus on synergizing these paradigms by developing tool-integrated reasoning frameworks, such as TORA (Gou et al., 2023; Shao et al., 2024), HTL (Li, 2024) and DotaMath (Li et al., 2024a), which merge CoT reasoning with code generation to provide more fluid interactions between abstract reasoning and precise computation. However, despite the potential benefits of incorporating external tools, their successful integration presupposes that the model is both adept at using the tool and capable of reasoning effectively about the problem with the code.  

This assumption raises concerns about LLMs’ capability boundaries of using tools, underscoring the need for more intelligent code integration strategies. Rather than a reactive decision, code integration should be a deliberate decision informed by the model’s capabilities, mirroring human-like methodology-selection for problem-solving.  

We distill this objective into a central goal: developing autonomous code integration (AutoCode) for math LLMs, as illustrated in Fig. 1. Existing tool-integrated math LLMs generally lack the AutoCode capability, because these models are trained to follow an externally imposed methodology that do not adapt to their unique strengths. Therefore, we ask:  

How to enable LLMs to learn their own strategies to select the methodology for math queries, such that it complements the model’s inherent capabilities?  

To address this challenge, we introduce a novel Expectation-Maximization (EM) formulation that enables a self-teaching mechanism without relying on external dictations. Specifically, the Expectation step (E-step) computes a reference strategy through self-exploration, representing the belief over its capabilities. The maximization step (M-step) updates the LLM based on the data induced by the new belief. Furthermore, we propose an efficient joint training scheme for this framework, which features a novel data synthesis strategy for offline data curation and efficient off-policy reinforcement learning (RL).  

Extensive experiments show that, using merely public query set, our method significantly improves existing math LLMs. For instance, our 7B model enhances accuracy on the challenging MATH benchmark (Hendrycks et al., 2021) by nearly $20\%$ and reaches $65.28\%$ accuracy, while reducing up to $65\%$ code executions.  

Our contribution is summarized as follows: (1) We identify a critical gap in the existing research on math LLMs, that they struggle with autonomous code integration (AutoCode). (2) We propose a novel EM learning framework that empowers LLMs to develop their own AutoCode strategies, tailored to their inherent capabilities. (3) We showcase a neat and efficient implementation of this EM framework, featuring a novel data synthesis strategy and an efficient off-policy RL training. Extensive results show substantial improvements in both accuracy and computational efficiency.

\section{2 METHODOLOGY  }


2.1 PROBLEM STATEMENT   
Recent research have studied tool integration for math LLMs. Specifically, given a math query $x_{q}\in X_{Q}$ , expressed in natural language, the goal is to generate a solution using a language model (LM), denoted as $\mathcal{M}_{\theta}$ , parameterized by $\theta$ . Importantly, the LM is augmented with access to a Python interpreter, allowing it to execute Python code as needed during inference. We are interested in allowing the model to choose the appropriate methodology (denoted as $c$ ) – either CoT reasoning or code snippets – and generate the corresponding solutions $y_{t}\in\mathcal{V}$ based on the preceding context $(x_{q},y_{<t})$ . When code integration is necessary, the model generates special tokens ‘‘‘python and $\cdots$ to trigger the Python interpreter, after which the execution results are appended to the ongoing context. Both the math query $x_{q}$ and the response $y_{t}$ consist of sequences of natural language tokens, with interleaved code integration as necessary (see Fig. 1 for an example).   
Our goal is to develop a language model that autonomously integrates code execution for math problem-solving, switching seamlessly between CoT reasoning and code execution when appropriate. Conceptually, such code-integrated reasoning process involves two repeated steps: (a) Methodology selection. The model first decides whether to use code execution or CoT reasoning based on the context; (b) Solution generation. Based on the chosen methodology, the model generates either executable Python code or CoT rationales.   
We note that the methodology selection step can occur either implicitly (via the model’s internal states) or explicitly (through verbal cues generated by the model). For example, in our implementation, the model is trained to signal the chosen method at the beginning of its response (see Fig. 1), through verbal cues such as Let’s write a program for code integration, and Let’s reason step by step for CoT reasoning. However, it is not required to signal every methodology-selection decisions. For instance, as shown in Fig. 1 (Right), the model can correct code using CoT reasoning without explicit cues.   
We formally define our problem as follows. Let $c\in{\mathcal{C}}\,=\,\{0,1\}$ denote the methodology of CoT and code integration, respectively. Given the math query $x_{q}$ , the model selects a methodology $c$ , and generates a corresponding solution $y_{a}\;\sim\;p(y_{a}|x_{q},c;\dot{{\cal M}})$ . This decision-making process iterates until the LM predict an end token. Upon termination, the model receives a binary feedback $r\,=\,\mathbb{I}(y_{a})\,\in\,\{0,1\}$ , where the indicator function $\mathbb{I}(y_{a})$ evaluates the correctness of the predicted solution $y_{a}$ by comparing it to the gold answer. For clarity and simplicity, we focus our discussion on a single iteration of the methodology-selection and solution-generation process, which adheres to the following factorization of the language policy: $\begin{array}{r}{p_{\theta}(y_{a}|x_{q})\stackrel{*}{=}\sum_{c}p_{\theta}(\dot{c_{}}y_{a}|x_{q})=\sum_{c}p_{\theta}(c|x_{q})}\end{array}$ · $p_{\theta}(y_{a}|x_{q},c)$ . 2.2 THE EM FORMULATION   
Challenge and Motivation. The key challenge in achieving autonomous code integration (AutoCode) lies in the absence of reliable supervision for making methodology-selection decisions. Existing math LLMs typically employ supervised fine-tuning (SFT) to empower tool integration (Yue et al., 2023; Wang et al., 2023b; Li et al., 2024a; Gou et al., 2023; Shao et al., 2024; Li, 2024), which relies on externally dictated expert decisions. Training on such data fall short because it fails to dynamically adapt to the model’s unique capabilities.   
To address this challenge, we draw inspiration from human decision-making. Humans evaluates whether to seek external assistance based on the complexity of the task and their belief in their ability to handle it. This belief is refined through exploration, observation and reflection. For instance, consider solving a complex math problem, such as finding the roots of an equation. A person might attempt manual calculations using roots formula, or resort to a calculator. To form a belief about whether external tools are necessary, humans explore both options and observe the outcomes. Through reflection on such experiences, they recognize their limitations in manual computation results, and develop a belief that relying on a calculator improves accuracy for such problems. The EM Framework. Inspired by this analogy, we propose an Expectation-Maximization (EM)- based approach that emulates the cognitive process of belief refinement and intelligent decisionmaking, alternating between two key steps (Fig. 2):

1. Self-Exploration (E-step): Explore the model’s inherent capabilities to identify a reference strategy for methodology selection that maximizes utility. 2. Self-Refinement (M-step): Refine the model’s belief about its capabilities under the supervision of the reference strategy, and evolve the model’s capabilities through reinforcement.  

To address the lack of direct supervision for methodology selection, we treat $c$ as a latent variable. Our goal is to identify the methodology $c$ and corresponding solution $y_{a}$ that maximizes the likelihood of generating a correct response for a given query. This motivates transforming the maximum value problem into a maximum likelihood problem, which we define as:  

$$
\begin{array}{r l}&{\mathcal{I}_{\mathrm{MLE}}(\theta)\doteq\log P(r=1|x_{q};\theta)\quad}\\ &{\qquad\qquad=\log\displaystyle\sum_{c}p_{\theta}(c|x_{q})\sum_{y_{a}}p_{\theta}(y_{a}|x_{q},c)\cdot P(r=1|y_{a},c,x_{q}).}\end{array}
$$  

The factorization reflects the distinct roles of methodology-selection $p_{\theta}(c|x_{q})$ and the solutiongeneration $p_{\theta}(y_{a}|x_{q},c)$ in the LLM’s decision-making process.  

The EM framework provides an effective solution for maximizing this MLE objective in the presence of latent variables Bishop & Nasrabadi (2006). Intuitively, EM handles the methodology-selection decision $c$ by introducing a reference distribution (strategy) $s(c|x_{q})$ , analogous to a belief system in human decision-making.  

From the MLE objective, we derive the evidence lower bound (derivations detailed in Sec. A.1):  

$$
\begin{array}{r l}&{\mathcal{I}_{\mathrm{MLE}}(\theta)\geq\mathbb{E}_{s(c|x_{q})}\left[\log\frac{p_{\theta}(c|x_{q})\cdot P(r=1|c,x_{q};\theta)}{s(c|x_{q})}\right]}\\ &{\qquad\qquad\overset{,}{=}\mathcal{I}_{\mathrm{ELBO}}(s,\theta).}\end{array}
$$  

The EM framework alternates between two-steps.  

E-step. This step seeks the reference strategy $s(c|x_{q})$ by optimizing the following objective:  

$$
\operatorname*{max}_{s}\mathcal{I}_{\mathrm{ELBO}}(s,\theta)=\operatorname*{min}_{s}\mathrm{D}_{\mathrm{KL}}\left(s\left(c|x_{q}\right)\|P\left(r=1,c|x_{q};\theta\right)\right).
$$  

This effectively computes the reference strategy $s(c|x_{q})$ as the posterior of methodology $c$ generating correct response for a given query $x_{q}$ , i.e., $P(r=1,c|\bar{x}_{q};\theta)$ . If decision $c$ are more likely to succeed, the reference strategy accordingly assigns higher probability mass to the decision. By computing the reference strategy, $E$ -step provides effective guidance for methodology-selection in the absence of reliable supervision.  

M-step. Using the reference strategy $s(c|x_{q})$ from the $\mathrm{E}$ -step, the M-step updates the model parameters $\theta$ to maximize the ELBO:  

$$
\operatorname*{max}_{\theta}\mathcal{J}_{\mathrm{ELBO}}(s,\theta)=\operatorname*{max}_{\theta}\mathbb{E}_{s(c|x_{q})}\left[\mathbb{E}_{p_{\theta}(y_{a}|x_{q},c)}[R(x_{q},y_{a})]+\log p_{\theta}(c|x_{q})\right].
$$  

The objective comprises two terms focusing on different sub-policies. The first term optimizes the solution-generation policy $p_{\theta}(y_{a}|x_{q},c)$ for reward maximization, akin to reinforcement learning through exploration. The second term computes a log-loss, essentially supervising the current methodology-selection strategy $p_{\theta}(c|x_{q})$ using the reference strategy.  

Discussion. Our EM framework mirrors the human cognitive process of belief refinement and intelligent decision-making. During the E-step, the framework engages in a form of self-exploration by probing its internal model capabilities to identify a reference strategy. This approach stands in contrast to SFT, which relies on external demonstrations.  

In the subsequent M-step, the focus shifts to self-refinement: the model adjusts its methodology selection based on the reference strategy while reinforcing solution generation. This iterative process enables the model to dynamically adapt to its own strengths and weaknesses, meanwhile fostering continuous improvement. Unlike standard Reinforcement Learning (RL) methods, which enhance decision-making through localized exploration around the current policy, our proposed approach uniquely narrows the policy search space by leveraging the guidance from the reference strategy.  

Beyond addressing the challenge of autonomous code integration, our EM framework is supported by a robust theoretical foundation. It exhibits favorable properties, such as monotonic improvement of the objective function. Specifically, the evidence lower bound (ELBO) objective satisfies the inequality: $\mathcal{J}_{\mathrm{ELBO}}(s_{1},\theta_{0})\leq\bar{\mathcal{J}}_{\mathrm{ELBO}}(\dot{s}_{1},\theta_{1})\leq\mathcal{J}_{\mathrm{ELBO}}(s_{2},\theta_{1})$ , indicating a guaranteed progression toward better performance as the model iterates through the EM steps.  



\section{2.3 PRACTICAL IMPLEMENTATION  }


While the EM framework provides a promising solution for AutoCode, its practical application faces two primary challenges. First, the E-step (Eq.5) involves computing the posterior, which is inherently complex. Second, the M-step (Eq.6) introduces fragmented training processes: SFT for methodology selection using offline data and RL for solution generation via on-policy interactions. This separation not only complicates implementation but is also nonsensical, as both policies share the same parameter space in a unified LLM policy and should not be trained separately.  

To address these challenges, we present a practical implementation that unifies the training of methodology-selection and solution-generation policies, enabling efficient joint optimization. This streamlined approach consists of a data curation stage and an offline RL training stage. Specifically, the data curation stage produces data for methodology selection and solution generation, combining them into complete responses using two distinct synthesis strategies. These complete responses enable a modified M-step objective (Eq. 6) that supports efficient offline training without the need for on-policy interactions. B.  



\section{2.3.1 DATA CURATION  }


We first elucidate the relationship between solving the E-step for the reference strategy and generating data for this strategy. Then we elaborate on the data synthesis strategies used to combine the training data for methodology-selection and solution-generation.  

E-step and Data Generation. In the E-step (Eq. 5), computing the exact posterior for the reference strategy is typically complex, often requiring the training of a variational distribution $s_{\phi}(c|x_{q})$ parameterized by separate neural networks $\phi$ (Zintgraf et al., 2019; Wang et al., 2020; 2023a). However, in our implementation, this complexity is mitigated. The reference strategy is only needed to supervise methodology selection $p_{\theta}(c|x_{q})$ , not during inference. Given the binary action space $c\in\{0,1\}$ , the posterior $P(r\,=\,1,c|x_{q};\theta)$ can be estimated via Monte Carlo simulations, similar to how humans refine beliefs through exploration and observation: to decide whether external assistance is necessary, humans explore the options and adjust their belief based on the outcomes.  

Specifically, the posterior is factorized as $P(r\,=\,1,c|x_{q};\theta)\,=\,p_{\theta}(c|x_{q};\theta)\cdot P(r\,=\,1|c,x_{q})$ . We estimate the prior through Monte Carlo rollouts:  

$$
p_{\theta}(c|x_{q};\theta)\approx\frac{1}{K}\sum_{i=1}^{K}\mathbb{I}\{y_{i}\mathrm{~uses~methodology~}c\}
$$  

where $y_{i}\sim\pi_{\theta}$ is one of $K$ random rollouts from the LLM generation policy $\pi_{\theta}$ .  

The likelihood $P(r=1|c,x_{q};\theta)$ is defined via the Q-function, $Q(x_{q},c)$ , which evaluates the expected return of methodology choice $c$ given the context of $x_{q}$ :  

$$
Q(x_{q},c)=\mathbb{E}_{p_{\theta}(y_{a}|x_{q},c)}[R(x_{q},y_{a})]\approx\frac{1}{K}\sum_{i=1}^{K}r_{i}.
$$  

where $R(x_{q},y_{a})$ represents the reward function. The $\mathrm{^Q}$ -values can be estimated using $K$ Monte Carlo rollouts per query-methodology pair. We note that the Q-function aligns directly with the likelihood function $P(r=1|c,x_{q};\theta)$ , as both both quantify the effectiveness of the query-methodology pair $(x_{q},c)$ . This enables us to define: $P(r=1|\bar{c},x_{q};\bar{\theta})\propto Q(x_{q},c)$ .  

Combining these estimates, the reference strategy satisfies $s^{*}(c|x_{q})\propto p_{\theta}(c|x_{q})Q(x_{q},c;\theta)$ , forming an energy-based distribution,  

$$
s^{*}(c|x_{q})=\frac{\exp\left(\alpha\cdot p_{\theta}(c|x_{q})Q(x_{q},c;\theta)\right)}{Z(x_{q})}.
$$  

where the temperature $\alpha\,>\,0$ controls the sharpness of the distribution, and $Z(x_{q})$ is the partition function that normalizes the distribution. Indeed, the reference strategy represents a softmaxed distribution over methodology choices, from which we sample to generate data for supervised methodology-selection training.  

Dataset Synthesis. Our goal for data curation is to collect a dataset where each dataset sample $(x_{q},y,r)$ includes a query $x_{q}$ , a response $y$ , and a reward $r$ . The complete response $y$ is obtained by concatenating sequences of methodology-selection and solution-generation (see Fig. 2 for an example): $\boldsymbol{y}=\bar{\mathrm{Concat}}(\{(c,y_{a})_{t}\}_{t=1}^{T})$ . The methodology choices $c$ are sampled from $\boldsymbol{s}^{*}\bar{(c|\boldsymbol{x}_{q})}$ , and the solutions are generated using two inference modes:  

• Dictated: Explicitly specifying the methodology $c$ in the instruction.   
• Native: Natively generating complete responses without guiding methodology.  

The data for learning methodology-selection and solution-generation is merged into complete responses using two synthesis strategies:  

• Self-Exploratory Synthesis. We select dictated and native solutions that aligns with the (sampled) reference decision $c^{*}$ , forming single-round or self-correction responses. • Self-Reflective Synthesis. We create multi-round responses by transitioning between methodologies. For example, initial attempts using one methodology (e.g., CoT) may fail, and we hint by a reflective hint to transition to the another methodology (e.g., code) for a successful solution. Formally, the responses are synthesized as $y=\operatorname{Concat}(\{c^{-},y_{a}^{-},c^{*},y_{a}\})$ . Here $c^{-}$ denotes an alternative methodology to the reference decision $c^{*}$ , and $y_{a}^{-}$ and $c=c^{*}$ are the corresponding solutions. Detailed examples are illustrated in Fig. 2.  

2.3.2 EFFICIENT JOINT TRAINING  

Using the curated dataset of complete responses, we unify the learning of methodology-selection and solution-generation into a single offline training process. To achieve this, we modify the M-step objective (Eq. 6) by introducing the off-policy policy gradients:  

$$
\operatorname*{max}_{\theta}\mathbb{E}_{s(c|x_{q}),\xi(y_{a}|x_{q},c)}\left[O\left(\xi,p_{\theta}\right)\cdot R\left(x_{q},y_{a}\right)\cdot\log p_{\theta}\left(y_{a}|x_{q},c\right)+\log p_{\theta}\left(c|x_{q}\right)\right],
$$  

where $\xi(y_{a}|x_{q},c)$ is a behavior policy, $p_{\theta}(y_{a}|x_{q},c)$ is the improvement policy, and $O(\xi,p_{\theta})$ is the off-policy correction term compensating for the discrepancy between these policies.  

To stabilize training, we use query-wise reward whitening and employ a clipping scheme on the off-policy correction term following PPO (Schulman et al., 2017): $\begin{array}{r l}{O\left(\xi,p_{\theta}\right)}&{{}=}\end{array}$ $\begin{array}{r}{\mathrm{Clip}\left(\frac{p_{\theta}\left(y_{a},\bar{c}\left|x_{q}\right)}{\xi\left(y_{a},c\right|x_{q}\right)},0.8,1.2\right)}\end{array}$  

This unified process efficiently integrates the training of two sub-policies into a cohesive framework, allowing for a neat implementation of iterative data curation and offline RL.

\section{3.2 ABLATION STUDY  }


The proposed approach relies on two key elements: (1) the EM framework, which factorizes response generation into methodology-selection $p_{\theta}(c|x_{q})$ and solution-generation $p_{\theta}(y_{a}|x_{q},c)$ , and (2) a self-reflective data synthesis strategy that generates multi-round responses.  

Ablation of the EM Formulation. We compare our method with a baseline using standard RL without explicit methodology-selection, employing an off-policy RL approach for computational parity. The performance curve on the in-domain test sets is shown in Fig. 3. shows that standard RL rapidly converges to suboptimal performance, whereas AutoCode achieves better final accuracy through sustained improvement. This indicates a clear advantage for our EM framework over standard RL.  

We also analyze code execution rates for both approaches on in-domain test sets. As Tab. 2 shows, the standard RL approach often introduces more code executions while remaining inferior accuracy. We hypothesize that standard RL focuses solely on outcome optimization, overlooking the role of methodology-selection in improving final accuracy. In contrast, our EM framework enforce its methodology-selection by leveraging the guidance from the reference strategy, which is computed through exploration of its capability boundaries.  

Logically, selecting the methodology yielding higher expected utility must in turn improve the final accuracy. We conjecture that the proposed EM framework outperforms standard RL because: the reference methodology-selection strategy helps narrow the policy search space during training. By restricting training samples to those methodology choices with higher utility, the language model can converge more efficiently, benefiting from effective guidance of methodology-selection.

\section{3.3 ANALYSIS OF THE LEARNED MODEL.  }


To understand the effectiveness of the learned methodology-selection strategy, particularly its ability to decide when to use or avoid code, we evaluate its contributions to accuracy. We focus our analysis on the first round of methodology-selection, arguing that this initial decision captures the essential characteristics of the strategy, while subsequent rounds play a minor role in overall accuracy.  

We introduce the alignment rate as a key metric to measure how closely the learned strategy aligns with an oracle strategy. The oracle strategy, determined over the test set, dictates that code is used only if it is the sole path to a correct response; otherwise, CoT reasoning is preferred. We classify the correct responses into three categories: (1) StrictAlign, where decisions match the oracle exactly, (2)  

AllowCode, where we consider using code acceptable if both code and CoT yield correct answers, and (3) MisAlign, where the model’s choice diverges from the oracle.  

Fig. 4 shows these alignment categories in stacked bars. The RL model has a significantly lower rate of strict alignment compared to AutoCode (lightblue bar), which is not surprising as the RL model is not explicitly trained for this alignment. In contrast, the proposed EM framework is forced to imitate the behavior of the reference strategy, which computes the oracle selection over training queries. Additionally, regarding code executions, the RL model also tends to favor code more than AutoCode, particularly in the case of Qwen2Math. This is because Qwen2Math has better overall accuracy using code than CoT reasoning, and RL captures this statistical relation. In contrast, the proposed method can implicitly reduces code execution as a side effect, because the oracle selection to imitate during training by design involves minimal code executions.  

Interestingly, compared with other models, a significant proportion of correct responses from AutoCode are in the MisAlign category. This seems counter-intuitive at first sight, but we note that the oracle choice is determined based on their expected utilities, which means the MisAlign choice can result in correct response at a probability, which is inferior to the oracle choice in the expected sense. This implies that a MisAlign choice can be optimized for final accuracy by improving the corresponding solution-generation capability. Further comparison with NO REFL suggests that multiround responses also play a crucial role in this advantage.  



\section{4 RELATED WORK AND DISCUSSION  }


Tool-Integrated Math LLMs. Math language models (LLMs) have been developed primarily along two major paradigms: Chain-of-Thought (CoT) reasoning and the use of external tools, such as Python programs (Yu et al., 2023; Yue et al., 2023; Toshniwal et al., 2024). Each paradigm offers unique benefits, and recent advancements increasingly seek to combine these approaches for synergistic effects, as seen in methods like Hybrid Instruction Tuning (Yue et al., 2023) and various forms of tool-integrated reasoning (Gou et al., 2023; Li et al., 2024a; Li, 2024; Wang et al., 2023b; Shao et al., 2024). Despite these advancements, existing models still face challenges with autonomous code integration, mainly because they rely on supervised fine-tuning where code integration is suboptimally dictated by external annotators. To address this gap, our work introduces a novel EM framework that avoids using external supervision to facilitate AutoCode capabilities.  

EM for RL. Expectation-Maximization (EM) has proven effective for maximum likelihood problems involving hidden variables, such as Expert Iteration (Anthony et al., 2017), Iterative Maximum Likelihood (Wu, 2016; Agarwal et al., 2019), Meta-Reinforcement Learning (Zintgraf et al., 2019; Wang et al., 2020), and Adversarial Games (Wang et al., 2023a). In the context of math LLMs, the most relevant works are (Singh et al., 2023) and (Ni et al., 2022), which apply EM-style iterative self-training to math problem-solving. Unlike these approaches, we employ the EM framework specifically to tackle the lack of reliable supervision for autonomous code integration in math LLMs.  

Discussion. This paper investigates autonomous code integration for math LLMs. To address the challenge of unreliable external supervision, we propose to factorize out the hidden methodologyselection from response generation, and develop a novel EM formulation. The EM framework alternates between computing a reference strategy for methodology-selection through self-exploration and updating language model based on the reference guidance. This approach supports an efficient joint training scheme that allows for holistic offline data collection coupled with RL training. Our extensive experiments demonstrate the effectiveness of the proposed method, and our ablation studies further elucidate the properties of the learned model.  

However, there are several limitations and areas for future work regarding AutoCode4Math. First, the generalization of methodology-selection depends significantly on the quality of the collected query set. Further research is needed to understand what characteristics of queries contribute to effective generalization. Second, we did not extensively explore the influence of hyperparameters related to RL iterations, such as dataset size and the number of iterations, in the current version. We are actively working on this. Third, as this is a preliminary work in autonomous code integration, we have not yet investigated alternative approaches for decision routing, such as using Mixtureof-Experts (MoEs) (Masoudnia & Ebrahimpour, 2014), and we not yet fully understand the fundamental reason why EM outperforms RL. These areas present important directions for advancing AutoCode capabilities in math LLMs.
