## Summary

The paper introduces DailyDilemmas, a dataset of 1,360 synthetic moral dilemmas generated by GPT-4, where each dilemma has two actions annotated with affected parties and associated human values. The authors evaluate six LLMs on these dilemmas and analyze their value preferences through five theoretical lenses (World Value Survey, Moral Foundation Theory, Maslow's Hierarchy of Needs, Aristotle's Virtues, Plutchik Wheel of Emotion). They also compare actual model behavior against stated alignment principles from OpenAI ModelSpec and Anthropic Constitutional AI, and test steerability via system prompts.

## Strengths

1. **Multi-theory evaluation framework reveals concrete, cross-model preference differences.** The paper traces LLM decisions through five established theoretical lenses and identifies specific, quantifiable disagreements — e.g., Mixtral-8x7B neglects *truthfulness* by 9.7% while GPT-4-turbo selects it by 9.4% (Section 5.1). This granular, theory-grounded comparison is more informative than single-framework analyses common in prior work.

2. **Empirical comparison of stated alignment principles vs. actual model behavior is novel and insightful.** The paper maps OpenAI ModelSpec and Anthropic Constitutional AI principles to underlying value conflicts and then tests whether models' actual decisions align with those principles (Section 5.2, Table 1). For example, GPT-4-turbo favors *transparency* over *privacy* (negative weighted score difference of -5.5) despite OpenAI's stated privacy principle. This goes beyond simply accepting provider claims at face value.

3. **Stratified sampling across 17 identified topics mitigates topic bias.** The dataset is constructed by topic-modeling 50,000+ generated dilemmas and sampling 80 per topic (Section 4.1), producing balanced coverage across interpersonal relationships, workplace, environmental issues, etc. This is more systematic than ad-hoc collection used in comparable moral dilemma datasets.

4. **Clear formal definition and induction-driven value extraction method.** The paper provides a formal structure for moral dilemmas (D, A^do/A^not, parties, perspectives, values) and a multi-step Chain-of-Thought approach to broaden (via perspective-taking) and deepen (via loss aversion) value consideration (Section 2.2). This principled pipeline is well-documented and reproducible.

## Weaknesses

### Fatal
None.

### Major

- **Circularity in value annotation: the ground-truth value labels are generated by GPT-4 and not validated against human annotators.** Every dilemma situation, affected party, and associated value in the dataset is produced by GPT-4 (Section 3). The human validation in Section 4.3 checks whether the *dilemma situations* resemble real Reddit posts — it does **not** validate whether the *value labels assigned to each action* are correct or complete. The word-level evaluation (60% of GPT-4-generated value words appear in Reddit comments) is a weak proxy: comment text is not authoritative value annotation, and synonym expansion is broad. Since the same class of model (GPT-4) generated the labels and is evaluated against them, the reported "value preferences" may partially reflect GPT-4's own generation patterns rather than an independent property of tested models. **Why this matters:** it undermines the claim that the dataset *reveals* value preferences rather than measuring alignment with GPT-4's value-assignment procedure. This is partially mitigated by: (a) cross-model disagreements (e.g., Mixtral vs. GPT-4 on *truthfulness*) show the dataset captures genuine variation beyond GPT-4's own output; (b) the five-theory framework provides external structure; (c) LLM-generated simulation data is an accepted methodology (the paper cites Park et al., Shao et al.). Nevertheless, the lack of human validation on the value labels themselves is a significant gap for a benchmark dataset.

- **The steerability experiment is too narrow to support the broad conclusion drawn.** The experiment uses exactly one model (GPT-4-turbo), two principles (principles 4 and 12 from OpenAI ModelSpec), and two prompt formulations per principle (Section 5.3). Yet the abstract concludes that "end users cannot *effectively* steer such prioritization using system prompts" — a general claim about steerability from a minimal design. The observed effect (preference shifts in one direction regardless of steering prompt) could stem from multiple unexamined factors: the model's prior bias may be too strong, the two selected principles may be unrepresentative, or the prompts may be poorly calibrated. **Why this matters:** drawing a general conclusion about end-user steerability from this narrow setting is not warranted. The paper should either expand the analysis substantially or temper the claim.

### Minor

- **Value-to-principle mapping for the ModelSpec analysis introduces additional circularity.** GPT-4-turbo is prompted to identify which of the 301 values are relevant to each OpenAI/Anthropic principle (Section 5.2, line 131), and the same model is then evaluated on dilemmas using those mappings. For the GPT-4-turbo analysis specifically, the mapping and the evaluation are not independent. (Claude-haiku's evaluation is independent since the mapping is done by GPT-4-turbo, not Claude.)

- **Validation scale is limited.** The human evaluation uses 30 Reddit posts (90 dilemmas) with Cohen's κ = 0.526 (moderate), and the word-level evaluation uses only 5 posts. These provide useful but thin evidence that the dataset reflects real-world dilemmas. The validation effort is commendable as a first step, but the sample size is small relative to the overall dataset size (1,360 dilemmas).

- **No analysis of the 301 value labels for coherence or redundancy.** The paper filters values by frequency (appearing in <100 dilemmas) but does not report whether the 301 remaining values are conceptually distinct, contain duplicates, or conflate related concepts. A manual audit or inter-annotator consistency check on the value set would strengthen confidence.

- **No dataset/code release commitment is stated in the provided sections.** For a paper whose primary contribution is a benchmark dataset, a commitment to public release is standard practice and should be stated.

## Nice-to-Haves

- Expand the steerability experiment to 2–3 models (including Claude) and 5–10 principles with multiple prompt formulations, and quantify variability. The current design is too sparse.
- Provide bootstrapped confidence intervals for the reported preference differences, especially since values are not uniformly distributed across the dataset.
- Directly compare model behavior on DailyDilemmas vs. existing benchmarks (ETHICS, Value-kaleido, MoralExceptionQA) to establish what new information the dataset provides.
- Validate the value labels on a substantial subset (e.g., 200 dilemmas) with independent human annotators to break the circularity.

## Novel Insights

The most interesting observation emerging from the review process is that the cross-model preference differences (e.g., Mixtral vs. GPT-4 on *truthfulness*) actually *partially rebut* the circularity concern: if the value labels purely reflected GPT-4's generation biases, all models would converge toward similar preferences. The fact that different architectures exhibit divergent value profiles suggests the dataset captures meaningful variation. This dynamic — where a vulnerability (LLM-generated labels) is partially counterbalanced by the divergent outcomes it produces — is worth highlighting and could be tested more rigorously by checking whether model families cluster by training methodology rather than by label generation source.

## Suggestions

1. **Validate a random subset of value labels with independent human annotators.** This single intervention would substantially address the main weakness. Even 200 dilemmas with 2–3 annotators each would break the circularity.
2. **Temper the steerability conclusion** to match the experiment's scope (e.g., "In our limited study with GPT-4-turbo on two principles, system prompts were ineffective at steering value preferences") or expand the experiment to support the original claim.
3. **State a commitment to release the dataset and code** in the final version. For a benchmark paper, this is essential for the contribution to be verifiable by the community.
4. **Add a brief manual audit** of the 301 values (e.g., report inter-annotator agreement on a random sample, or flag potential duplicates) to establish coherence.
