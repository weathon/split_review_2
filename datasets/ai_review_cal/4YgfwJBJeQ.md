## Summary

This paper proposes StructChart, a two-stage paradigm for chart understanding that: (1) extracts chart information using a Chart-oriented Information Extractor (CIE) and represents it as Structured Triplet Representations (STR), (2) feeds STR to an LLM (GPT-3.5) for downstream reasoning tasks (QA, summarization, redrawing). The paper additionally introduces the SCRM metric for evaluating chart perception quality, and SimChart9K, an LLM-generated synthetic chart dataset. The core contributions are in the STR representation, which outperforms linearized CSV (LCT) by 3.6 points on ChartQA when using the same reasoning engine, and the data augmentation pipeline that enables matching full-data perception performance with only 20% real data.

## Strengths

- **Structured Triplet Representations (STR) improve reasoning over linearized CSV (LCT)**: Table 4 shows STR+GPT-3.5 achieves higher Exact Match than LCT+GPT-3.5 (reported as 86.7% vs 83.4% — a 3.6 point gain), when the LLM reasoning engine is held constant. This clean within-pipeline comparison cleanly isolates STR's value.

- **SCRM provides a chart-type-agnostic perception metric with tunable tolerance**: Equations 3–9 define evaluation across three tolerance levels (strict, slight, high) using IoU-based precision/mPrecision. This directly addresses the gap that prior metrics were tied to single chart types.

- **SimChart9K enables matching full-data perception with only 20% real data**: Table 5 shows that 20% of ChartQA real samples + SimChart9K yields mPrecision(strict)=84.47, exceeding the 100% real-data baseline of 84.14. Tables 3 and 6 show consistent gains on PlotQA and Chart2Text. This is the paper's strongest experimental result.

- **Continuous performance scaling with simulated data**: Table 3 shows mPrecision(strict) rising monotonically from 78.88 (0.1K simulated samples) to 85.53 (9K simulated samples), demonstrating the practical value of the LLM-based generation scheme.

- **Unified framework spanning perception, reasoning, summarization, and redrawing**: Table 1 explicitly contrasts StructChart against prior works, showing it is the only method covering all four task categories.

## Weaknesses

### Fatal
None.

### Major

- **Overclaiming in the QA comparison against prior methods**: The paper states "Our StructChart+GPT3.5 pipeline surpasses all baselines on the ChartQA validation set" (line 186). This comparison conflates the contribution of STR with the use of a substantially larger reasoning model (GPT-3.5) — the prior baselines (VL-T5-OCR, Pix2Struct, Matcha, DePlot) use smaller finetuned models. The paper does include the well-controlled comparison (LCT+GPT-3.5 vs STR+GPT-3.5, a 3.6-point gap), which is its strongest evidence. However, the headline framing suggests the *paradigm* surpasses prior work, when the experiment does not separate the effect of STR from the effect of switching to a much larger reasoning model. This is primarily a framing/positioning issue affecting the presentation of results, not a technical flaw in the method itself.

### Minor

- **"100% performance" phrasing is imprecise**: Section 4.3 is titled "ACHIEVING 100% PERFORMANCE BY ONLY 20% REAL DATA." The text clarifies that this means matching the perception metrics of the model trained on 100% real data, not 100% absolute accuracy. However, the title alone could mislead readers. The text could be clearer, e.g., "Matching Full-Data Perception Performance with 20% Real Data."

- **No quantitative analysis of the self-inspection mechanism**: The data augmentation pipeline (Section 3.3) uses an iterative skip mechanism to filter non-executable drawing code. The paper describes it at a high level ("iteratively skip the non-executable code generated by GPT-3.5, until all the drawing code... can be executable") but provides no data on success rate, number of iterations typically required, or rejection rate. This matters for assessing the cost and reliability of the data production method.

- **Variable-resolution ViT design choice not credited**: The CIE uses "a fixed number of patches... according to the original resolution" (line 54). This is a known technique from Pix2Struct (Lee et al., 2022), which the paper cites in related work but does not credit for this specific design choice. The paper should explicitly acknowledge this.

- **Claim that STR is less position-sensitive than LCT lacks supporting ablation**: The paper argues LCT is "highly position-sensitive" while STR is not, but triplets still encode ordering (the order in which they are fed to the LLM). An explicit ablation showing STR is more robust to row/column permutation than LCT would strengthen this claim.

## Nice-to-Haves

- **Error analysis for the CIE perception stage**: The paper could analyze failure cases — e.g., charts with small font sizes, overlapping text, decimal precision, or complex layouts. This would help guide future work.
- **Analysis of SCRM tolerance levels' correlation with downstream QA accuracy**: The three tolerance levels (strict, slight, high) are defined, but the paper does not analyze which best predicts downstream QA performance.

## Suggestions

1. **Reframe the QA comparison in Table 4**: Present the clean within-pipeline STR vs. LCT comparison (with GPT-3.5 held constant) as the primary result, and move the comparison against prior methods to a separate table with explicit caveats about reasoning model size and training data.
2. **Add a permutation-robustness ablation for STR vs. LCT**: Show that STR's performance degrades less under random row/column permutations; this would directly evidence the claim about reduced position sensitivity.
3. **Report the self-inspection mechanism's statistics**: Provide the average number of iterations, success rate, and rejection rate for SimChart9K generation.
4. **Rephrase Section 4.3's title**: Replace "ACHIEVING 100% PERFORMANCE" with something like "MATCHING FULL-DATA PERCEPTION PERFORMANCE" to avoid misinterpretation.
5. **Acknowledge Pix2Struct for the variable-resolution ViT design** where the CIE is described.
