## Summary

VideoPrompter is a training-free framework for zero-shot video understanding that enhances both sides of a VLM: (1) visual features are enriched by fusing video embeddings with descriptions generated by a video-to-text model (Video-ChatGPT/VGPT), and (2) classifier representations are enriched via GPT-3.5-generated language attributes, descriptions, and a novel Tree Hierarchy of Categories that provides high-level action context. The approach is evaluated on action recognition, retrieval, and time-sensitive tasks across seven datasets and four VLMs, showing consistent improvements.

## Strengths

- **Simultaneous enhancement of visual and text representations yields consistent gains across multiple VLMs and benchmarks.** Table 2 shows CLIP improves by +13.29% on HMDB-51, +11.05% on UCF-101, and +4.64% on K400, with similar gains for ViFi-CLIP, AIM, and ActionCLIP. Figure 4 demonstrates the two modules (VGPT and GPT-3.5) are complementary and their combination outperforms either used alone. Figure 3 (left) confirms that fusing video and description embeddings beats using either modality alone.

- **High-level action context via LLM-based tree hierarchy provides a novel and effective enhancement for video action recognition.** Table 6 shows that adding action context further boosts CLIP from 49.17% to 52.03% on K400 and from 50.79% to 52.51% on HMDB-51. Table 1 lists the generated high-level contexts (e.g., "playing sports" for basketball/cricket/baseball), supporting a genuine conceptual contribution beyond prior context-based methods (e.g., WafflingCLIP) that assumed a single high-level context unsuitable for diverse video datasets.

- **Plug-and-play adaptability to multiple VLMs without any training.** Table 2 shows consistent improvements on four different VLMs (CLIP, ViFi-CLIP, AIM, ActionCLIP), all achieved with zero fine-tuning, directly validating the claim that the framework is a "plug-and-play module."

- **Generalization to retrieval and time-sensitive tasks.** Table 3 shows gains on MSR-VTT retrieval (Video-to-Text R@1: +3.11, Text-to-Video R@1: +1.8). Table 4 reports a +10% gain on a time-consistency synthetic dataset and +1.4% on Charades, demonstrating applicability beyond standard action recognition.

- **Interpretability via decomposition of attribute contributions.** Figure 2 visualizes per-attribute cosine similarity (e.g., "golf-course," "golf-ball," "swing" for predicting "golf"), providing transparency into model decisions that standard zero-shot VLMs lack.

## Weaknesses

### Fatal
None.

### Major

- **CLIP-based filtering introduces selection bias that conflates description quality with model self-alignment.** Section 4.2.2 describes generating 10 VGPT descriptions per video and using CLIP's own cosine similarity (between the video embedding and each description embedding) to select the top-3 descriptions. This means the same model being evaluated is used to curate its own inputs: descriptions that are already well-aligned with CLIP's embedding space are preferentially selected. Figure 3 (middle) shows filtering helps, but this ablation compares filtered vs. unfiltered — it does not disentangle whether the gain comes from genuinely better descriptions or from selecting descriptions that the same CLIP model will naturally score higher. The paper frames this as a preprocessing step but does not discuss the circularity or provide an alternative filtering strategy (e.g., using a different model). This methodological concern directly affects the zero-shot purity of the action recognition results.

### Minor

- **The comparison with CUPL (Table 5) is confounded and does not cleanly support the "three descriptors are enough" claim.** The comparison varies multiple factors simultaneously: CUPL uses GPT-3 while VideoPrompter uses GPT-3.5 (a model upgrade); CUPL has no VGPT module while VideoPrompter includes VGPT descriptions. The observed improvement could come from the better LLM, the VGPT descriptions, or the action context rather than from using only three descriptors. An ablation holding the LLM version constant and varying descriptor count *within* VideoPrompter would be needed to substantiate the claim. The paper partially acknowledges this by saying "combined with the video-to-text guided visual feature enhancement module" (Sec. 4.2), but the headline claim in Sec. 2.2 ("only requires three descriptors") is overly strong given the confounds.

- **Missing baseline: VGPT's own zero-shot classification performance.** The paper relies on VGPT (Video-ChatGPT) to generate video descriptions but never reports what accuracy VGPT achieves when prompted directly to classify actions (e.g., "What action is happening? Options: {class list}"). VGPT is a capable video QA model, and without this baseline the reader cannot assess whether the ensemble is genuinely additive (VGPT + CLIP > either alone) or whether most of the gain reflects distilling VGPT's own knowledge through CLIP. The paper notes one failed attempt at using GPT-3.5 + VGPT descriptions for direct classification (Sec. 4.1), but this is not the same as evaluating VGPT as a standalone classifier.

- **No statistical significance or variance reported.** No standard deviations, confidence intervals, or multi-seed runs are provided. Given the modest gains on retrieval tasks (e.g., +1.8% Text-to-Video R@1), it is unclear whether these improvements are stable or within noise. This is especially important for the retrieval and Charades results where gains are small.

- **The SSv2 results are not meaningfully analyzed.** SSv2 performance remains very low (4.87% for CLIP+VideoPrompter). The paper notes the action context is ineffective because GPT-3.5 groups all classes under "manipulating objects" (Sec. 3), but does not analyze whether the VGPT descriptions or language descriptors provide any marginal benefit. Understanding *why* the method fails on fine-grained temporal understanding would deepen the contribution, given the otherwise thorough evaluation.

- **The claim "performs on par with fully fine-tuned methods" is somewhat overstated.** In Table 2, CLIP+VideoPrompter achieves 72.77% on UCF-101 vs. ViFi-CLIP's 77.5% — a ~5 point gap. On HMDB-51 it is closer (50.79% vs. 51.82%). "Competitive" would be more accurate than "on par" for the UCF case.

### Trivial

- **The handling of negative β₂ is underspecified.** β₂ is defined as the cosine similarity between the query video embedding and the description embedding (line 191), which ranges from -1 to 1. When β₂ is negative, the description embedding would be subtracted from the video embedding rather than added. The paper does not discuss whether this occurs in practice or how it is addressed (e.g., clipping to 0).

## Nice-to-Haves

- A hyperparameter sensitivity analysis for the number of VGPT descriptions (currently fixed at 3 for action recognition, 10 for retrieval) and for the number of language descriptors would strengthen the evaluation.
- Reporting approximate inference time or API cost relative to the base VLM would help practitioners assess the practical trade-off of the ensemble.
- The paper could discuss using open-source alternatives to GPT-3.5 and VGPT to improve reproducibility, since proprietary API models change over time.

## Suggestions

1. **Address the filtering concern directly** by (a) explicitly discussing the potential selection bias in the paper, (b) providing an ablation that filters descriptions using a different model (e.g., an off-the-shelf sentence encoder) or via random selection, and (c) showing that the method's improvement holds without the filtering step — or, if it does not, discussing what this implies about the source of the gain.

2. **Add a controlled descriptor-count ablation:** Compare 3 vs. 10 vs. 50 GPT-3.5 descriptors (without VGPT, holding the LLM version constant) to directly support the "three descriptors are enough" claim.

3. **Report VGPT's zero-shot classification accuracy** by prompting it as a direct classifier: "What action is happening in this video? Options: {list of class names}." This would establish whether VGPT + CLIP is strictly additive.

4. **Tone down the "on par" framing** for UCF-101 specifically (5-point gap to ViFi-CLIP), replacing it with "competitive" or providing a more precise characterization.

5. **Report standard deviations** across at least 3 random seeds (or note the evaluation protocol's stability) for the main results, especially retrieval where gains are modest.
