## Summary
Blueprint-Bench introduces a benchmark for evaluating spatial intelligence in AI models through the task of converting apartment photographs into accurate 2D floor plans. The paper evaluates LLMs (via SVG code), image generation models (direct image output), and agent systems (Docker-based) on 50 apartments with ~20 interior images each, scoring outputs via a composite similarity metric based on room connectivity graphs and size rankings. The headline finding is that most models perform near or below a baseline generated without image input, while humans substantially outperform all tested AI systems.

## Strengths
1. **Cross-architecture comparability on a unified spatial task**: The paper evaluates LLMs, image generation models, and agent systems on the exact same task with a shared scoring metric (§2.2). This enables direct numerical comparison between these model families on spatial reasoning, addressing a genuine gap given that recent image-generation model announcements (GPT Image, NanoBanana) lacked quantitative benchmarks (Section 1).

2. **Controlled comparison of single-pass vs. iterative refinement**: The paper tests whether poor performance stems from single-pass generation by comparing standard LLMs with agent-based systems (Codex CLI, Claude Code) that can iteratively refine outputs (§3, Figure 8). The finding that iterative refinement provides no meaningful improvement—and that agents often fail to even inspect their own outputs—is non-obvious and rules out a plausible alternative explanation for the benchmark's difficulty.

3. **Well-specified extraction pipeline**: The scoring algorithm uses clearly described computer vision techniques (HSV filtering, contour detection, flood-fill segmentation from detected red centers, green-pixel scanning along walls) to parse floor plans into structured representations (§2.3). The extraction steps are reproducible given the strict formatting rules.

4. **Transparent documentation of methodological failures**: Section 2.4 honestly reports experiments with LLM-based extraction (abandoned due to prior bias about which room type "should" be largest) and shape-based scoring (abandoned because it harshly penalized small mistakes unpredictably). This strengthens confidence in the chosen methodology.

## Weaknesses

### Fatal
None.

### Major
1. **The "random baseline" is misleadingly constructed and named**: The baseline is called "random" (Figures 5, 7; Abstract line 9) but is actually generated by LLMs *without image input* — it captures whatever prior knowledge models have about typical apartment layouts (§2.2: "created a worst-case baseline by generating typical floor plans using LLMs and image generation models without any image input"). A true non-informative baseline (random room placement, random connectivity) would likely score near zero. The paper's central claim that "most models perform at or below a random baseline" is therefore ambiguous — models are being compared to a baseline that already encodes implicit spatial structure, which inflates the apparent gap and makes the headline result harder to interpret.

2. **Scoring metric weights are arbitrary and unvalidated**: The composite score uses fixed weights (50% edge overlap, 20% degree correlation, 10% graph density, 10% room count, 5% door count, 5% door orientation) with no justification, sensitivity analysis, or validation against human similarity judgments (§2.3). For a benchmark paper where the metric is a central contribution, this is a significant gap. The paper further acknowledges that the size-ranking-to-room-ID mapping causes cascading errors (§2.4) and speculates that "one similarity scoring model would make the human's lead over the AI models much larger" (§3) — meaning the metric's relative ranking of humans vs. AI is itself sensitive to an acknowledged design issue.

3. **Human baseline is too thin to support the paper's strongest conclusions**: Human data was collected on only 12 of 50 apartments (§3, Figure 7 caption). No information is given about number of participants, their backgrounds, time limits, training on formatting rules, number of raters per apartment, or inter-rater agreement. The paper's headline result — that AI models lag "substantially behind" humans — relies on comparing 12 data points from an unspecified number of humans against model scores averaged over 50 apartments. This is not a robust reference ceiling for a benchmark.

4. **Benchmark conflates instruction-following with spatial intelligence**: GPT-4o and NanoBanana scored below the random baseline due to "poor instruction following" (§3, line 138) — outputs violating formatting rules could not be scored. The paper acknowledges this tension (§2.4: "Blueprint-Bench should test spatial intelligence, not instruction following") but does not resolve it. Models that understand spatial layouts perfectly but fail output format get low scores, while models that happen to produce rule-compliant but spatially random outputs could score above baseline through format compliance alone. This confound means the benchmark's scores conflate at least two distinct capabilities.

### Minor
1. **Small effective sample size for a benchmark**: N=50 apartments is small for drawing fine-grained model distinctions. The paper claims some models "statistically perform better than the random baseline" (§3, line 112) without reporting any statistical test or confidence intervals. The 0.02–0.05 gaps between GPT-5, Gemini 2.5 Pro, GPT-5-mini, and Grok-4 cannot be interpreted without uncertainty estimates.

2. **Missing reproducibility details**: The paper does not specify prompts used per model, temperature/sampling parameters, number of attempts/generations per apartment, or image presentation order (§2.2). These are essential for fair comparison and independent reproduction.

3. **Model version and categorization inconsistencies**: "CodeX (GPT-6)" in Figure 5 vs. "Codex (GPT-5)" in Figure 7 refer to the same agent but with different model versions. Claude Code (Opus 4.1) is categorized as "Image model" in Figure 5's table despite being an agent scaffold. The appendix mentions model names (Claude 4.5, Claude 3.5 Sonnet/Haiku/Opus) that do not match the main paper's model list (Claude Opus 4.1, Claude Sonnet 4).

4. **"Epochs" used without definition**: The results section (§3, line 112) refers to averaging "across apartments and epochs" but never defines what an epoch means (multiple runs? multiple attempts per apartment?).

5. **No discussion of dataset diversity**: The paper does not describe whether the 50 apartments cover varied layout types (studio apartments, multi-story lofts, irregular shapes), which matters because model performance is likely uneven across layout complexity.

### Trivial
None.

## Nice-to-Haves
- Report a separate format-compliance rate per model to disentangle instruction-following from spatial reasoning.
- Add sensitivity analysis for the scoring weights (do model rankings change if weights shift?).
- Validate the scoring metric against human similarity judgments (e.g., pairwise floor-plan comparison on a Likert scale).
- Expand and fully document the human evaluation: multiple participants per apartment, standardize instructions, report inter-rater agreement.
- Replace the "random" label for the no-image baseline with a more accurate term (e.g., "image-free baseline" or "prior-knowledge baseline") and report a true random baseline alongside it.
- Add a brief discussion situating Blueprint-Bench relative to existing spatial reasoning evaluations.
- Provide confidence intervals or bootstrap-based tests for all cross-model comparisons.

## Suggestions
