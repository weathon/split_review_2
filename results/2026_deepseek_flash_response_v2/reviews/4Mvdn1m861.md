## Summary

TokenCount proposes a training-free framework for object counting using SAM, without architectural modifications or auxiliary models. It introduces two components: (1) probabilistic prompt generation that samples point prompts from a similarity-derived multinomial distribution, and (2) output-token-based verification that uses TS-SS (a hybrid geometric similarity metric) on SAM's decoder output tokens to distinguish positive from negative instances. The method achieves MAE 16.25 on FSC-147 (best among SAM-only training-free methods) and MAE 4.68 on CARPK (beating all training-based methods).

## Strengths

1. **Output token-based verification is a genuinely novel idea** — The paper identifies that SAM's output tokens jointly encode semantic (angular) and positional (magnitude) information, making standard similarity metrics (cosine, L2) inadequate. Using TS-SS as a hybrid metric improves MAE from 16.48 (cosine) to 16.25 on FSC-147 (Table 3). The controlled ablation in Table 5 directly shows that operating on output tokens (16.25 MAE) outperforms operating on image embeddings (16.94 MAE) in the same pipeline, cleanly isolating the benefit of the output token space.

2. **Strong CARPK results** — On CARPK, the method achieves MAE 4.68 / RMSE 6.13, beating all training-based methods (e.g., SAFECOUNT 5.33/7.04, BMNet+ 5.76/7.83) and most training-free methods using only SAM. This is a striking demonstration that a training-free, SAM-only pipeline can outperform methods requiring category-specific training data.

3. **Probabilistic prompt generation with adaptive distribution updates** — Rather than using static grids or superpixels, the method computes a probability distribution from exemplar-query similarity and iteratively updates it: verified positive regions are zeroed out, negative regions are down-weighted. This avoids redundant prompting and is validated by Table 4, which shows consistent improvement with more iterations and prompts per iteration.

4. **Thorough ablation studies** — Three separate ablations isolate the contribution of each component: verification metric (Table 3), iteration/prompt trade-offs (Table 4), and output-token vs. image-embedding space (Table 5). These systematically confirm that each design choice contributes to performance.

5. **PCA visualization supports the core claim** — Figure 5 shows that output tokens form well-separated clusters for positive vs. negative instances, while image embeddings from the same prompts overlap, directly visualizing why the output token space is more discriminative.

## Weaknesses

### Fatal
None.

### Major

1. **Abstract and central claims overstate the results, contradicted by the paper's own data** — The abstract states: "our method achieves superior accuracy with an MAE of 16.25, outperforming existing training-based and training-free counting methods." This is false on the evidence presented. In Table 1, TFCAC (a training-free method using SAM+DINO) achieves **12.26** MAE — substantially better. Several training-based methods also outperform 16.25: LOCA (10.79), PseCo (13.05), BMNet+ (14.62). The same overreach appears in the conclusion ("performance equal to or better than existing methods"). The body text is more measured ("best performance among training-free SAM only methods"), but the abstract and conclusion overclaim. This is not a minor wording issue — the headline claim is misleading.

2. **Stochastic method evaluated without any measure of variance** — The core of the method is stochastic: prompts are sampled from a multinomial distribution (Section 3.1). Running the same image twice with different random seeds will produce different prompts and counts. Yet the paper reports a single MAE/RMSE per configuration with no error bars, standard deviations, or confidence intervals. The improvements over simpler alternatives are small — TS-SS (16.25) vs. cosine (16.48) is only 0.23 MAE; output token space (16.25) vs. image embedding space (16.94) is 0.69 MAE. Without knowing whether the standard deviation is 0.1 or 2.0, the reader cannot assess whether these differences are meaningful or whether the method is stable. Every table (1–5) shares this flaw.

3. **CARPK comparison may be unfair due to asymmetric exemplar usage** — For CARPK, the paper states it "randomly selected 12 objects from the training set to use as exemplars" (Section 4.1), but does not report how many exemplars the compared methods use. Standard protocols for training-free methods on CARPK typically use 1–3 exemplars. Using 12 provides substantially richer reference information, making the headline "outperforming all supervised methods" less informative without an ablation controlling for exemplar count.

### Minor

4. **Method achieves best results through brute-force prompting (~1400 SAM decoder runs per image)** — The best configuration in Table 4 (16 iterations × 128 prompts) uses a mean of 1,438 prompts per image. At 8 iterations × 32 prompts (mean 253 prompts), the MAE is 29.10 — worse than TFOC (19.95). The method only becomes competitive at high prompt counts. The paper briefly discusses computational efficiency in the Discussion section but does not quantify this trade-off against competitors.

5. **Key verification threshold (300) is tuned on validation data without sensitivity analysis** — Section 4.1 states "Based on validation experiments, we set the token verification threshold to 300." This threshold controls the binary decision of whether a sampled prompt yields a positive or negative instance, yet its sensitivity is not studied. No ablation shows performance across a range of threshold values (e.g., 100–1000). While tuning on validation data is standard practice, the lack of robustness analysis means a reader cannot tell if results are fragile to this choice.

6. **Selective comparison against weakest training-based method** — Section 4.2 highlights that the method "is superior to the training-based method Counting-DETR's 16.79" while stronger training-based baselines (LOCA 10.79, PseCo 13.05) are not mentioned in this comparison. The full table (Table 1) reports all baselines, so this is a framing issue rather than an omission, but it gives an inflated impression of competitiveness relative to training-based methods on FSC-147.

### Trivial
- The Hadamard product in Eq. (1) between a 64×64×256 tensor and a 64×64×1 tensor requires broadcasting across the channel dimension, which is not stated explicitly.
- The number of exemplars used for FSC-147 few-shot is not stated (only CARPK's 12 is specified).
- The NMS IoU threshold is not reported (the paper says "high IoU values" without a number).

## Nice-to-Haves
- A pseudocode algorithm of the full iterative procedure would aid reproducibility (probability update rule, early stopping integration).
- Analysis of the TS-SS value distribution for positive vs. negative output token pairs (e.g., a histogram) would complement the PCA visualization.
- A failure analysis categorizing which types of FSC-147 images the method performs poorly on, and whether failures are deterministic or stochastic.

## Removed Points

These points were flagged by reviewers but are removed for the following reasons:

2. **"The paper does not report RMSE for CARPK baselines for two entries"** — The dash entries in Table 1 for FamNet and CFOCNet+ NAE/SRE on CARPK are standard practice when those metrics were not reported in the original papers. This is not an omission by the authors.
3. **"The one-shot RMSE is very high (135.86) and not discussed"** — The paper does discuss this (Section 4.2: "Although our RMSE of 135.86 is higher than some training-based methods, the results are promising"). The discussion is brief but not absent.
4. **"Conflict with training-free framing because threshold is tuned on validation data"** — "Training-free" in this literature means no update of model weights, not no hyperparameter tuning. The threshold selection is standard practice. The lack of sensitivity analysis is the real issue (kept as Minor weakness #5).
5. **Criticisms about missing appendix content or proofs** — The parser strips these sections; they exist in the original submission.
6. **Strength Finder claim about "state-of-the-art performance" as a blanket strength** — Retained as a strength but properly scoped: it applies specifically to CARPK (where the claim holds) and is qualified by the exemplar count concern (weakness #3).

## Novel Insights

None beyond the paper's own contributions. The key observation — that SAM's output tokens encode joint semantic-positional information that makes standard similarity metrics suboptimal, and that TS-SS can leverage this dual encoding for counting — is the paper's own contribution, not something the reviews add.

## Suggestions

1. Tone down the abstract and conclusion to match the actual results: "competitive with existing training-free methods" rather than "outperforming existing training-based and training-free counting methods."
2. Report MAE/RMSE variance over at least 5 random seeds for all key configurations. This is the single most impactful addition.
3. Add an ablation for CARPK exemplar count (1, 3, 6, 12) to show how performance varies and whether the comparison against baselines is fair.
4. Add a threshold sensitivity analysis for the TS-SS verification threshold (100–1000).
5. Report the number of exemplars used for FSC-147 few-shot experiments.
6. Add a discussion comparing computational cost (prompts/image, runtime) against competitors to contextualize the accuracy-efficiency trade-off.
