## Summary

TokenCount proposes a training-free object counting framework that combines probabilistic prompt generation with output token-based verification, using only SAM without additional encoders. The key idea is to repurpose SAM's decoder output tokens—which integrate positional and semantic information through bidirectional attention—as the verification criterion for distinguishing positive from negative instances, while using a similarity-derived probability distribution for efficient prompt sampling.

## Strengths

- **Novel use of SAM's output tokens for verification (Section 3.2).** Repurposing SAM's decoder output tokens as the verification criterion is a genuinely novel approach among training-free counting methods. It avoids the similarity-ambiguity problem of prior work and requires no additional encoders, cleanly leveraging SAM's existing architecture. This is the paper's strongest conceptual contribution.

- **Competitive overall results.** The method achieves the best MAE among SAM-only methods on FSC-147 (16.25), outperforms all training-based methods on CARPK (4.68 MAE), and runs at 1.69s per image on FSC-147. The system-level performance demonstrates practical value for a training-free approach.

- **Principled probabilistic prompt generation design.** Using a softmax-normalized similarity map as a multinomial sampling distribution (Eq. 1) with an iterative update rule (positive → set to 0, negative → decreased) is a sensible alternative to fixed grid or superpixel prompting.

- **Systematic ablation studies (Tables 3, 4, 5).** The paper isolates the contributions of the verification metric, iterative sampling configuration, and feature space choice, providing clear evidence for each design decision.

## Weaknesses

### Fatal
None.

### Major
- **Abstract overclaims performance on FSC-147.** The abstract states the method "achieves superior accuracy with an MAE of 16.25, outperforming existing training-based and training-free counting methods." Table 1 directly contradicts this: training-based methods LOCA (10.79), PseCo (13.05), SAFECOUNT (14.32), BMNet+ (14.62) and training-free TFCAC (12.26) all achieve lower MAE. The CARPK claim is accurate, but the FSC-147 claim is a factual misrepresentation of the paper's own results. This must be corrected.

- **Method is underspecified in ways that affect reproducibility.** (a) SAM variant (ViT-B/L/H) is not stated, only "the official SAM." (b) The exemplar input format (point, box, or mask) is never clarified. (c) When multiple exemplar tokens are accumulated, how similarity to multiple tokens is aggregated (max, average, or other) is not specified. (d) Temperature τ from Eq. 1 is defined but its value is not reported; the "t-scale factor of 0.066" in implementation details is ambiguously linked to τ. (e) The maximum iteration limit is mentioned ("we set a maximum iteration limit") but never stated. (f) The TS-SS verification threshold of 300 is reported without any characterization of the TS-SS value range, and no sensitivity analysis is provided. Collectively, these omissions prevent full reproducibility.

- **High RMSE on FSC-147 (133.11) is not discussed.** The RMSE is much worse than training-based methods (LOCA: 56.97, BMNet+: 91.83) and TFCAC (56.33). This implies very large errors on some images. While the paper acknowledges degradation with small instances, it does not address this high-error pattern or its implications for practical deployment.

### Minor
- **Improvements from the two key components are modest.** TS-SS (16.25) improves over cosine similarity (16.48) by 0.23 MAE (Table 3), and output token space (16.25) improves over image embedding space (16.94) by 0.69 MAE (Table 5). No confidence intervals or statistical significance tests are reported, making it unclear whether these differences are meaningful beyond random variation.

- **Non-monotonic performance with more iterations.** For 128 prompts, MAE improves from 18.90 (8 iter) to 16.25 (16 iter) but then worsens to 16.65 (32 iter) in Table 4. This behavior is not explained.

- **CARPK evaluation uses a single random draw of exemplars.** The paper randomly selects 12 training-set objects as exemplars (Section 4.1) but does not report multiple trials. Results could vary substantially depending on which exemplars are chosen.
