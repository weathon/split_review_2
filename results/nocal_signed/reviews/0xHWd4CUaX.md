## Summary

This paper proposes an RL framework for automated code refactoring that uses contrastive pre-training of code graph embeddings, a composite reward function combining traditional metrics, embedding dynamics, and semantic preservation checks via differential testing. The approach is evaluated on three datasets against rule-based, learning-based, and RL-based baselines, with an additional cross-language generalization experiment.

## Strengths

- **Meaningful ablation study (Table 2).** The component-level analysis shows large, interpretable deltas: removing contrastive pre-training drops SI by 7.5 points, removing semantic tests drops SP by 8.6 points. These are the strongest piece of evidence in the paper and confirm each major component contributes positively.

- **Sensible high-level architecture.** The three-phase design — contrastive pre-training of graph-code embeddings, then RL fine-tuning with a composite reward — is a natural way to combine self-supervised representation learning with policy optimization for code refactoring.

- **Useful embedding-quality sanity check.** The correlation (Pearson's r=0.72, Figure 2) between embedding-space movement and observed syntactic improvement provides some evidence that the learned representations are not completely disconnected from code quality.

## Weaknesses

### Fatal

None.

### Major

- **No variance reporting on any experimental result.** Tables 1, 2, and 3 all report single numbers with no error bars, standard deviations, confidence intervals, or any mention of how many random seeds or runs were averaged. RL policy gradient methods are known to be high-variance. Without this information, the reader cannot assess whether the claimed improvements (e.g., 83.7% vs 79.4% SI) are statistically meaningful or due to noise. This is the most serious evidential gap in the paper. *Impact: -9.7/10*

- **Cross-language generalization experiment compares against mismatched baselines (Table 3).** The model, trained on Java, is tested on Python (vs. PyLint) and C++ (vs. Cppcheck) — both rule-based linters rather than learning-based refactoring systems. On SP, PyLint (90.4%) and Cppcheck (93.1%) actually outperform the proposed method (88.9%, 91.2%). No RL-based baselines (GraphRL, NeuroRefactor) are adapted to Python/C++, so this experiment does not inform cross-language generalization relative to competitive alternatives. *Impact: -8.7/10*

- **The embedding dynamics reward term is conceptually questionable.** The term *α* tanh(*β* ‖**h**_t − **h**_t−1‖₂) in Eq. (5) is always non-negative for any action that changes the code, because any modification to the code graph will shift the embedding. There is no principled reason why larger latent-space movement should correspond to better refactoring — this term could reward unnecessary or destabilizing changes. The post-hoc correlation (r=0.72, Figure 2) only shows that better refactorings involve larger changes; it does not validate the term as a *training signal*. The ablation study removes "embedding rewards" as a bundle without isolating this specific term. *Impact: -8.6/10*

- **The paper's central claim is contradicted by its own design.** The paper repeatedly states it overcomes "handcrafted," "heuristic-based reward functions," but the composite reward (Eq. 5) uses manually-set weights: **w**_q = [0.4, 0.3, 0.3], *α* = 0.2, *β* = 1.0, *γ* = 0.5. No sensitivity analysis or justification for these values is provided, and no evidence that the method is robust to them. The claimed advantage is therefore overstated. *Impact: -8.8/10*

### Minor

- **Edit Distance (ED) framed as "lower is better" is not justified.** A larger Levenshtein distance could indicate more thorough refactoring, so it is not obvious why minimal distance to the original code is desirable. *Impact: -0.8/10*

- **No quantification of pre-training cost or test case generation scale.** The paper acknowledges pre-training cost as a limitation but provides no GPU-hours or wall-clock time. The number of test cases generated by symbolic execution (Section 4.5) is also not reported. *Impact: -1.0/10*

- **Several important limitations not discussed.** These include sensitivity to manually-set reward weights, reliance on available test cases for semantic verification, and reliance on graph construction quality. *Impact: -2.2 to -1.0/10*

## Nice-to-Haves

- Perform a sensitivity analysis on the reward weights (**w**_q, *α*, *β*, *γ*) to establish robustness.
- Adapt the same learning-based baselines (GraphRL, NeuroRefactor) to Python/C++ for a meaningful cross-language comparison.
- Replace or better justify the embedding dynamics reward term; an ablation replacing it with a constant would clarify whether it provides genuine signal.

## Suggestions

1. **Report all results with variance across multiple random seeds (at least 5).** This is the single highest-impact improvement and is standard practice for RL papers.
2. **Redesign the cross-language experiment** to compare against the same class of methods (learning-based refactoring systems) adapted to target languages.
3. **Provide a principled justification for the embedding dynamics reward** or redesign it. Ablate this term in isolation.
4. **Add a sensitivity analysis** for the manually-set reward weights to assess robustness.
5. **Quantify pre-training resource costs** (GPU-hours, wall-clock time) and report the scale of symbolic-execution test generation.

## Score and Decision

The paper presents a reasonable high-level idea, but the evaluation has fundamental evidential gaps. The complete absence of variance reporting in a high-variance RL setting means the central comparative claims cannot be assessed. The cross-language experiment uses inappropriate baselines, the embedding dynamics term lacks principled justification, and the central claim of replacing handcrafted rewards is overstated by the paper's own design. While the ablation study provides some useful evidence, these issues collectively prevent the paper from reliably establishing its claimed contributions.
