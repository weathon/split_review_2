## Summary

This paper evaluates nine open-source LLMs (12-16B parameters) on two reverse engineering tasks — name recovery and type inference — using a dataset of 40,000 functions from GNU projects compiled across four architectures (x86-64, x86-32, ARM, MIPS) at four optimization levels. The authors build an automated evaluation pipeline and measure both zero-shot and fine-tuned (LoRA, 200 steps) performance. The core finding is that current LLMs achieve very low F1 scores (mostly below 0.10) without fine-tuning, and fine-tuning yields inconsistent and generally modest gains.

## Strengths

- **Broad multi-model, multi-architecture benchmark**: Evaluates nine distinct LLMs across four CPU architectures and four optimization levels with 40K deduplicated functions. This is one of the most comprehensive evaluations in the binary reverse engineering setting, providing a useful empirical map of current capabilities.

- **Controlled within-family evidence that larger size does not predict performance**: Figure 2 compares CodeLlama 7B, 13B, and 34B on all three tasks, showing nearly identical F1 scores across sizes. Because this comparison controls for architecture and training data, it is clean evidence (Finding 6) that scaling model size alone does not automatically improve reverse engineering performance.

- **CodeWordNet ablation validates the need for semantic matching**: Figure 1 demonstrates that removing CodeWordNet drops F1 scores by ~50-70%, confirming that strict string matching would unfairly penalize semantically valid predictions. This is a concrete, well-designed control experiment that supports the paper's evaluation choices.

- **Documents inconsistent fine-tuning effects across models**: Tables 2-4 show substantial gains (WizardCoder 0.01→0.33 on variable name recovery at O0) alongside performance decreases (DeepSeek-V2 0.10→0.05 at O1), providing a nuanced picture that goes beyond "fine-tuning helps."

- **Practical insight on prompt templates and training time**: Table 7 shows >3× variation in fine-tuning time across models, and a controlled probe on CodeLlama traces this to prompt template structure (Finding 7). This is a reproducible, non-obvious finding with practical value.

## Weaknesses

### Fatal
None.

### Major

- **Name recovery F1 metric is underspecified**: The paper states it uses the SYMLM method with CodeWordNet to compute semantic distances and "partial scores" (Section 3.4), but never explains how these per-sub-word similarity scores are converted into standard precision, recall, and F1. Standard F1 is defined over binary correct/incorrect classifications; without the mapping from continuous sub-word distances to binary decisions (or the thresholding scheme), the reported F1 values are uninterpretable and non-reproducible. Many entries are near 0.00, but the reader cannot determine whether this reflects genuine model failure or properties of the scoring regime. **This directly affects the paper's headline numerical results.**

- **Auxiliary LLM post-processing pipeline is unvalidated**: The evaluation relies on an unnamed auxiliary LLM to normalize heterogeneous model outputs into structured form (Section 3.2). The paper provides no accuracy assessment, error rate, failure examples, or identification of which model is used. Because Finding 8 confirms that target LLMs frequently fail format instructions, the post-processing step is a critical uncontrolled variable — if it misformats or alters predictions, the evaluation measures pipeline errors rather than target LLM performance. Without validation, the reliability of all downstream metrics is in question.

- **Fine-tuning experiments are likely under-trained**: Each model is fine-tuned for only 200 steps (Table 7) on a 160K-sample training set using LoRA. The paper provides no learning curves, no evidence of convergence, no validation loss monitoring, and no plateau-based stopping criterion. The "modest gains" and occasional performance drops (DeepSeek-V2: 0.10→0.05 at O1) are exactly what one expects from severe under-training, not evidence of fundamental fine-tuning limitations. The conclusion that fine-tuning has "limited impact" (Finding 2) is unsupported without convergence guarantees.

- **No statistical rigor**: Results are reported to three decimal places without confidence intervals, significance tests, variance estimates, or multiple-run statistics (Tables 2-6). Many scores are near zero and differences between models are as small as 0.01-0.02. Without error bars, it is impossible to distinguish signal from noise in any comparative claim (e.g., which model is "best" at a given task).

### Minor

- **Ground truth provenance is not described**: The paper describes building a dataset from GNU projects (Section 4.1) but does not explain how ground-truth names and types were obtained or verified (e.g., from debug symbols, DWARF info, or source-to-binary mapping). Decompilation can introduce artifacts, and this information is important for assessing label quality.

- **No systematic error analysis**: Table 8 shows four cherry-picked success cases for Qwen2.5. The paper provides no quantitative breakdown of failure modes (format errors vs. partial semantic matches vs. completely wrong predictions) across the full 40K sample set, which would be critical for understanding the near-zero F1 scores and guiding future work.

- **Type inference uses only strict equality**: The paper acknowledges this limitation (Finding 2), and it is a defensible design choice. However, many prior works use relaxed matching for user-defined types, and the strict criterion may deflate scores relative to what practitioners would consider reasonable performance.
