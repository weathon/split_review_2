## Summary

Critique-RL proposes a two-stage online RL approach for training language models to critique model outputs without requiring stronger supervisors or oracle verifiers at test time. The key insight is that using only indirect reward signals (based on the actor's refinement correctness) causes the critique model's discriminability (judging whether a response is correct) to collapse into conservative or aggressive failure modes. Critique-RL addresses this by first optimizing discriminability with direct rule-based rewards (Stage I), then optimizing helpfulness while preserving discriminability via regularization (Stage II). Experiments on Qwen2.5 models across math reasoning tasks show consistent gains, with ablations confirming the necessity of both stages.

## Strengths

1. **Well-diagnosed problem with compelling evidence**: The paper identifies and visualizes a concrete failure mode via training dynamics (Figure 3) — indirect RL rewards cause critique models to become either conservatively inert or aggressively harmful on one dimension of discriminability. This diagnostic analysis is clear, internally valid (all baselines use the same RL algorithm in this preliminary study), and convincingly motivates the two-stage design.

2. **Strong ablation isolating the core contribution**: Table 3 ablates components while holding the RL algorithm (RLOO) fixed. Removing Stage I, Stage II, or the discrimination regularization all cause measurable drops (e.g., MATH Acc@Refine: 48.6 → 47.6, 45.9, 47.3). This is the cleanest evidence for the two-stage design and directly supports the paper's central claim.

3. **Consistent empirical gains across settings**: Critique-RL achieves notable improvements over all baselines on 3B and 7B models across MATH, GSM8K, AQuA (in-domain), SVAMP, and TheoremQA (out-of-domain). The method also benefits from iterative training (Table 2: second iteration improves Acc from 48.6 to 51.0) and improves test-time compute scaling (Figure 1).

4. **No stronger supervisor required**: SFT data is generated by Qwen2.5-3B-Instruct (same scale as the trained model), and RL training uses only rule-based correctness verifiers — not labeled critique data from GPT-4 or similar. This makes the approach practical for scalable oversight.

## Weaknesses

### Fatal
None.

### Major
1. **Confounded comparison against prior RL methods**: Retroformer uses PPO and CTRL uses GRPO, while Critique-RL uses RLOO. The reported gains (e.g., 58.40 vs 53.86 on MATH for 7B) cannot be cleanly attributed to the two-stage reward design because they could partly reflect algorithmic differences in RL stability or sample efficiency. The paper acknowledges these differences but does not control for them. The ablation study (Table 3) is internally valid since it uses RLOO throughout, but the main results table (Table 1) against Retroformer and CTRL remains confounded. This weakens the headline claim that "Critique-RL outperforms prior RL-based methods" — a fair comparison would require reimplementing baselines with the same base RL algorithm (RLOO), varying only the reward.

### Minor
