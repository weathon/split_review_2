## Summary

TokenCount proposes a training-free framework for class-agnostic object counting that repurposes SAM's decoder output tokens for instance verification. The method combines probabilistic prompt generation (sampling from a similarity-based probability distribution in SAM's image embedding space) with output token-based verification using the TS-SS geometric similarity metric. The key insight is that SAM's output tokens encode both semantic and positional information through their attention mechanism, and can be used to distinguish positive from negative instances without additional models or fine-tuning.

## Strengths

- **Novel core idea — repurposing SAM's output tokens for verification.** Prior training-free SAM-based counting work (TFOC, C-Anything, TFCAC) relies on similarity in the image embedding space or requires additional models (DINO). The observation that output tokens encode semantic and positional information through bidirectional attention (Section 3.2), and can be used for verification without modifying SAM's architecture, is a non-obvious and genuinely interesting insight. The PCA visualization (Figure 5) provides qualitative support.

- **The CARPK result is genuinely strong.** An MAE of 4.68 outperforms all training-based methods (best: SAFECOUNT at 5.33) and all training-free SAM-only methods (best: TFOC at 10.97). This is a clean, unambiguous result on a standard benchmark.

- **Training-free and auxiliary-model-free.** The method uses only SAM with no fine-tuning and no additional encoders (unlike TFCAC which adds DINO, or OmniCount/TFCounter which use additional foundation models). For deployment scenarios where model footprint and licensing matter, this is a concrete practical advantage.

## Weaknesses

### Major

1. **Abstract claims are not supported by the paper's own data (Table 1).** The abstract states: *"Experimental results show our method achieves superior accuracy with an MAE of 16.25, outperforming existing training-based and training-free counting methods."* This is contradicted by Table 1: Ours (16.25) is worse than TFCAC (12.26, training-free), LOCA (10.79), PseCo (13.05), SAFECOUNT (14.32), and BMNet+ (14.62). The method ranks 7th of 14 on FSC-147 MAE. The abstract also says the method achieves *"comparable performance to training-free approaches that require additional models"* — TFCAC achieves 12.26 vs 16.25, a 32% relative gap. While Section 4.2 correctly frames the result as *"best among training-free SAM-only methods,"* the abstract's unqualified claim is at odds with the evidence. This is the most significant weakness because it inflates the paper's central selling point.

2. **Very high RMSE on FSC-147 indicates instability.** Ours achieves RMSE **133.11** on FSC-147 — second worst in Table 1 (only SAM alone at 137.50 is worse). Compare to TFCAC (56.33), LOCA (56.97), BMNet+ (91.83), PseCo (112.86). The one-shot results (Table 2) show the same pattern: MAE 18.57 vs RMSE 135.86. An RMSE this high relative to MAE implies the method sometimes produces dramatically wrong counts. The paper only mentions this in passing (Section 5: *"performance degradation in scenarios with dense distributions of very small instances"*) without analyzing or quantifying these failures. For a counting method, this is a serious practical limitation.

3. **No variance or statistical significance reported despite stochastic sampling.** The prompt generation samples from a multinomial distribution (Section 3.1), making results stochastic between runs. Yet all metrics are single numbers with no standard deviation, confidence intervals, or number of trials. The key comparisons — TS-SS (16.25) vs. cosine similarity (16.48, Table 3, a ~1.4% gap) and output token space (16.25) vs. image embedding space (16.94, Table 5, a ~4% gap) — lack error bars. Without them, these claimed advantages could be within the noise of the stochastic procedure.

4. **Unsubstantiated efficiency claims.** The paper claims the method is *"more than twice as fast"* as TFCAC (Section 4.2) and frames the method as addressing computational inefficiency of prior work (§1). However, only the method's own runtime (1.69s/image on FSC-147) is reported; no runtime data for TFCAC or any other baseline is provided. The efficiency advantage is asserted but unverifiable.

5. **CARPK evaluation uses 12 exemplars without establishing fair comparison.** The paper states: *"For CARPK, following the testing procedure, we randomly selected 12 objects from the training set to use as exemplars."* Twelve exemplars is far more than the standard 3 exemplars used for FSC-147 few-shot evaluation. The paper does not state how many exemplars the compared baselines (BMNet+, SAFECOUNT, LOCA) use on CARPK, making it unclear whether the reported advantage reflects method quality or a more generous evaluation setup.

### Minor

6. **The verification threshold (300) is not justified or analyzed.** The paper states *"Based on validation experiments, we set the token verification threshold to 300"* but provides no sensitivity analysis. The TS-SS metric produces a product whose magnitude is hard to interpret (Eq. 2-3), making the threshold opaque. A sweep over a range of thresholds would demonstrate robustness or reveal sensitivity.

7. **Internal inconsistency between motivation and method design.** The paper criticizes prior work for using similarity in the image embedding space (§1: *"the ambiguity of the similarity itself introduced significant uncertainty"*), yet the probabilistic prompt generation (Section 3.1, Eq. 1) relies on cosine similarity in the exact same image embedding space to construct its probability distribution. The paper never reconciles this tension. (A plausible resolution — that prompt generation only needs approximate localization while verification needs precision — is never stated.)

8. **Missing implementation details weaken reproducibility.** (a) How the exemplar mask is obtained is not explicitly stated (it implies running SAM's decoder but does not confirm this). (b) The "nonzero" operation in Eq. 1 operates on resized mask values that are continuous probabilities — the threshold for "nonzero" is not defined. (c) The temperature parameter τ = 0.066 is given without explanation of how it was selected. (d) No validation split is described despite reference to "validation experiments" for threshold selection.

9. **Ablation missing the prior-art baseline.** The ablations compare output token space vs. image embedding space (Table 5) and TS-SS vs. simpler metrics (Table 3), but there is no baseline combining "grid prompting + image embedding similarity" — which represents the prior art (effectively TFOC or C-Anything). Without this, the paper cannot fully attribute improvement to the combination of both proposed components vs. each individually.
