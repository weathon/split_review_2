## Summary

This paper introduces BIRD-INTERACT, a benchmark for evaluating text-to-SQL systems through dynamic, multi-turn interactions. Built on LIVESQLBENCH, it contributes (1) a function-driven user simulator that avoids ground-truth leakage common in prior LLM-based simulators, (2) two evaluation settings (protocol-guided *c*-Interact and agentic *a*-Interact) with budget-constrained awareness, and (3) a 600-task suite covering the full CRUD spectrum with state-dependent follow-up sub-tasks. Experiments on 7 frontier LLMs show success rates of only 8–29%, demonstrating a significant gap between SQL generation capability and the interaction skills required for realistic text-to-SQL use.

## Strengths

- **Well-motivated and clearly identified gap.** The paper correctly identifies two real limitations of existing multi-turn text-to-SQL benchmarks — static conversation transcripts (every model sees the same dialogue history regardless of its own interaction strategy) and restriction to SELECT-only queries. This framing is accurate and consequential.
- **Carefully engineered function-driven user simulator with demonstrated improvements.** The two-stage approach (mapping model questions to AMB/LOC/UNA actions before generating responses) directly addresses ground-truth leakage in prior LLM-based simulators. The USERSIM-GUARD evaluation (Section 6, Figure 6) is compelling: baseline simulators fail on UNA questions up to 67.4% while the proposed approach reduces this to 2.7%.
- **Dual evaluation settings with thoughtful budget constraints.** The *c*-Interact (protocol-guided) and *a*-Interact (agentic) settings capture different modes of real-world interaction, and the budget mechanism scaling with ambiguity count and user patience is more principled than a flat turn limit. The finding that GPT-5 is worst in *c*-Interact but best in *a*-Interact (Table 2) is a non-obvious result that a good benchmark should surface.
- **Coverage of the CRUD spectrum.** Expanding beyond SELECT-only into DML/DDL operations (INSERT, UPDATE, DELETE) with state-dependent follow-up sub-tasks adds a dimension of realism absent from prior work like Spider, COSQL, and the original BIRD benchmark.

## Weaknesses

### Fatal
None.

### Major

- **Test case verification for state-modifying queries is not described.** For SELECT queries, test cases typically compare result sets. For INSERT/UPDATE/DELETE, the test must verify database state changes (e.g., that a row was inserted with correct values, or that a deletion cascaded correctly). The paper mentions "executable test cases that verify functional correctness" and "fresh PostgreSQL 14 Docker instances" but never explains how correctness is determined for DML/DDL operations. This is a meaningful gap in the evaluation infrastructure description for a benchmark that prominently features CRUD coverage. (Weight: 2.71)

- **The memory grafting experiment (Section 5.2, Figure 5) is under-specified and does not cleanly test its stated hypothesis.** (1) The "without memory grafting" rate for GPT-5 in Figure 5 (13.8%) does not match the *c*-Interact priority SR in Table 2 (14.50%); the paper does not state what task subset the grafting experiment uses or explain this discrepancy. (2) The paper says GPT-5 receives "ambiguity resolution histories from two other better models" but does not specify whether these histories include the correct SQL queries generated by those models — if they do, the experiment conflates communication ability with SQL generation ability. (3) The comparison is structurally asymmetric: Qwen-3-Coder achieves 18.5% through its own interaction trajectory, while GPT-5 gets Qwen's interaction history *plus* its own SQL generation. Showing that A's history + B's SQL beats A alone does not cleanly isolate communication ability. (Weight: 0.03)

### Minor

- **The "ITS Law" framing overgeneralizes the evidence.** The claim that "a model satisfies this law if, given enough interactive turns, its performance can match or even surpass that of the idealized single-turn task" is supported by only one model (Claude-3.7-Sonnet) in Figure 4 — other models (O3-Mini, GPT-4o, Qwen-3) show much flatter or declining trajectories. A single positive example does not constitute a law. (Weight: 4.33)

- **The idealized single-turn performance baseline is shown in Figure 4 for the LITE set but is not included in the main results Table 2 for the FULL set.** Without this baseline in the primary results table, readers cannot separate whether the low success rates (8–29%) reflect inherent SQL task difficulty or the added difficulty of the interaction framework. (Weight: 4.65)

- **No confidence intervals or variance estimates are reported** for any success rate in Table 2 (single runs, acknowledged due to cost). While this is common in costly LLM evaluations, some rankings involve very small margins — e.g., Claude-Sonnet-3.7 at 18.00% vs. Deepseek-Chat-V3.1 at 18.50% in *c*-Interact priority — and the human correlation study (Table 3) reports Pearson r based on 7 data points, where confidence intervals are necessarily wide. (Weight: 5.20)

- **The budget formula coefficients** (B_base=6, +2 multiplier on m_amb and λ_pat) are stated without justification or sensitivity analysis. (Weight: 4.37)

- **The inter-annotator agreement of 93.33–93.50% (Table 1) is reported without specifying what it measures** — ambiguity classification, SQL correctness, or something else. (Weight: 2.68)
