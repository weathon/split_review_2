## Summary

This paper proposes a framework for integrating differentiable approximations of formal verification constraints into the reinforcement learning loop for code synthesis. The method uses a learned surrogate that mimics verification outcomes (type safety, memory safety, termination) as a continuous reward signal, enabling gradient-based policy optimization. Experiments on a set of programming benchmarks report improved verification success rates and efficiency compared to post-hoc verification baselines.

## Strengths

- **Well-motivated problem framing.** The paper correctly identifies the tension between discrete formal verification and continuous neural policy optimization, and makes a coherent case for why post-hoc verification or black-box reward shaping are suboptimal compared to integrating verification signals into the training loop (Section 1).
- **Clear high-level architecture design.** Figure 1 provides an effective overview of the pipeline from input processing through hierarchical policy, differentiable verification, and reward computation.

## Weaknesses

### Major

1. **Figure 2 reports proportions exceeding 100% in a stacked area chart (lines 280–290).** The table adds Memory Safety (94%) and Termination Guarantees (97%) to a "Total" of 191%, and the y-axis extends to 175. These are overlapping properties — the same program can satisfy both — so they cannot be stacked or summed. This is a basic data presentation error that undermines confidence in the paper's quantitative reporting. While the individual percentages may be plausible, presenting them as a stacked total is misleading.

2. **The Verification Success Rate (VSR) metric is critically underspecified (line 244).** VSR is defined as "Percentage of generated programs satisfying all safety properties," but the paper never states whether this is measured by the exact SMT solver V or the differentiable surrogate \tilde{V}. If measured by \tilde{V}, the metric is circular — the method is evaluated on its own approximation, and comparisons to baselines that use exact verification are invalid. If measured by V, the paper must state this explicitly and clarify the evaluation protocol. Without this clarification, the headline results in Tables 1 and 2 cannot be properly interpreted.

3. **The paper's framing conflates learned approximations with formal guarantees.** The method uses a sigmoidal surrogate \tilde{V} (Equations 2, 5) that outputs continuous scores approximating verification outcomes — it is a learned classifier, not a verifier. Yet the paper uses language like "provably safe code synthesis" (line 207), "provable safety guarantees" (line 377), and frames the contribution as enabling "verifiable" code synthesis. The comparison to post-hoc SMT verification (which provides actual proofs) at 5x lower verification time (85ms vs 420ms) is misleading because the products are not equivalent. The paper should reframe honestly: the method provides learned differentiable approximations of verification as reward signals, not formal verification.

### Minor

4. **No statistical significance is reported.** Tables 1 and 2 show single numbers per condition without standard deviations or confidence intervals across random seeds. Given the stochasticity of RL training, this makes it impossible to assess whether reported differences are meaningful.

5. **The gradient update rule (Equation 7) is not fully explained.** The term λ∇_θ \tilde{V}(P, φ) proposes a direct gradient of the verification surrogate with respect to policy parameters, but P is generated by discrete token sampling from π_θ. The paper does not clarify how gradients flow through the discrete sampling step to reach θ. This needs explicit justification.

6. **Training data for the verification surrogate is never specified.** The paper does not state how many programs are used to train \tilde{V}_w via Equation 8, how they are sampled, or whether the surrogate is chasing a moving target during policy training.
