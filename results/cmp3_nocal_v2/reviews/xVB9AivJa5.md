## Summary

Blueprint-Bench introduces a new evaluation benchmark that tests spatial reasoning by tasking AI models with converting apartment photographs into 2D floor plans following strict formatting rules. The benchmark is model-agnostic (LLMs via SVG, image generation models, and agent scaffolds), enabling cross-architecture comparisons on a capability — spatial reconstruction — that is not explicitly trained for. On a dataset of 50 apartments, all tested models score poorly (0.15–0.42 on a 0–1 scale), most at or near a no-visual-information baseline, while a single human subject scores 0.547 on a 12-apartment subset.

## Strengths

- **Novel, well-motivated task design.** Using real apartment photographs (in-distribution for multimodal models) to test spatial reconstruction — a capability not explicitly trained for — is a clever stress test for general intelligence, distinct from abstract out-of-distribution benchmarks like ARC. The connection to evaluating emerging image generation models (GPT-Image, Nano Banana) addresses a real gap in the evaluation ecosystem.

- **Model-agnostic framework across architectures.** The benchmark accepts outputs as SVG code (LLMs), direct images (image generation models), or files from agent environments (Docker), enabling comparisons that most benchmarks cannot support — notably comparing an image generation model against the underlying LLM it derives from.

- **Thoughtful agent comparison.** Testing iterative-refinement agents (Codex CLI, Claude Code) alongside single-pass models allows the paper to test whether the generation paradigm is the bottleneck. The negative result (agents show no meaningful improvement) is the right question to ask even if the answer is null.

- **Acknowledges key limitations.** Section 2.4 surfaces several real issues: size-ranking errors cascade into connectivity penalties, room shape is not evaluated, and instruction-following confounds the spatial intelligence measurement. The authors at least name these constraints rather than ignoring them.

## Weaknesses

### Major

1. **Room-identity assignment by size rank conflates spatial understanding with size estimation.** The scoring algorithm assigns room IDs by size ranking (largest room = ID 1, etc.). When a model correctly captures the connectivity structure but slightly misorders rooms 2 and 3 by estimated size, every connectivity comparison compares wrong rooms. The composite score (50% edge overlap, 20% degree correlation) cannot separate "understands layout but gets sizes slightly wrong" from "does not understand layout." The paper acknowledges this in Section 2.4 ("the penalty of making a mistake in the size ranking causes additional penalties when scoring the connectivity") but uses the entangled metric for all headline claims. The fix — reporting connectivity and size accuracy as separate sub-scores with room correspondence resolved by a matching algorithm rather than fixed rank ordering — is feasible but would change the reported results. This matters because the paper's core finding is about spatial intelligence, yet the metric cannot isolate it.

2. **The "random baseline" is misleadingly labeled and its interpretation is ambiguous.** Section 2.2 describes it as a "worst-case baseline" generated by the same model families *without any image input*. This is not a random process; it is a "no-visual-information" baseline that draws on each model's training priors about typical floor plan structure. The paper repeatedly calls it a "random baseline" (abstract, Section 3, Figures 5 and 7) and frames results as "most models perform at or below random." But a model that understands nothing about the specific apartment could still score above this threshold by leveraging its training priors, making the comparison partially circular. Additionally, the baseline values differ across Figures 5 (0.279) and 7 (0.322) — this is because they are computed on different subsets (50 vs. 12 apartments), which is never stated explicitly. The conclusion that models lack spatial intelligence may be correct, but the baseline against which this is measured is not what its label suggests.

3. **The benchmark partially measures instruction-following, not purely spatial intelligence.** The paper's own data illustrates this: GPT-4o scores 0.15 and Nano Banana scores 0.18, which the paper attributes to "poor instruction following" (Section 3). GPT Image scores 0.32 and the paper notes it "consistently outputs floor plans mostly according to the rules" but shows poor spatial reasoning. The 9 formatting rules (3px walls, 10×10px red dots, no door swings, etc.) are a specialized output format that models may fail to produce correctly even if they understand the layout. The paper acknowledges this in Section 2.4 ("Blueprint-Bench should test spatial intelligence, not instruction following") and calls it the "right tradeoff." However, the composite score remains an un-decomposed mixture of spatial intelligence and format compliance. A model that understands the apartment perfectly but outputs green walls instead of black walls scores 0. For models that are worst at instruction-following, the benchmark reveals little about their spatial reasoning.

### Minor

4. **Model categorization and naming inconsistencies.** The table in Section 3 lists Claude Code (Opus 4.1) as "Image model," yet Section 2.2 explicitly describes Claude Code as one of "two different agent scaffolds." The text refers to "Codex GPT-5 agent" but the Figure 5 table lists "CodeX (GPT-6)" and Figure 7 lists "Codex (GPT-5)" — two different version numbers. Grok 4 and GPT-5 are listed as "Image model" in the table, but the abstract categorizes both as LLMs. While these inconsistencies do not change the numerical results, they undermine confidence in the reported data and suggest carelessness in presentation.

5. **Human baseline is too weak for quantitative comparison.** Human performance is based on a single subject (Section 3: "the human") and measured on only 12 of the 50 apartments (Figure 7 caption). N=1 cannot support quantitative conclusions about "human-level performance." The claim that "human performance remains substantially superior" (abstract) is qualitatively plausible but statistically unsupported by the evidence presented.

6. **"Epochs" is never defined.** The results text states "across apartments and epochs" (Section 3), with the same phrasing in figure captions. The term "epochs" — presumably referring to multiple generations per model per apartment — is never explained. This is a missing methodological detail that affects reproducibility.

### Trivial

- None beyond the presentation issues already listed.

## Nice-to-Haves

- **Report decomposed sub-scores.** Separating connectivity accuracy (via a matching algorithm robust to room ordering) from size-ranking accuracy would let the paper show *why* each model fails, strengthening the spatial-intelligence claim.
- **Validate the extraction pipeline.** The flood-fill parsing algorithm (detecting red dots, segmenting rooms, identifying doors) is never quantitatively validated (precision/recall on held-out annotated samples). Errors in extraction propagate into scoring.
- **Add dataset diversity information.** Fifty apartments is a reasonable size, but nothing is reported about architectural style, geographic origin, or room-count distribution, which affects generalizability.
- **Provide statistical significance tests.** The paper mentions "statistically perform better" but gives no p-values, confidence intervals, or test names. With N=50 apartments, some observed differences may not be significant.

## Novel Insights

None beyond the paper's own contributions. The harsh review's structural critique of the entangled scoring metric is the most novel analytical insight — it identifies that the benchmark's central measurement conflates spatial understanding with size estimation in a way the authors acknowledge but do not resolve. This is a methodological observation about the paper rather than a new finding about the subject matter.

## Suggestions

1. **Disentangle the scoring metric.** Replace fixed room-ID assignment by size rank with a bipartite-matching algorithm that finds the optimal room correspondence between predicted and ground-truth graphs. Report a connectivity-only sub-score and a size-ranking sub-score separately. This directly addresses the most significant methodological concern.
2. **Replace the "random" baseline with two clearly defined baselines:** (a) a genuinely random connectivity graph (same room count, random edges) and (b) the current no-visual-input model baseline, reported side by side. State the baseline value for each figure and explain why it differs.
3. **Fix the model categorization table** to accurately reflect whether each entry is an LLM, image generation model, or agent, and ensure consistent naming (Codex/CodeX and GPT-5/GPT-6) throughout.
