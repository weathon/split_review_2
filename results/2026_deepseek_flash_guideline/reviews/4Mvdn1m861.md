## Summary
TokenCount proposes a training-free object counting framework built on SAM. It uses two components working in synergy: (1) a **probabilistic prompt generation** stage that uses cosine similarity of SAM's image embeddings to propose candidate locations via multinomial sampling, and (2) an **output-token-based verification** stage that uses SAM's decoder output tokens with a TS-SS (Triangle Similarity-Sector Similarity) metric to distinguish positive from negative instances. The method achieves competitive MAE on FSC-147 (16.25, best among SAM-only training-free methods) and strong results on CARPK (4.68 MAE, beating all listed supervised methods).

## Strengths
1. **Novel use of SAM output tokens for verification**: Unlike prior training-free methods (TFOC, C-Anything) that rely on image-embedding cosine similarity for instance identification, TokenCount directly leverages SAM's decoder output tokens. Table 5 provides direct controlled evidence: the same pipeline using output token space (MAE 16.25) outperforms image embedding space (MAE 16.94). Figure 5's PCA visualization shows qualitatively better positive/negative separation in output token space.

2. **CARPK performance exceeding all supervised methods**: The method achieves MAE 4.68 and RMSE 6.13 on CARPK, surpassing every listed training-based method including SAFECOUNT (5.33/7.04) and BMNet+ (5.76/7.83). This is a noteworthy result since CARPK tests precise localization rather than density estimation.

3. **Systematic ablation of probabilistic prompt generation**: Table 4 demonstrates monotonic improvement as prompts per iteration increase (MAE drops from 29.10→18.90→16.25 for 32→64→128 prompts at 16 iterations), confirming that the verification stage correctly identifies additional objects and that the iterative exploration strategy works as designed.

4. **Clean early-stopping mechanism**: The IoU-based convergence criterion (IoU > 0.95 for 5 consecutive rounds, §4.4) is a practical engineering contribution that adapts computational cost to image difficulty.

## Weaknesses

### Major
None.

### Minor

1. **No variance reporting for a stochastic method**: The prompt generation samples from a multinomial distribution over a 64×64 grid (§3.1, line 134). Different random seeds place prompts at different locations, producing different output tokens and different final counts. The paper reports only point estimates for all metrics with no measure of dispersion. Since key ablation differences are small (TS-SS 16.25 vs. cosine 16.48 — a 1.4% gap), the reader cannot assess whether these differences are meaningful relative to the method's inherent stochasticity. Running 5–10 trials and reporting mean ± std would resolve this.

2. **Selective emphasis on MAE while RMSE is worst among comparable methods**: On FSC-147, the method's RMSE (133.11) is marginally worse than every other SAM-only training-free method (TFOC: 132.16, C-Anything: 131.24) and dramatically worse than methods using additional encoders (TFCAC: 56.33). The data is in Table 1, but the paper never acknowledges or discusses this RMSE pattern. Since RMSE is more sensitive to large errors, this suggests heavy-tailed failures that merit analysis. A characterization of error distribution or per-category breakdown would clarify whether the RMSE issue is structural or incidental.

3. **Efficiency claims asserted without baseline timing**: The paper claims "more than twice as fast" as TFCAC (line 230) and "superior computational efficiency" (line 305). It reports its own timing (1.69s per image on A100) but provides no timing measurements for any baseline. With ~1438 prompts per image (Table 4), each requiring a SAM decoder forward pass, the computational cost is non-trivial and the claimed advantage is unverifiable without comparable measurements.

4. **Abstract overclaims relative to full paper**: The abstract states the method "outperforms existing training-based and training-free counting methods." However, TFCAC (training-free, SAM+DINO) achieves MAE 12.26 on FSC-147 vs. 16.25 — a meaningful gap. The paper acknowledges this in Section 4.2 with appropriate qualification, but the abstract's unqualified phrasing is misleading.

5. **TS-SS threshold (300) unexplained**: The TS-SS is the product of two unnormalized positive terms (Eq. 2–3), so its range depends on output token vector magnitudes. The threshold of 300 (line 180) is a critical hyperparameter, but no sensitivity analysis or validation procedure is reported. This is especially important because TS-SS is a non-standard metric borrowed from document clustering.

6. **Probability update rule unspecified**: For negative verifications, the paper states the probability "is decreased" (line 148) without specifying the decrease amount (constant factor? learned decay? proportional decrease?). This detail is needed for reproducibility.

## Removed Points
- **Criticism about "similarity metric tension"**: The harsh critic claimed the paper's prompt generation relies on the same image-embedding similarity it criticizes. This conflates two different stages. The paper criticizes using image-embedding similarity *for verification/criterion* (the final decision about what is a positive instance). Prompt generation uses similarity only to *propose candidate locations* — a lower-stakes task where imperfect recall is tolerable because proposals are subsequently verified by output tokens. This is a sound two-stage proposal→verification design. No tension exists.
- **Criticism that RMSE is "concealed"**: The data is fully visible in Table 1. The paper emphasizes MAE (selective but not concealed). Retained as a minor weakness about selective emphasis rather than concealment.
- **Generic concerns about missing code release**: Not a substantive evaluation criterion for the paper's content per the filtering rules.
