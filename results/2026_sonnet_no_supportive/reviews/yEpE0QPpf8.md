Now I have enough to write the draft review.## Summary
Grounding-IQA introduces a new IQA paradigm that integrates spatial grounding (bounding boxes) with image quality assessment, covering two subtasks: GIQA-DES (quality description with bounding boxes) and GIQA-VQA (quality QA with referring/grounding). The paper contributes a 160K-sample dataset (GIQA-160K) built via an automated annotation pipeline, and a benchmark (GIQA-Bench) evaluated on 100 test images. Fine-tuning existing MLLMs on this dataset confers grounding-IQA capabilities.

---

## Strengths

- **Novel and principled task formulation**: Combining spatial grounding (referring-in + grounding-out) with IQA is a principled extension over prior work. Q-Ground (Chen et al., 2024b) is noted as the closest prior work but lacks referring capability; the two-subtask decomposition (GIQA-DES, GIQA-VQA) is distinct from existing IQA and grounding datasets (Sec. 2.2).

- **Well-designed automated annotation pipeline with measurable ablation support**: The four-stage GIQA-DES pipeline addresses real failure modes. The use of description phrase T_r instead of raw category names for Grounding DINO (Fig. 4) is concretely verified. The IQA-Filter (Algorithm 1) filtering quality-irrelevant boxes via Q-Instruct patch queries is a defensible heuristic. The ablation in Table 2a confirms refinement impact: mIoU improves from 0.5624→0.5851, Tag-Recall from 0.5045→0.5497, and BLEU@4 from 20.97→23.67.

- **Informative multi-task ablation (Table 3)**: Training only on GIQA-VQA severely degrades DES grounding (Tag-Recall drops from 0.5497 to 0.3283), while combined training recovers it. This provides genuine insight into subtask data interaction beyond simply observing that more data helps.

---

## Weaknesses

### Fatal
None.

### Major

- **Core motivational claim inadequately supported by quality-only evidence**: The paper's central argument (Sec. 1) is that spatial grounding enables "more fine-grained quality perception." However, on quality-only metrics in Table 5, the evidence is marginal: Grounding-IQA (mPLUG-Owl2-7B) achieves LLM-Score 63.00 vs. Q-Instruct (mPLUG-Owl2-7B) at 62.00; BLEU@4 is 22.87 vs. 22.69 (Q-Instruct LLaVA-v1.5-7B); Acc (W) is 0.5875 vs. 0.5375. These margins are small enough to be within noise, and grounding metrics are not available for IQA baselines. The paper primarily demonstrates that models can emit bounding boxes after fine-tuning, not that grounding substantively improves quality description or QA accuracy. This gap between stated motivation and what the evidence demonstrates is the core weakness of the paper as argued.

- **Llama3 self-reference in evaluation creates systematic measurement bias**: The LLM-Score metric (Sec. 3.4) uses Llama3 as judge. The training data (GIQA-160K) was constructed using Llama3 for tag extraction and QA generation (Sec. 3.2), and the GIQA-Bench GIQA-VQA samples were "generated by the annotation pipeline and further refined and answered by humans" (Sec. 3.4)—which also uses Llama3. Models trained on Llama3-generated language patterns and judged by Llama3 against Llama3-influenced benchmark data likely produce inflated LLM-Score for the Ours group relative to baselines. This confound is not acknowledged.

- **Benchmark too small for reliable quantitative conclusions**: GIQA-Bench contains only 100 test images (100 DES, 150 VQA samples). Table 5 compares 10+ methods on 9 metrics, yet differences of 1 point on LLM-Score (~1%) or 0.2 BLEU@4 points are not statistically meaningful at this scale. No confidence intervals are reported, making fine-grained comparative claims in the paper unreliable.

### Minor

- **Equation (1) is internally inconsistent with Equation (2)**: Eq. (1) states `id_l = y1 · m · n + x1 · n`. With n=m=20, this gives `id_l = 400·y1 + 20·x1`, so `id_l % 20 = 0` always—inconsistent with the inverse mapping in Eq. (2) which requires `id_l % n = x1`. The correct expression should likely be `id_l = y1 · n + x1`. The implementation probably works correctly, but the formula in the paper needs correction.

- **IQA-Filter's use of Q-Instruct (a baseline) in the pipeline is undisclosed**: The annotation pipeline uses Q-Instruct to filter bounding boxes (Sec. 3.2, Stage-3), yet Q-Instruct appears as a baseline in Table 5. While not circularity (Q-Instruct is used only as a quality oracle for box filtering), this dependency should be disclosed and any potential effect on comparison fairness discussed.

### Trivial
- Table 5 uses the row label "IQG" inconsistently with "IQA" terminology used throughout the paper.

## Nice-to-Haves

- A downstream task evaluation (image editing, quality-targeted enhancement, or quality-aware retrieval) foregrounded in the main body — rather than deferred to supplementary — would directly address the core motivational gap by demonstrating something grounded descriptions enable that text-only descriptions cannot.
- Expanding GIQA-Bench from 100 to ~500 images would allow comparative results in Table 5 to support fine-grained quantitative claims.
- A brief pipeline failure analysis (cases where Grounding DINO finds no relevant objects, or IQA-Filter eliminates all boxes) would build trust in GIQA-160K quality beyond the box-size distribution proxy in Fig. 6.

## Novel Insights
The multi-task ablation (Table 3) is the most transferable finding: training solely on GIQA-VQA collapses DES grounding performance (Tag-Recall: 0.5497 → 0.3283), suggesting that linguistically rich GIQA-DES descriptions are necessary anchors for spatial grounding even in VQA-style tasks. This has broader implications for data-mixing strategies in multi-task MLLM fine-tuning—diversity between dense-description and QA formats matters, not just data volume.

---

## Suggestions

1. Add bootstrapped confidence intervals to Table 5, or expand GIQA-Bench to ≥500 images, to make quantitative comparisons statistically defensible.
2. Promote at least one downstream task experiment (image editing guided by grounded quality descriptions) to the main body to directly support the "fine-grained quality perception" claim that the current quality-metric comparisons cannot fully establish.
3. Fix Eq. (1) to read `id_l = y1 · n + x1` for consistency with Eq. (2).
4. Add a brief discussion of the Llama3 self-reference in LLM-Score evaluation and how it may affect cross-group comparisons.
5. Disclose explicitly that Q-Instruct (used as an IQA oracle in the annotation pipeline) is also a comparative baseline in Table 5.
