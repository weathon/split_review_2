## Summary
Ambig-SWE extends SWE-Bench Verified with 500 synthetically underspecified GitHub issues and introduces an interactive evaluation framework to study how LLM agents handle incomplete task specifications. The paper decomposes agent capabilities into three measurable steps — detecting underspecificity, generating targeted clarifying questions, and leveraging interaction to improve task resolution — and evaluates six proprietary and open-weight models across all three dimensions. Key findings include that interaction can improve resolve rates by up to ~100% relative over non-interactive underspecified settings, that models almost universally default to non-interactive behavior without explicit prompting, and that Qwen 3 Coder exhibits pathological non-interactive rigidity despite strong raw SWE-Bench performance.

---

## Strengths

- **Well-decomposed three-step evaluation framework**: Breaking agent behavior into (i) underspecificity detection, (ii) question quality, and (iii) task resolution is genuinely diagnostic and provides actionable signal for each deficiency independently. No prior SWE-Bench evaluation does this.

- **Empirically comprehensive multi-model study**: Six models spanning two capability tiers (proprietary: Claude Haiku 3.5, Sonnet 3.5, Sonnet 4; open-weight: Llama 3.1 70B, Deepseek-v2, Qwen 3 Coder 480B) are evaluated across 500 issues with Wilcoxon tests validating significance at each comparison, yielding robust cross-model insights.

- **Nuanced navigational vs. informational information analysis** (Table 1): The finding that Qwen 3 Coder's resolve rate *decreases* from 55.4% to 52.4% when file path information is provided — because it ignores it and re-explores anyway — is a non-obvious, actionable finding for agent designers.

- **Transparent treatment of dataset limitations**: The paper conducts distributional difference analysis (Zhong et al., 2023) comparing synthetic vs. natural underspecified issues and provides a principled justification for not using natural underspecified issues (lack of verified ground-truth specifications for causal measurement).

## Weaknesses

### Fatal
None.

### Major

- **Synthetic underspecification distributional gap**: The underspecified issues are generated by GPT-4o, and the paper's own analysis (§2.1) reveals that the synthetic issues are more aggressively stripped of code snippets and error messages than natural underspecified issues. While natural underspecified issues also contain conversational fragments, external links, and partial code traces, the synthetic ones have none of these. Agents evaluated on clean synthetic summaries may behave differently when facing messier, partially-specified real-world issues with embedded traces and links. The paper acknowledges this but does not fully close the gap — even a small curated set of 20–30 real underspecified issues with known resolutions could validate generalization.

- **Incomplete evaluation for the best model**: Footnote 4 discloses that Claude Sonnet 4 is evaluated on only 100/500 instances in the Hidden setting due to cost. This means the central result of RQ1 (Figure 3, Table comparing Hidden vs. Interaction) draws the Hidden baseline for the strongest model from a different — and four times smaller — sample than all other models. The paper states findings are "still statistically significant," but the subset selection could introduce sample bias, and this is disclosed only in a footnote rather than prominently in the results table.

### Minor

- **74% improvement claim inconsistency with tabulated data**: The abstract and introduction state "up to 74% over the non-interactive settings." From Figure 3: Claude Haiku 3.5 improves from 13.4% to 26.8% (≈100% relative), Claude Sonnet 4 from 40% to 61.4% (≈54%), Claude Sonnet 3.5 from 24.2% to 39.6% (≈64%). The source of the precise "74%" figure is not traceable from the main text and should be clarified.

- **Underspecificity detection window fixed at 3 turns**: §7 acknowledges detection is measured only within the first three turns, but no ablation or sensitivity analysis is provided. The choice of 3 turns is not justified relative to alternative cutoffs.

- **Information gain metric disconnected from task utility**: The cosine distance metric in §5 treats all acquired information equally. The paper itself observes that Qwen 3 Coder achieves the highest cosine distance (0.179) yet similar resolve rates to Claude Sonnet 4 (0.171 distance, 50% fewer questions). This decoupling suggests the metric does not directly predict task success, yet §5 is framed as explaining performance differences.

### Trivial
None.

## Novel Insights
The paper's discovery that Qwen 3 Coder — one of the strongest coding models (64.6% resolve rate on fully specified issues) — exhibits 100% false-negative rate on underspecificity detection under any prompt condition, and that receiving navigational information *hurts* its performance (55.4% → 52.4%) because it ignores it and re-explores anyway, is a genuinely surprising finding that reveals a fundamental disconnect between raw task-solving capability and interactive adaptability. This suggests that SWE-Bench training optimizes for a rigid, code-exploration-first protocol that becomes a liability in interactive settings — an insight with direct implications for how coding agents should be trained.

## Suggestions
1. Clarify in the abstract/main text exactly how the "74%" figure is computed.
2. Move the Claude Sonnet 4 100-instance caveat to the main results table (caption or explicit row note), not just a footnote.
3. For future versions: include even a small validation set on natural underspecified issues to address the synthetic-distribution concern.
