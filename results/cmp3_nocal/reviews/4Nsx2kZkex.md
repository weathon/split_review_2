## Summary

This paper proposes DV-RL, a framework that integrates differentiable approximations of formal verification into the reinforcement learning loop for code synthesis. The key idea is to replace discrete verification oracles with smooth surrogate functions, enabling gradient-based joint optimization of task completion and safety during policy training. The method combines a bilevel optimization loop (periodically calibrating the surrogate against an exact verifier) with hierarchical program generation and verification-guided token sampling.

## Strengths

- **Bilevel optimization formulation (Eqs. 8–9) is a sound architectural choice.** Maintaining a separate surrogate that is periodically calibrated against an exact verifier through KL-divergence minimization is a principled way to keep the differentiable approximation faithful to formal semantics. The periodic hard-constraint injection (Eq. 13) for surrogate drift is a sensible design element.

- **Hierarchical verification approach mirrors program analysis structure.** Applying differentiable checks at both the AST/control-flow level (via GNNs processing program dependence graphs) and the token level is a natural decomposition that aligns with how formal program analysis tools operate.

## Weaknesses

### Fatal
None.

### Major

1. **The gradient injection term (Eq. 7) is technically unsupported as presented.** Equation 7 writes:  
   `∇_θ J(θ) = E_{P∼π_θ}[∇_θ log π_θ(P)·R(P)] + λ ∇_θ Ṽ(P,φ)`.  
   The second term requires differentiating the verification score with respect to policy parameters θ. The program P is generated by sampling discrete tokens from π_θ, and Ṽ(P,φ) depends on θ only through this discrete sample. The paper describes Ṽ as a function of the program P and its own parameters w (trained separately via Eq. 8), with no shared representations between the policy network (12-layer Transformer) and verification surrogate (3-layer GNN + MLP). No reparameterization trick, Gumbel-softmax relaxation, straight-through estimator, or any other mechanism for propagating gradients through discrete sampling is provided. The paper claims this term enables the policy to "accommodate a change in generation according to safety violations before they completely appear in the reward" (Section 4.2), but the mechanism for computing this gradient is never explained. This undermines a core claim of the paper.

2. **No statistical uncertainty reported anywhere.** Tables 1 and 2 report single scalar values for VSR, FC, VE, and SQ without standard deviations, confidence intervals, or any indication of the number of independent runs. RL training is inherently high-variance — single runs of PPO can differ substantially across random seeds. Without multiple seeds, there is no way to assess whether the reported improvements over baselines are statistically significant or within noise. This is a standard methodological expectation that is not met.

3. **Figure 2 data presentation is invalid.** The table embedded in Figure 2 reports a "Total (%)" column that is the arithmetic sum of the "Memory Safety" and "Termination Guarantees" columns (e.g., 94% + 97% = 191%). The y-axis is labeled "Proportion of Generated Code Snippets (%)" and ranges from 0 to 175. Since these are overlapping categories (a single program can satisfy both properties), summing them into a "Total" and presenting this as a stacked area chart with values exceeding 100% is a data visualization error. The individual per-property percentages are individually plausible, but the presentation as a stacked sum reaching 191% is actively misleading and undermines trust in the quantitative results.

### Minor

1. **CMDP/safe-RL framing is imprecise.** The paper invokes the constrained MDP formulation (Altman, 2021) in Section 3.3 but the actual training objective (Eq. 6) is a scalarized weighted sum `α·R_task + (1-α)·Ṽ` with α=0.7, not a constrained optimization that enforces safety bounds. This is reward shaping, not constrained safe RL with hard guarantees. While many papers in the area use "safe" loosely, the gap between the framing and the method should be clarified.

2. **Best baseline comparison is not adequately discussed.** Syntax-Guided Synthesis achieves 97.5% VSR, outperforming DV-RL's 95.8% on the primary safety metric. The paper frames its results as "superb verification rates" and highlights improvements over weaker baselines (Pure RL, Constrained RL), but does not directly address why a user would prefer DV-RL over Syntax-Guided Synthesis beyond speed (VE: 85ms vs 510ms). The claimed headline improvement of "26.5% over pure RL" selects the weakest comparator.

3. **Key design choices are underspecified.** (a) The similarity measure S(τ₁,τ₂) in Eq. 2 for type checking is never defined — the paper treats type checking as a continuous similarity score without specifying how types are embedded or what similarity function is used. (b) Equation 10 uses Ṽ(P_≤t, φ) for verification-guided token-level sampling, but Ṽ is defined over complete programs (type environments, PDGs) — how this is computed incrementally for incomplete ASTs is not explained.

4. **FC gains are marginal.** DV-RL's functional correctness (74.6%) is only 2.2 points above Pure RL (72.4%) and 4.5 points above RL+Post-hoc (70.1%), and the SQ difference between DV-RL (0.73) and RL+Post-hoc (0.71) is likely within noise given the absence of variance estimates.
