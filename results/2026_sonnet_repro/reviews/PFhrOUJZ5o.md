## Summary

LAION-Comp is a large-scale scene graph dataset of 540,005 aesthetic images annotated via GPT-4o with objects, attributes, and relations, extending LAION-Aesthetics V2. The paper additionally contributes four baseline models built on SDXL, SD1.5, SD3.5, and FLUX backbones augmented with a GNN-based scene graph encoder, and introduces CompSGen Bench—a 20,838-sample benchmark derived from the LAION-Comp test split targeting complex scene generation. The core thesis is that large-scale structural annotation substantially improves compositional generation over text-only or prior small-scale SG datasets.

---

## Strengths

- **Order-of-magnitude scale advantage over existing SG datasets.** At 540K annotated image-SG pairs, LAION-Comp is substantially larger than Visual Genome and COCO-Stuff. The multi-backbone ablation study (Table 4) shows monotonically improving metrics as data proportion increases, and at 10% of LAION-Comp SDXL-SG already achieves Entity-IoU 0.874, higher than the same model trained on full Visual Genome (0.813, Table 2), providing direct evidence that annotation quality, not just volume, drives the improvement.

- **Controlled same-backbone dataset comparisons validate LAION-Comp's quality.** Table 2 compares SGDiff and SG-Adapter trained identically on COCO, Visual Genome, and LAION-Comp. For SG-Adapter, LAION-Comp (SG-IoU 0.538, Ent-IoU 0.866, Rel-IoU 0.852) uniformly outperforms VG (0.515/0.803/0.782) and COCO (0.485/0.840/0.833). This same-architecture comparison cleanly attributes the improvement to the dataset, not architectural choices.

- **Rich and semantically diverse relation vocabulary.** The paper quantitatively shows that non-spatial relations dominate in LAION-Comp (77.48%) versus Visual Genome's spatial skew (58.02%), and top-10 relations account for only ~22% of all relations. This is reflected in the annotation prompt (Fig. 2) which explicitly requires precise, non-spatial verbs ("holding", "supporting") over shallow positional labels.

- **GPT-4o annotation pipeline achieves high verified accuracy.** Section 3.1 reports 98.8% / 97.5% / 95.7% accuracy for objects, attributes, and relations via partial human verification, supporting the claim that automated annotation at scale is reliable. The prompt engineering (unique object IDs, abstract adjective attributes, relation specificity) is principled and reproducible.

## Weaknesses

### Fatal
None.

### Major

- **CompSGen Bench is in-distribution with respect to training, creating evaluation circularity.** Section 3.3 states: "From the 50,000-image test set, we select samples with over four relations." Both the training set (480K) and the CompSGen test set (20,838 samples) are generated by the same GPT-4o annotation pipeline with the same prompts. The primary accuracy metrics—SG-IoU, Entity-IoU, and Relation-IoU—measure alignment with scene graph annotations produced by that same pipeline. A model that learns the annotation style (vocabulary, relational grammar, object granularity) of GPT-4o's outputs will score higher on these metrics even if it is not meaningfully better at compositional generation in a distribution-independent sense. The Table 3 results cannot cleanly disentangle in-distribution overfitting to the annotation format from genuine compositional fidelity. The paper would need at least one held-out evaluation using independently authored test prompts or metrics not derived from the LAION-Comp annotation pipeline (e.g., T2I-CompBench results, mentioned but deferred to the appendix) to support the Table 3 claims with confidence. This does not invalidate Table 2's same-backbone dataset comparisons, which are more robust.

- **Backbone quality confound in Table 3.** In Table 3, the primary T2I and SG2IM baselines (SGDiff, SG-Adapter) are built on SD1.x, while the authors' models use SDXL, SD3.5, and FLUX. The FID gap between SDXL (25.2) and SGDiff (35.8) is 10.6 points; the gap between SDXL and SDXL-SG on the same benchmark is only 1.5 points. This means the dominant portion of the visual quality advantage in Table 3 comes from the backbone, not the scene graph conditioning or LAION-Comp annotations. Table 3 does not control for backbone, making it inadequate to isolate the data contribution from the architecture contribution. (This concern is weaker for Table 2, where same-backbone comparisons are presented.)

- **No ablation isolating the GNN encoder contribution from "SG-as-text."** Equation 1 introduces a GNN that refines CLIP-encoded triple embeddings via a learnable scaling factor α initialized to zero. The paper presents this as a novel architectural component, but there is no ablation comparing the GNN to the simple baseline of providing the scene graph as a flattened text sequence to the existing CLIP encoder without the GNN. Table 4 only varies data proportion, holding the GNN architecture fixed. Without this control, one cannot determine whether performance gains come from the dataset, the GNN graph processing, or both. This is significant because if flattened SG text achieves equivalent performance, the architectural contribution reduces to the data contribution—still valid, but requiring different framing.

### Minor

- **The Table 1 metric comparison between LAION Captions and LAION-Comp SGs is methodologically uneven.** SG-IoU+, Ent-IoU+, and Rel-IoU+ are metrics computed against scene graph representations. Measuring a natural language caption's "accuracy" using these scene-graph-centric metrics structurally disadvantages text captions and favors scene graphs regardless of how well those captions actually describe the images. The result (Table 1: LAION Caption Rel-IoU+ = 0.557 vs LAION-Comp Rel-IoU+ = 0.749) is expected by construction, not purely by annotation quality. A complement—e.g., showing that the scene graph faithfully describes the image content through independent visual grounding—would provide stronger evidence.

- **FID increase justification is weak for this scale of fine-tuning.** Section 5.1 invokes DreamBooth (Ruiz et al., 2023) and SG-Adapter to explain FID increases from fine-tuning, citing "fine-tuning pre-trained T2I models inevitably increases FID scores." This reasoning applies to narrow few-shot fine-tuning scenarios. LAION-Comp training involves 480K samples, which is not comparable to DreamBooth's regime. The authors should either measure FID on a held-out set that better reflects LAION-Comp's distribution or acknowledge this limitation directly.

- **CLIP scores reported on COCO (Section 5.1) without explanation.** The paper states "we further compute CLIP scores on COCO, which are 0.630 for SDXL and 0.635 for SDXL-SG" but provides no context for why COCO is chosen as the evaluation set for CLIP scores when the primary benchmark is LAION-Comp-derived, nor is the difference (0.005) analyzed or contextualized.

## Novel Insights

The paper's most practically significant finding—that training on a large-scale GPT-4o-annotated scene graph dataset produces consistently better compositional accuracy than training on COCO or Visual Genome for the same model architecture—points to a broader lesson: the bottleneck in compositional generation is less about architecture and more about annotation quality and relational diversity in the training data. The explicit dominance of non-spatial relations (77.48% in LAION-Comp vs. 41.98% in VG) and its correlation with better benchmark performance (Table 2) suggests that prior SG datasets' spatial skew was actively limiting compositional generalization rather than merely leaving performance on the table.

## Suggestions

1. **Add an independent benchmark evaluation.** Construct or adopt a held-out test set (e.g., curated T2I-CompBench subsets focused on multi-relation scenes) where test prompts are defined independently of LAION-Comp annotations. Show that LAION-Comp-trained models outperform COCO/VG-trained models on this external set using metrics not derived from LAION-Comp's annotation pipeline.

2. **Ablate GNN vs. SG-as-text.** Add a row to Table 2 or 4 for "SDXL + SG-as-text" (scene graph serialized as flat text, no GNN). This single control would cleanly partition the contribution between data and architecture.

3. **Backbone-controlled Table 3.** Add SGDiff-SDXL and SG-Adapter-SDXL entries trained on LAION-Comp to provide a cleaner apples-to-apples comparison in Table 3 that disentangles backbone from data contributions.
