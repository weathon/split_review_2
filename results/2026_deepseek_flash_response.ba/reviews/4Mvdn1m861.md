## Summary

This paper proposes TokenCount, a training-free object counting framework built on SAM without architectural modifications or auxiliary models. It has two components: (1) a probabilistic prompt generation stage that constructs an exemplar-conditioned probability distribution over the image and iteratively refines it based on verification feedback, and (2) an output token-based verification stage that uses SAM's decoder output tokens with the TS-SS hybrid similarity metric to distinguish positive from negative instances. The method is evaluated on FSC-147 (MAE 16.25) and CARPK (MAE 4.68, beating all supervised methods listed).

## Strengths

- **Strong CARPK results (Table 1):** The method achieves MAE 4.68 and RMSE 6.13 on CARPK, outperforming all six supervised methods listed (FamNet: 18.19, BMNet+: 5.76, SAFECOUNT: 5.33, LOCA: 9.97, etc.). This is a genuine training-free result that exceeds category-specific supervised approaches on specialized aerial imagery. The paper attributes this convincingly to SAM's strong segmentation of well-bounded objects in consistent viewpoints.

- **Output token space verification is well-motivated and supported (Tables 3, 5, Figure 5):** The paper demonstrates that verification in SAM's output token space (16.25 MAE) outperforms the same method when operating in the image embedding space (16.94 MAE, Table 5). PCA visualizations in Figure 5 provide supporting evidence that positive/negative instances form more separable clusters in output token space. The idea of repurposing SAM's decoder output tokens—which integrate semantic and positional information through bidirectional cross-attention—as the verification space is conceptually interesting.

- **Thorough ablation of prompt budget vs. accuracy (Table 4):** The paper provides a granular analysis across 9 operating points (varying iterations from 8–32 and prompts/iteration from 32–128), showing clear trends and enabling practitioners to make an informed accuracy-efficiency trade-off. This is the most informative table in the paper.

- **No auxiliary models required:** The method uses only SAM, unlike SAM+α approaches such as TFCAC which require an additional DINO encoder.

## Weaknesses

### Major

- **Misleading abstract claim (Section 1, line 9):** The abstract states the method "achieves superior accuracy with an MAE of 16.25, outperforming existing training-based and training-free counting methods." This is factually inaccurate: TFCAC (a training-free method) achieves 12.26 MAE on the same benchmark, and several training-based methods (LOCA: 10.79, PseCo: 13.05, SAFECOUNT: 14.32, BMNet+: 14.62) also outperform 16.25. The main text (line 228) correctly qualifies this as "best performance among training-free SAM only methods," but the abstract overclaims. For a top-venue submission, this level of mismatch between abstract and actual results is a serious issue.

- **TS-SS verification metric — central novelty supported by only 0.23 MAE improvement (Table 3, Section 4.4):** The paper's core technical novelty in the verification stage is the use of TS-SS over standard similarity metrics. Table 3 shows: TS-SS (16.25 MAE) vs. cosine similarity (16.48) vs. L2 distance (16.53). The improvement over cosine is 0.23 MAE (~1.4% relative), and RMSE is essentially identical across all metrics (133.11–134.51). No statistical significance or variance is reported. The paper frames this as TS-SS "breaking through a plateau" (Section 4.4, line 275) that cosine and L2 have reached, but a 0.23 MAE difference without any significance test does not constitute strong evidence that standard metrics are "inadequate" (Section 3.2, line 156) for this task. The claim that a novel hybrid metric is *necessary* rather than merely marginally beneficial is unsupported.

- **Computational efficiency asserted without fair comparison (Section 4.2):** The paper claims "inference time that is more than twice as fast" as TFCAC but provides no timing data, runtime table, or controlled experiment for any baseline method. The best result requires an average of ~1,438 prompts per image on FSC-147 (Table 4, 16×128). Without runtime measurements for TFCAC, OmniCount, TFOC, etc. on the same hardware, the efficiency advantage cannot be evaluated. The method also lacks an ablation comparing probabilistic prompt generation against a uniform grid at matched prompt density to quantify the claimed advantage.

- **High RMSE relative to MAE indicates instability, unanalyzed (Table 1):** On FSC-147, the method achieves MAE 16.25 but RMSE 133.11. For comparison, training-based LOCA achieves MAE 10.79 / RMSE 56.97, and training-free TFCAC achieves MAE 12.26 / RMSE 56.33. An RMSE of ~133 with an MAE of ~16 implies catastrophic prediction errors (hundreds of objects off) on some images. The Discussion (Section 5) mentions "performance degradation in scenarios with dense distributions of very small instances" in one sentence but provides no quantitative analysis — no per-category breakdown on FSC-147 (147 categories), no density-bucket analysis, no failure-case study. This omission is significant because it prevents understanding whether the method is usable in practice for specific object types or density regimes.

### Minor

- **Token verification threshold of 300 (Section 4.1) never defined:** The paper states "Based on validation experiments, we set the token verification threshold to 300" but does not specify: (a) what quantity is being thresholded (the TS-SS value? the output token magnitude?), (b) how 300 was selected (validation split? grid search range?), or (c) how sensitive the results are to this value. This is a critical hyperparameter that directly controls the precision-recall trade-off.

- **Iterative probability update rule described qualitatively (Section 3.1, lines 140–148):** The paper states that for positive verifications "the probability distribution at the corresponding coordinate is set to 0" and for negatives "the value of the probability distribution at that mask region is decreased." The exact update for negatives (multiplicative factor? proportional decrease?) is never specified with an equation. This makes the method non-reproducible.

- **One-shot counting gap larger than few-shot (Table 2):** The one-shot MAE of 18.57 vs. TFCAC's 15.15 represents a 22% relative gap, notably larger than the 33% gap in the few-shot setting (16.25 vs. 12.26). The paper calls this "competitive" but does not discuss why the gap widens with fewer exemplars.

- **No confidence intervals or variance estimates on any metric:** Given that the key claims (TS-SS vs. cosine, output token space vs. image embedding space) rest on margins of 0.23 and 0.69 MAE respectively, the absence of any variance estimate is a significant omission.

- **No grid baseline comparison:** The paper motivates probabilistic prompt generation by criticizing uniform grids (Section 2.2) but never compares against a grid-based variant at matched prompt density to quantify the advantage.

## Nice-to-Haves

- The Exemplar count for FSC-147 should be stated explicitly (only CARPK's 12 exemplars is reported).
- The paper could benefit from analyzing failure cases by object scale or density to explain the high RMSE.
- Reporting per-category breakdowns on FSC-147 would help assess where the method works and where it does not.

## Novel Insights

None beyond the paper's own contributions.

## Suggestions

1. **Fix the abstract** to accurately characterize performance relative to TFCAC and training-based methods, e.g., "best performance among training-free SAM-only methods and competitive with methods using additional encoders."
2. **Provide statistical significance** for the TS-SS advantage: run TS-SS vs. cosine multiple times with different random seeds and report mean ± std.
3. **Add a timing comparison table** measuring TFCAC, OmniCount, and TFOC on the same A100 hardware alongside your method at multiple operating points from Table 4.
4. **Analyze failure modes** on FSC-147 by object scale or density buckets to explain the MAE/RMSE discrepancy.
5. **Define the token verification threshold** precisely and include a sensitivity analysis.
6. **Provide the iterative probability update** as a precise equation, especially the negative-case update rule.
7. **Add a uniform grid baseline** at matched prompt density to quantify the advantage of probabilistic prompt generation.
