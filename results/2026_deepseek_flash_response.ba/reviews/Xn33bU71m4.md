## Summary
This paper evaluates nine open-source LLMs (7B–16B parameters) on two reverse engineering tasks—name recovery and type inference—using a dataset of 40,000 decompiled functions across four architectures and four optimization levels. The main finding is that none of the models achieve practically useful performance even after LoRA fine-tuning: F1 scores remain below 0.1 for type inference and below 0.35 for variable name recovery.

## Strengths
- **First systematic head-to-head comparison of 9 LLMs on identical RE tasks/protocols**: Tables 2–5 evaluate CodeLlama, Llama2, DeepSeek-V2, DeepSeek-R1, Qwen2.5, Qwen3, WizardCoder, Phi4, and Gemma3 on the same 40,000-function dataset with the same metrics. Prior work (e.g., SYMGEN with CodeLlama-34B only, ReSYM with StarCoder-3B only) evaluates a single model, making it impossible to distinguish task difficulty from model capability. This paper provides the missing cross-model baseline.

- **Unified evaluation of name recovery and type inference under one framework**: The paper jointly assesses function name recovery, variable name recovery, and type inference (Tables 2–4), showing that type inference is significantly harder than name recovery—all models score <0.1 F1 on type inference even after fine-tuning. This finding emerges only from a unified evaluation.

- **Cross-decompiler comparison on real-world firmware**: Table 6 provides practically actionable guidance by showing that most models perform better on IDA Pro outputs than Ghidra outputs (e.g., CodeLlama type inference: 0.03 Ghidra vs. 0.10 IDA Pro), a comparison absent from prior work.

## Weaknesses

### Major

1. **Unexplained 3–15× discrepancy between Figure 1 and Table 2 undermines quantitative trust.** Both report F1 scores for function name recovery on x86-64 with original (non-fine-tuned) models using CodeWordNet. Figure 1 reports values of ~0.15–0.25 (e.g., CodeLlama O0 ~0.15, Qwen3 O0 ~0.25, per the numerical approximations in the figure caption, lines 333–348), while Table 2 reports 0.01–0.05 for the same models and configurations (CodeLlama O0 = 0.04, Qwen3 O0 = 0.05). The paper provides no explanation. Since this is an evaluation/benchmarking paper where all claims rest on quantitative results, readers cannot determine which set of numbers is correct. This is the most serious weakness in the paper.

2. **Fine-tuning experiment (200 steps) does not support the conclusions drawn from it.** The paper fine-tunes for only 200 steps on a training set of 160,000 functions (Section 4.3). With typical batch sizes of 8–32, only 1,600–6,400 samples are processed—roughly 1–4% of the training data. No learning curves, convergence evidence, or LoRA hyperparameters (rank, alpha, batch size, learning rate) are reported (Section 3.3 mentions LoRA but gives no hyperparameter details). The paper then draws conclusions such as "fine-tuning has limited impact on type inference" and "gains are inconsistent and not guaranteed" (Findings 1–2). These conclusions reflect the behavior of a very brief warm-start, not fine-tuning as normally understood and practiced in the field.

3. **Auxiliary LLM extraction pipeline is unspecified and unvalidated.** All reported F1 scores pass through an "auxiliary LLM" (Section 3.2) that parses heterogeneous model responses into a uniform format. The paper does not state which LLM was used for this purpose, nor does it report any validation of extraction accuracy. Systematic extraction failures (e.g., correctly-predicted names phrased in unexpected ways being discarded, or partial outputs from truncated responses being parsed incorrectly) could systematically depress all reported F1 scores. For a benchmarking paper where every quantitative result depends on this pipeline, this is a significant methodological gap.

4. **Results are not compared against prior work reporting positive results.** The paper motivates itself by citing SYMGEN and ReSYM as works that fine-tune LLMs for these tasks, but provides no quantitative comparison to their reported performance. If prior work achieves meaningfully higher F1 scores (as the motivation section implicitly suggests by calling those works "successful"), the discrepancy demands explanation—whether it stems from different evaluation metrics, data, model sizes, or fine-tuning protocols. Without this comparison, the paper's core claim that "current LLMs remain fundamentally limited" cannot be distinguished from the alternative that the experimental setup (prompts, data representation, evaluation pipeline) is simply not comparable to what prior successful work used.

### Minor

5. **Headline result (0.37 F1 for DeepSeek-R1) in the introduction lacks a clear reference.** Line 19 states that after fine-tuning, DeepSeek-R1 "reaching an F1 score of 0.37." On the presented x86-64 results, the highest DeepSeek-R1 F1 is 0.17 (Table 3, variable name, O0, fine-tuned). If the 0.37 result appears in the appendix (results for other architectures), the introduction should reference the specific table and configuration. As written, a reader cannot locate the evidence for the paper's marquee quantitative claim.

6. **No error bars, confidence intervals, or variance estimates.** The paper acknowledges "randomness of LLMs and random data selection" in the reproducibility statement (line 428), yet every F1 score in every table is a single point estimate. For a benchmarking study comparing 9 models, readers need to know whether reported differences between models are meaningful or within noise.

7. **No qualitative error analysis.** The paper reports near-zero F1 scores but does not analyze what models actually produce in their outputs—whether predictions are semantically related but lexically different, whether types are close but not exact matches, or whether models hallucinate entirely. Table 8 provides four examples for one model, but a systematic error taxonomy across all models would be far more informative.

### Trivial

8. **Approximate numbers in the Figure 1 caption** (marked with ~) alongside precise numbers in Table 2 create unnecessary confusion. Both should use the same precision or clearly state their source.
