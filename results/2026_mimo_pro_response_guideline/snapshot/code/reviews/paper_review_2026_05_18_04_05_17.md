## Summary

This paper presents a tracklet-based pipeline for jersey number recognition in broadcast soccer footage. The proposed system chains Real-ESRGAN super-resolution, OWLv2 open-vocabulary detection, collage-based temporal aggregation, and a Qwen vision-language model fine-tuned with LoRA. The key result is an accuracy improvement from 49.7% (zero-shot) to 76.41% after two epochs of fine-tuning on a 1,840-sample set, along with a recognition-stage runtime comparison showing the collage approach is faster than per-frame PARSeq OCR. The paper also includes a separate study of legibility classification backbones (ResNet34, EfficientNetV2, MobileNet, ConvNeXt, Swin-T).

## Strengths

1. **LoRA fine-tuning yields a clear accuracy gain.** Zero-shot Qwen achieved 49.7% on a 1,840-sample set; after two epochs of LoRA fine-tuning, accuracy rose to 76.41% (Section V.C.1). This 27-percentage-point improvement demonstrates that parameter-efficient fine-tuning adapts the vision-language model to the jersey recognition task with relatively little data.

2. **Collage-based aggregation reduces recognition-stage inference calls.** Table I compares PARSeq (635 crops, 9.05 s) against Qwen with collages (5 inputs, 1.19 s) on the same tracklet. The reduction from 635 recognition calls to 5 is substantial, and the paper explicitly acknowledges this comparison excludes OWLv2 runtime (Section V.D). The design insight—that consolidating multiple frames into a single input reduces downstream compute—is a valid contribution.

3. **Honest error analysis including ground-truth label issues.** Section IV.D.4 documents specific cases where SoccerNet labels are incorrect (e.g., a tracklet labeled "6" that clearly shows "54"), and Figure 14 provides a concrete example. Acknowledging that annotation errors depress reported accuracy is good scientific practice.

4. **Removal of the PARSeq charset constraint.** Section V.A.5 correctly identifies that PARSeq restricts output to two digits (0–99), while Qwen-VL can recognize arbitrary-length numbers, broadening applicability beyond the original pipeline's constraints.

## Weaknesses

### Fatal
None.

### Major

1. **No end-to-end accuracy comparison against the stated baseline (structural).** The paper repeatedly identifies Koshkina & Elder (2024) [1] as its baseline, yet it reports **zero accuracy numbers for this baseline** on the same test set (Section V.C.1). The only accuracy reported is 76.41% for the proposed Qwen+LoRA system. Without knowing what the baseline achieves on the same data, the central claim that the proposed pipeline is "a useful approach" cannot be evaluated. The headline metric is unmoored: if the baseline achieves 50%, this would be a strong result; if it achieves 90%, the proposed method is worse. This is not a minor oversight—it is the absence of the most basic validation a new-method paper requires. Adding this comparison would address the flaw, but as submitted the paper does not demonstrate that its core contribution has value relative to existing work.

### Minor

2. **Runtime comparison is partial and the conclusion overreaches.** Table I explicitly covers only the OCR/recognition stage and excludes OWLv2, which the paper itself describes as a large transformer (~1B params) running on all frames of a tracklet (635 frames in the test tracklet). The paper then states "these results indicate that the proposed recognition architecture is faster in practice" (Section V.D). This conflates "recognition-stage" speed with full-pipeline speed. A fair comparison would measure end-to-end runtime for both pipelines on the same hardware. The partial comparison is useful but the overbroad conclusion should be corrected.

3. **Legibility classifier experiments are largely disconnected from the main contribution.** Sections III.A–III.B present an extensive comparison of legibility backbones (ResNet34, EfficientNetV2, MobileNet, ConvNeXt, Swin-T) using tracklet-level weak supervision. However, the final proposed pipeline does **not** use any explicit legibility classifier—OWLv2 serves as an implicit filter instead. The paper acknowledges this (Swin-T was not adopted because a two-tracklet test showed 0.34% worse accuracy), but ~30% of the technical content describes a line of inquiry that does not feed into the final system. While this material could be valuable as an ablation, its current presentation as a standalone study dilutes the paper's focus on the main pipeline contribution.

4. **Insufficient experimental detail for reproducibility.** The paper reports 76.41% accuracy on "a 1,840 sample set" but does not specify: (a) how these samples are split between training and testing, (b) how many distinct jersey-number classes are present, (c) whether accuracy is computed per-frame or per-tracklet, (d) whether the zero-shot and fine-tuned evaluations use the same test items, or (e) the exact prompt used for Qwen inference. The training loss plot (Figure 12) shows 264 steps with 1,840 samples, implying a batch size of ~7—but this is not stated. These omissions hinder reproducibility and interpretation.

## Nice-to-Haves

- **Component ablations.** The paper qualitatively motivates each pipeline component (Real-ESRGAN, OWLv2, collage, Qwen) but provides no quantitative ablation measuring the accuracy drop when any component is removed or replaced. Adding such ablations would turn the qualitative design discussion into rigorous evidence.
- **OWLv2 detection rate analysis.** The paper uses OWLv2 as an "implicit legibility classifier" but reports no statistics on what fraction of legible frames OWLv2 successfully detects. This would validate a core design decision.
- **Dataset and metric clarity.** Specifying the exact SoccerNet split used, train/test composition, and per-frame vs. per-tracklet accuracy would significantly improve the paper.

## Removed Points

These points were flagged by the reviewers but are removed for the following reasons:

1. **"The legibility studies are a separate study occupying one-third of the paper that should be removed"** — While the legibility section is somewhat disconnected, it does contain useful empirical data (Swin-T vs. ResNet34 comparison on 6,827 crops) and the paper explicitly explains why Swin-T was not adopted. Better to keep it as supporting material than remove it entirely, but its prominence should be reduced.

2. **"The paper should report per-tracklet accuracy for the baseline"** — This is already captured by Major Weakness #1 (missing accuracy comparison). Not a separate issue.

3. **Strength: "OWLv2 consolidates legibility filtering and number localization"** — This is a design claim without quantitative validation. The paper provides no detection-rate analysis to support it.

4. **Strength: "Real-ESRGAN pre-processing demonstrably improves digit clarity"** — The evidence is limited to qualitative figure comparisons (Figures 9, 10). No accuracy ablation with/without super-resolution is provided.

5. **Strength: "Systematic evaluation of multiple legibility backbones"** — The CNN comparison (ResNet34, EfficientNetV2, MobileNet) uses only 5 tracklets, which is not "systematic." The ConvNeXt/Swin-T evaluations are more thorough (20 tracklets, 6,827 images) but are disconnected from the main pipeline.

## Suggestions

1. **Add an end-to-end accuracy comparison** against the Koshkina & Elder (2024) baseline on the same test set, reporting per-tracklet accuracy for both pipelines. This is the single highest-leverage improvement and is non-negotiable for a new-method paper.

2. **Provide full experimental details**: train/test split of the 1,840 samples, number of classes, per-frame vs. per-tracklet metric definition, the Qwen prompt template, LoRA hyperparameters (rank, alpha, target modules, batch size, learning rate).

3. **Qualify the runtime claim**: state explicitly that the comparison covers only the recognition stage and that full end-to-end timing (including OWLv2 and Real-ESRGAN) would be needed to assess total pipeline speed.

4. **Either integrate or downsize the legibility section.** If OWLv2 subsumes legibility filtering, make that case with detection-rate statistics. Otherwise, move the legibility backbone study to an appendix or significantly shorten it.
