## Summary

This paper systematically evaluates nine open-source LLMs (CodeLlama, Llama 2, DeepSeek-R1/V2, Qwen 2.5/3, WizardCoder, Phi4, Gemma3) on two reverse engineering tasks — name recovery and type inference from stripped binaries. The dataset spans 4 architectures, 4 optimization levels, and 40,000 functions from GNU projects. The paper finds that current LLMs perform poorly on these tasks (most scores below 0.1), with fine-tuning providing inconsistent and often insufficient gains.

## Strengths

- **Well-motivated gap.** The paper correctly identifies that model selection in LLM-based reverse engineering is often arbitrary (SYMGEN uses CodeLlama-34B, ReSYM uses StarCoder-3B, without clear rationale), and that systematic benchmarking is missing. This motivation is articulated clearly in §1–§2. *(favorability: 1.00)*
- **Broad dataset construction.** Four architectures (x86-64, x86-32, ARM 32-bit, MIPS 32-bit), four optimization levels, 40,000 unique functions from GNU software, with deduplication. This is a reasonable scope for an evaluation benchmark. *(favorability: 0.54–1.00 across sub-aspects)*
- **CodeWordNet for name evaluation.** Using semantic distances via CodeWordNet (following SYMLM) to handle semantically equivalent names is a reasonable methodological choice that avoids penalizing legitimate synonyms. *(favorability: 0.99)*
